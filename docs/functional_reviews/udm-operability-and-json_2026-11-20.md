# UDM operability and JSON boundaries

**Proposed · 2026-11-20 UTC.** Derive preparation, validation and change impact from the
declarations that govern the work. Give executable acquisition, production identity and permission
to reuse an earlier result separate decisions with a shared source of facts. Use PostgreSQL's native
numeric types as the basis for consistent JSON interchange. The operator should be able to identify
the first unmet prerequisite before a provider starts and retain eligible work when a downstream
operation or orchestration changes.

The [causal analysis][causes] and [JSON boundaries review][json] are the inputs. This review
inspected main at `46268676f`, including the [UDM coordinator][udm], [identity][identity],
[recovery][recovery], [CLI][cli] and [qualification][qualification] owners. It re-read the original
managed results and the [retained JSON probes][json-evidence]. Historical **Tested** and
**Measured** results apply to their recorded revisions and scopes. The design below is **Proposed**.
The [design standard][standard] guides ownership, scoped authority, layered identity, and execution
fit. The recommended changes use current declarations and custody wherever they can express the
needed facts.

Independent source reviews challenged the proposed ownership and failure behavior. Three resulting
constraints shape the recommendations. Scope the load boundary before narrowing executable checks.
Test Python and PostgreSQL schema agreement even under a single engine family. Retire repeat checks
only where the retained cut or owned payload still establishes the same guarantee.

## Make changes local and explain their consequences

<a id="O01"></a>
### O01 · Derive executable acquisition from the selected operation

The N42 Standard deployment and Integrated application admission passed. Main reproduced all 624
native programs. The cold Integrated attempt then refused the transform's acquired resource before
inference (`cfbf7d53d411497b85442167f7d2b70e`). The capture task was where the failure surfaced. The
causal probe reproduced the exact fingerprint difference using two intervening M1 and event edits.
Relocating identical bytes had no effect. Editing an actual transform callable or a declared
transform input also changed the asset. The probe establishes why the digest moved. Whether either
incidental-looking edit can change Integrated execution remains open. [N42 experiment][causes-n42]

`pdf_transform_assets` starts from common code and all four mode entry points. `code_asset` embeds
the observed graph digest and unknowns in an acquired resource. `verify_prepared_product` then
compares that resource as an exact executable prerequisite. This lets a conservative source survey
grow the scope of admission. It also leaves M1 with independently maintained source and callable
lists. [Mode selection][pdf-transform] · [Asset construction][code-asset] · [Actual executable
checks][port]

**Recommend.** Declare the selected callable surfaces, resource selectors and runtime bindings under
the operation's existing prepared implementation. Derive source capture, early preparation checks
and runtime verification from that specification. Start with selected PDF Standard/Integrated and
M1. Capture shared initialization and provider dependencies where they can affect the selected
boundary. Resolve physical origins at acquisition, including fixture execution. Preserve comparison
against the admitted archive, the actual loaded callable's qualified binding and code, origin bytes,
profile and required resource contents. Verification must still refuse when a required executable
correspondence is unresolved. Retain broad observed edges and unknowns as attributed impact
evidence. A known required dependency continues to govern admission under its own contract.

Use the existing workload declaration and resolver as the consolidation boundary. Extending
whole-package equality would preserve the present failure. Conversely, a human-maintained allowlist
of relevant-looking modules would make omitted required dependencies hard to detect. Deriving the
subset from the selected declaration, checking it against actual bindings, and preserving the
conservative route while its executable boundary is unresolved makes both failure modes visible.
Retire parallel lists, all-mode capture for a single selected mode and the bespoke fixture
acquisition path as the replacement covers their callers. Keep common integrity checks in the port
verifier.

**Demonstration.** Prepare each selected mode at a source relocation and run its real resolver.
Compare the two historical edits independently with a changed transform dependency, rebound
callable, changed provider resource and omitted M1 planner module. If selection cannot account for
an edit, preview reports the unresolved dependency and its consequence. Close the operation-scoped
M1 route with real GLiNER publication and a scoped native readback, including the CPU and logical
provider receipt. The existing final M1 provider obligation belongs to qualification. [M1
case][causes-m1]

### O02 · Explain producer identity and adopt compatible work

The book's N29 and N42 same-named recipes differ. The census has hashes, so it cannot attribute each
difference to a source or contract. N35 to N36 shows an implementation-revision and support-contract
difference for one draft. A separate equal-recipe example recomputed because incomplete lowering
identity made the request demand-scoped. Document these as distinct reasons. N36 same-demand stop
and resume already published three receipts and left no leases. Unchanged repeat published zero.
[Book evidence][causes-book] · [Stop and resume controls][stop]

**Recommend.** Let UDM-10 derive the material projection from the selected operation, its contracts,
and its acquiring runtime. Preserve a typed breakdown beside the existing identity or preview from
the owned inputs. Distinguish executable correspondence, determinants of the result, and sufficient
knowledge to establish reuse. In the material projection include the result-affecting implementation
and resources, exact input and support meaning, operation parameters, selected output contract and
applicable replicate. Keep original producer provenance, deployment, demand and attempt coordinates
on their respective owners. Give source or distribution uncertainty a conservative result according
to the decision it affects. Add a field-level comparator to the existing owner so operators can tell
whether a recipe, reuse scope, source, or support premise changed. An archive with only an old
digest can report the difference and that its contributing fields are unavailable.

Use the comparison in native request attachment and checkpoint eligibility through UDM-25. Committed
intents keep exact reconciliation. Private drafts and acknowledged pages retain their distinct
acquisition and retirement rules. Authenticate the original producer, generation, retirement,
manifest and replay bytes. Reacquire current support and publication authority before using adopted
work. Output equality can stop downstream propagation where a consumer's substitutability rule
allows it. It supplies no independent evidence of the original producer's custody. Historical output
can remain in its original custody when it is ineligible for current use. Prefer conversion or
regeneration over retaining a second execution path. [Request attachment][attachment] · [Spool
projectors][spool] · [UDM recovery][recovery]

**Demonstration.** Run a bounded regional case with a changed downstream step and operation inputs
held fixed. Preview should identify the changed field and preserve eligible acknowledged pages, then
show original attribution and current publication on native readback. Compare a genuine producer,
schema, parameter or resource change, distinct support, revoked authority, an active or counterfeit
producer and changed replay bytes. A changed or unresolved determinant may require fresh work for
the affected operation. An identical repeat should publish zero new receipts. Keep the same-demand
recovery route for incomplete cross-request proof. [ADR-0141 continuation boundary][continuation]

### O03 · Derive consumer checks from typed input requirements

The rich failure had two causes. N40 reached a live presentation gate while checking historical fit
custody. N41 requested a rich producer family from the public authorization operation, which
declares `none`. The bounded N42 repair passed the actual rich journey and 18 native controls. The
existing effect-policy and release facts were sufficient. [Rich evidence][causes-rich] ·
[Effect-policy owner][effects]

**Recommend.** Put input requirements on the consuming role and compile them against the producer's
admitted roles and support contract. Express the output role, CPU/publication witness, required
effect, validity-family claim and disclosure with the types already carrying those distinctions.
Where a fact is missing, extend its owner. Preserve explicit `none`, an undetermined declaration and
a known family as different states. Use historical cut, disclosure and receipt facts to authenticate
original support. Apply current authority to current disclosure and effects. A preflight can report
whether the declarations and acquired inputs are compatible. A live grant or revocation still
belongs to its runtime enforcement point.

Generate the producer/consumer projection and its explanation once from those facts. Retire
duplicate family switches and hand-carried requirement argument groups when the consumers move. Use
Pydantic `Field(discriminator=...)` or `Discriminator`/`Tag` for suitable shape families, starting
with CPU basis when it is touched. Keep domain cross-field checks and existing SQL-mirrored tagged
value semantics with their owners. The command-class row mutation in the causal analysis
demonstrates useful data-driven behavior with generated SQL held fixed. A new independently
versioned relation is justified when authorized editing of policy has its own lifecycle and multiple
actual consumers. Derived rows already serve the observed admission defects. A single generic
executor would still need separate rules for source custody, disclosure, and effects. [Rich
admission source][rich] · [Relational control][causes-mechanism] · [Pydantic discriminated
unions](https://pydantic.dev/docs/validation/latest/concepts/unions/#discriminated-unions)

**Demonstration.** Check a mixed-family journey where an ordinary authorization input satisfies its
declared role and fit material remains protected. Exercise a wrong issuer, substituted fit input,
changed epoch and revoked current grant through independent native controls. The rejection should
name the consuming role and the failed premise.

<a id="O04"></a>
### O04 · Show the first failing boundary in existing commands

**Recommend.** `ci model change inspect` reports the first changed material field and downstream
scope from the compiled comparison. `ci schema explain-operation` shows the admitted required roles,
families and effects and their native consequences. `ci results inspect` reports observed stages
from preparation through executable acquisition, provider publication and scoped readback. Put the
failing operation and resource, expected/actual basis and a typed next action on the existing
preparation diagnostic and managed observation boundaries. Use the existing bounded JSON and Rich
presentations. Reuse target acquisition and managed result custody, retaining recorded bindings,
redaction and availability. A passive preview can resolve declaration compatibility and available
custody facts. Provider readiness and live authorization remain conditional until their owners
observe them. [Operational CLI][cli] · [Current result inspection][result-inspection] ·
[ADR-0069](../adr/0069-cli-operations-custody.md)

A successful native parity check should be visible beside a failed executable acquisition. A later
publication with an unsuccessful assertion should be visible as a failed scoped readback. These
distinctions enable the operator to choose preparation, a bounded retry, or an exact resume without
reconstructing a journey from several bulk logs. Retire diagnostic guesswork based on the task name
or a fingerprint alone. The current reader reports the N42 port refusal and retained event timeout,
but the event summary carries no native binding or phase details. Keep causal and native attribution
with their existing owners. [Current evidence][causes]

**Demonstration.** Inspect a preparation refusal without a provider submission or work claim.
Compare the report with one genuine successful publication and an independent scoped readback.
Confirm that unavailable phases are marked as such, and that neither operator view nor JSON output
discloses protected support or credentials.

## Give JSON contracts and validation explicit owners

<a id="O05"></a>
### O05 · Use PostgreSQL-native numbers and one interchange codec

**Recommend.** Use ordinary finite JSON numbers at interchange and PostgreSQL `jsonb` for document
storage. Map typed whole-number fields to the applicable PostgreSQL integer domain and Python `int`.
Use PostgreSQL `double precision` and Python `float` for typed approximate calculations. JSONB
represents JSON numbers using PostgreSQL `numeric`. The application identity profile owns spelling
and scale where they matter. Where a field's SQL type supplies numeric semantics, let Psycopg adapt
that type. Use one documented rounding and comparison rule for a field that affects eligibility,
support or classification, with an explicit typed storage unit or SQL comparison where needed. This
follows the operator's preference for consistent PostgreSQL-native handling. There is no general
requirement to carry arbitrary decimal precision or lexical scale through Python, CLI/MCP and the
wire. [PostgreSQL JSON types](https://www.postgresql.org/docs/18/datatype-json.html) · [PostgreSQL
numeric types](https://www.postgresql.org/docs/18/datatype-numeric.html)

Use one strict interchange owner. Prefer a stdlib `json` adapter with `object_pairs_hook` for
duplicate refusal, `parse_constant` and a finite-number check for input, and `allow_nan=False` when
emitting. Enforce the existing byte budget and the supported PostgreSQL value domain. Normalize
parser, Unicode and depth failures to one boundary error. PostgreSQL `jsonb` has already normalized
duplicate keys by the time a row is returned, so refuse duplicates on input text before insertion. A
PostgreSQL value outside the declared interchange domain needs a typed boundary outcome, including
values that would overflow to infinity on Python decode. Retain `None` versus absent-field behavior
and exact integer representation within the owning contract. Validate the same supported fractional
values across rows, cursors, exports and worker frames. The exact numerical loss observed in the
prior review now motivates consistent numerical semantics and removal of the implicit
`analyzed_scope` key rule. At a typed integer boundary, classify an input before it could round to
an integral float. Define accepted spellings and range and verify their agreement with SQL.
[Current wire codec][wire-codec] · [Retained library contracts][json-evidence] · [Python JSON
API](https://docs.python.org/3.14/library/json.html)

Use Pydantic model/`TypeAdapter` validation in Python mode for already decoded data, with field
types and validators carrying the stated numeric domain. Typed presentation owns its serialization.
Prefer retiring `wire_json_loads`'s key dispatch, fragmented Psycopg and row adapters,
encode-to-validate passes and decimal-string/tag bridges that exist only for interchange. Remove MCP
double transmission after its typed contract and D8 consumers move together. Preserve byte-sensitive
worker framing and frozen SQL literal spelling until their owning contracts can demonstrate equality
or transition deliberately. Where a consumer needs the emitted byte size, measure the serializer's
actual delivery bytes once. [Pydantic strict
mode](https://pydantic.dev/docs/validation/latest/concepts/strict_mode/) · [D8 interface
owner](../design/D8-agent-and-query-interfaces.md) · [Prior codec correspondence][codec-review]

The existing RapidJSON options, distribution/interpreter and external surfaces are authenticated by
UDM-10. Remove that dependency and its custody surface when the replacement covers the remaining
callers. If an identified boundary warrants keeping RapidJSON during transition, 1.26 fixes embedded
NUL truncation and `Decoder.start_object`/`end_object` supports duplicate detection. A switch would
still require option, byte-vector and acquired-callable checks. The 1.26 fix is release-note evidence.
`orjson` is unwarranted for the chosen role. Revisit `msgspec` if a measured or evidenced bottleneck
or a suitable typed protocol contract materially changes the comparison. [Current runtime
contract][external-runtime] · [RapidJSON 1.26
changes](https://github.com/python-rapidjson/python-rapidjson/blob/v1.26/CHANGES.rst#126-2026-11-01)
· [RapidJSON decoder
hooks](https://python-rapidjson.readthedocs.io/en/latest/decoder.html#rapidjson.Decoder.start_object)

**Demonstration.** Round-trip representative finite fractions, zero and signed zero, integers,
bounds, null and omitted values through the actual PostgreSQL, Python, export and worker boundaries.
Reject non-finite tokens, overflow, bad Unicode, trailing bytes, duplicate keys and over-deep input
with the expected outcome. Check affected old and new payloads at their owning read/write boundary
and compare existing frozen native byte vectors before any retirement.

<a id="O06"></a>
### O06 · Keep identity encoding separate from transport and presentation

**Recommend.** Use one identity owner with named, versioned profiles for D1 keys, owned value
digests and SQL parity where actual consumers require it. Preserve the current D1 key profile and
archive bytes. Hash retained bytes directly when byte custody is the question. Derive values used
for semantic identities from declared fields and encode them under the profile, independently of
Pydantic JSON presentation, transport and PostgreSQL `jsonb` output. Declare spelling and equality
for any finite floats used in a production determinant, including signed zero and equivalent numeric
input spellings. A domain that admits arbitrary objects needs an injective profile. Avoid
introducing new Decimal identity tags for ordinary interchange. Keep existing historical profiles
readable where custody requires them, and isolate their legacy tag semantics. Inventory affected
digest callers before claiming a byte-preserving refactor. The prior inventory established the tag
collision in the encoding. The presence of that shape in production data remains open. [JSON
identity findings][json-identity] · [ADR-0100](../adr/0100-ddo-contextual-identities.md) · [D1 key
owner](../design/D1-knowledge-representation.md)

A schema digest names a contract and a source digest authenticates bytes. Neither should substitute
for the material projection in [O02](#O02). Where currently relied-on bytes move, use a named
identity transition with regenerated consumers and current custody. Preserve the original receipts
and migrate compatible retained work on its existing admissibility rules. The alternative of
selecting a faster transport encoder for every hash would leave presentation and material versioning
coupled. Retire general-purpose canonical calls for byte sizing, round-trip validation and
presentation after their actual callers move. [Canonical key code][canonical] · [Value identity
code][value-identity]

**Demonstration.** Compare pinned key, SQL and value vectors, including currently admitted legacy
values. A presentation-only setting change should leave the material identity stable. A real
determinant edit should move the appropriate identity. Compare a legacy Decimal-tagged value with a
literal object of the same shape before accepting a new profile or migration.

<a id="O07"></a>
### O07 · Generate one schema per authority and make Python and PostgreSQL agree

**Recommend.** Require an explicit dialect at schema preparation. Keep the authored wire schema
authoritative for the native protocol, derive Pydantic-owned schemas with a shared
`GenerateJsonSchema` subclass, and preserve declared LinkML, kind and external contract authority.
Move the execution-evidence splice through the common dialect lowering and put shape constraints in
the owning model. Use `WithJsonSchema` where a scalar deliberately owns its schema contribution. Pin
generated schema vectors because that hook alone leaves other Pydantic output free to change.
Replace ad hoc transformations, including the execution-evidence `close()` pass, and the detached
reader's hard-coded selection of `Draft7Validator` for kind bodies. [Wire generation][wire] · [Kind
validation and export][demand-results] · [Pydantic schema
hooks](https://pydantic.dev/docs/validation/latest/concepts/json_schema/#customizing-the-json-schema-generation-process)

Build Python validators once through a factory keyed by the effective schema, declared dialect and
trusted local registry context. Use `validator_for` with explicit supported-dialect selection,
`check_schema`, and an explicit `referencing.Registry` containing only the captured resources.
Supply structured errors from the existing correction-detail types. Choose the portable intersection
of actual Python and pg_jsonschema behavior at shared boundaries. For fixed hashes, generate
explicit length plus an ASCII hex pattern. Specify strict end-of-string matching for other admitted
patterns and verify the generated profile with the differential cases. Keep `format` advisory within
the profile. Put sensitive numeric comparisons under their owning typed domain checks where shared
engine behavior cannot be established. Use the actual deployed catalog to locate dialect omissions
and reconcile generated inventories before deleting redundant checks. [Python referencing
contract](https://python-jsonschema.readthedocs.io/en/v4.26.0/referencing/) · [PostgreSQL validator
source](https://github.com/supabase/pg_jsonschema/tree/v0.3.4) · [Retained engine
comparison][json-evidence]

The shared profile and the installed digest cover different facts. The retained dialect, regex and
precision disagreements establish that equal bytes alone cannot demonstrate equivalent
interpretation. Test the profile first with the current engines. Consider `jsonschema-rs` if the
profile is impractical, and require version, numeric input and option parity even with an engine
from the same family. Keep Draft 7 explicit for the current wire. Draft 2020-12 is a conditional
coordinated change when another warranted wire transition can absorb it. The global contract digest
is carried in every native wrapper and call descriptor, so even a local semantic fix can fan out to
the frozen native population. Inventory downstream descriptors, continuations and stored evidence
before moving bytes. Use forward native generation/admission and historical decoding at the owning
interface. [ADR-0128][wire-adr] · [Wrapper generation][native-protocol]

**Demonstration.** Diff generated schemas and the affected native artifacts. Require equivalent
answers on the supported profile at real Python and PostgreSQL boundaries. Exercise unresolved
references without retrieval, tuple element rejection, fixed digest with trailing newline, narrow
fractional boundaries and mixed draft input. Preserve client refusal and rollback under a mismatched
contract or an off-contract result.

### O08 · Carry established guarantees through event work and JSON validation

The bounded event journey entered the scorer at 838.2 seconds under a 900-second watchdog.
Publication of frame, fit and authorization already occurred. The scorer attachment and two negative
cases did not complete. A prior run spent more time before the first protected-data refusal, with
several differences in scope and source. Identical cuts and same-release correspondence already have
two bounded duplicate-work fixes. Current code can still paginate the frontier and gather the whole
support closure, then derive validity for the same shared producers across roots or pages. The
retained result and stage markers identify the phase that stopped. They provide no database wait or
nested statement attribution, and no established contribution from JSON. [Event
evidence][causes-event] · [Demand support acquisition][demand-results] · [Support edges][support]

**Recommend.** Acquire the sufficient support projection for the selected use. Reuse established
material guarantees within their authenticated cut and validity scope through existing reader and
operation owners. Batch repeated validity work on shared nodes while preserving each root's distinct
attribution, missing-member behavior and keyset page semantics. Acquire a fresh cut or current
authority for changed epochs, principal, purpose, disclosure and publication. Prefer local sharing
to a general persistent result cache. Keep the real event journey with bounded source preparation,
native publication, scoring and protected-authority controls. Use a bounded private replay to
discriminate remaining physical work before changing SQL. Sample waits and blockers during scorer
attachment, then compare the duration, call count and plans of the identified phase only. Keep a
genuine integrated journey for qualification. A longer watchdog would supply evidence of eventual
completion, with the observed amplification still open.

Apply the same ownership rule to JSON checking. The current native frontdoor already checks requests
in SQL and checks installed digest and client results before transaction commit. Start the
follow-through on PE-RC01 and PE-F04 at residual validation, copying and encode/decode work. Create
one owned snapshot at true ingress and carry it through trusted typed/native consumers. Retire
repeated field-copy passes where the type prevents mutation, `_validate_wire_value`'s
encode/decode/encode pass when one walk and schema check suffice, and repeated structural validation
on rows whose immutable write custody and unchanged contract establish the property. Keep detached
export validation, actual effects and domain checks, and the SQL-result check where the call commits
internally. Schema agreement and custody must establish the premises before each redundant check can
retire. Link residual obligations to UDM's current wire and qualification owners when this work is
selected. [Current native frontdoor][storage] · [ADR-0128][wire-adr] · [Prior validation
obligations][ddo]

**Demonstration.** Show one boundary check per direction and one detached-export check on the
affected routes. Exercise identical and distinct cuts, a changed epoch and revoked support, a
substituted use and counterfeit authored parameters. Confirm genuine event scoring and its expected
value, native authorization leaf, and refusal of protected frame or label bodies. For M1 and
equivalent targeted assertions, request only their operation's read scope. Assess physical cost from
the affected path rather than extrapolating timings from the retained timeout.

### O09 · Resolve configuration once at the settings owner

**Recommend.** Have acquisition, workers, CLI and private fixtures receive sections from the one
validated `Settings` construction route. Derive private-cohort scrubbing from the settings model
through `known_env_names`. Translate `SettingsError` at the boundary and expose redacted origins via
`settings_sources_data`, with validated construction for profiles, credentials and authoring
targets. Use `JsonConfigSettingsSource` for the execution-policy file if its merge and precedence
agree with current behavior. Keep product environment variables with settings and CI lane controls
with `ci`. Move any target fingerprint to [O06](#O06)'s identity owner when its digest basis
changes. Retire direct section constructions, handwritten scrub lists, private origin lookup and
unchecked copy/update paths. This change can proceed independently of the codec and schema changes.
[Settings proposals and confirmed defects][json-settings] · [Current settings owner][settings] ·
[Pydantic Settings source
state](https://pydantic.dev/docs/validation/latest/concepts/pydantic_settings/#accessing-the-result-of-previous-sources)

**Demonstration.** Confirm the private cohort excludes `CORPUS_DEPLOYMENT__URL`, normal Nemotron
endpoints reach each selected consumer, malformed input produces one bounded diagnostic, and a valid
origin report retains precedence without exposing secrets. Preserve the existing separate
disposition for removing `llm` and `gpu` sections.

Start with selected executable preparation and its diagnostic using the current archive and native
contracts. Compare the historical edit pair before narrowing an enforced boundary. The settings and
decoder hardening that preserve existing transport can proceed independently. Project typed consumer
requirements next or in parallel. Device-specific resource checks and current authority stay with
their current acquisition and effect owners. The decision on cross-request recovery follows the
material projection and its demonstrated coverage. A private bounded regional case should establish
the intended behavior before the whole-book run.

Specify the JSON roles and numeric model before changing codecs or hash inputs. Reconcile the actual
consumers of fractions and stored typed bodies, including dynamic prepared packs, and exercise the
new domain on actual paths. This replaces the need for a general Decimal field inventory with a map
of type-sensitive boundaries, comparison rules, and existing durable representations. Classify old
hashes as byte custody, value identity or incidental uses before retiring any encoder. Keep the
RapidJSON 1.25/1.26 byte comparison and callable contract check conditional on that dependency
surviving on a byte-sensitive path.

Make schema dialects and registry ownership explicit before dropping checks. Verify pattern handling
on installed cases, including variable-width patterns, and inventory kind `body_schema` keywords in
their actual declared dialects. Use the generated and installed function population to resolve
source-versus-catalog call counts. An ECMA engine remains a conditional option if a portable profile
cannot express the needed constraints. Determine the global digest fanout before selecting a schema
migration and preserve independent validation at detached boundaries. The prior open checks are
inputs to these transition decisions, including the literal Decimal tag collision. [JSON open
checks][json-open]

Use the event diagnostic to select the physical change independently of library adoption.

attempt cannot distinguish those costs. Use the bounded diagnostic in [O08](#O08) to select the
first physical change. The recommendation to avoid repeated work within identical premises rests
on source and the already removed duplicate paths. [Retained event attempt][causes-event]

material identity and acquisition, UDM-05/06 and the role/effect owners govern admitted
