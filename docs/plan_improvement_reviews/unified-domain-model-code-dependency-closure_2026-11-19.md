# Unified domain model · Code dependency closure review

**Date** 2026-11-19. **Inspected baseline** `aa128c808`, clean at entry. **Standing** Proposed recommendations and bounded observations. The [UDM coordinator][udm], [program identity][identity], [cache system][cache], [qualification][qualification], and [operational CLI][cli] supply the current obligations. [DA-075][da75] remains owned by the coordinator.

## Judgment

Give the generator and selected readers explicit, different workload boundaries over one source-custody mechanism. For the generator, start with the exact inputs needed to reproduce the stored artifact, including source bytes it records as provenance. For readers, identify the code that derives the ordered response under an already acquired native cut, including its query contract, bounds and diagnostics. Preserve native authority at every lookup and keep the scoped entity content witness separate from Python code identity. Improve the existing static analysis where the resulting boundaries actually need it.

The four reproduced scans have identical sets of 33 findings and populations of 585, 585, 585 and 589 modules. They contain 21 compile, loaded-text or evaluation findings, 11 nonliteral imports and one file loader. They describe occurrences in a module population. Two of the most prolific owners, operation ports and consumers, account for 21 of the findings. One import path is the automatic scan of package parents, which then visits the local `from .prepare import …` inside the public preparation wrapper in `semantic/__init__.py`. This expands the static population into orchestration even for entry points that have no reason to call preparation. The entry modules currently supply no callable roots to the identity scanner. [Original qualification][previous] · [Reproduction and fixtures][probe]

The existing process distinguishes authenticated loaded bytes, determining identity and cache compatibility. Preserve those distinctions. `_query_custody` observes what the process actually imported and refuses supported drift. A complete determining identity additionally requires the supported workload's initialization, call and external-input boundaries to close. A storage codec or retention change may invalidate cache entries while leaving a semantic continuation valid. Under incomplete identity the reader still derives a fresh authorized page and withholds resumability. [ADR-0137][adr] · [Identity contract][identity]

**Observed · 2026-11-19.** The uncalled function fixture reported a dynamic import despite its independent runtime result depending only on a relative alias. A second fixture changed the result through import-time initialization and the current narrowing refused that initialization. A third fixture used an indirect, ordinary `getattr` lookup of an import function. Changing the imported helper changed the result while the analyzer returned the same complete digest. This is a bounded counterexample to treating recognition of a fixed syntax list as general completeness. It does not establish that any of the four production requests took an equivalent path. [Probe][probe]

For 05–31 and 33, the repeated scan does not differentiate which roots reach the owning operation. G must separately account for PDF and Arrow schema preparation, version checks and any exact captured files. N/R/F consume native results and authorizations, with no observed production evidence that they invoke the listed producer verifiers. The proposed narrower boundaries must establish that fact before pruning branches. Treat any reachable annotation evaluation as execution with a namespace, including eager effects and the second evaluation of strings. Compiling bytes for a comparison is distinct from executing those bytes, and even a verified comparison can affect failure or eligibility.

## Recommended amendments

<a id="I01"></a>
### I01 · Separate initialization, callable reachability and byte custody

**Proposed · shared prerequisite for UDM-10, UDM-14 and UDM-15.** Keep one captured module population with attributable source sites. Use a separate projection for import initialization and reached code, including eager decorators, defaults, class bodies and metaclasses, supported runtime annotation evaluation, and imports performed on callable branches. An import edge initializes a module under the supported loader, while an uninvoked function's local import is a separate edge. Keep unresolved dispatch or effects in the model. A proof of closure must name the supported scopes and the binding or explicit capability that authorizes each dynamic edge. Preserve the distinction between execution, verification and copied provenance. [Core DP-02, DP-08 and DP-09][principles] · [Code-intelligence CI-01–07 and CI-10][profile]

Extend the existing `ClosedPythonSources` model where it establishes real bindings. Use `ast` for normalized syntax and explicit initialization forms. Replace module-wide alias heuristics in the authoritative path with scope-sensitive binding. Use LibCST's `ScopeProvider` and qualified-name metadata. The pinned 1.9.0 probe confirms that `FullyQualifiedNameProvider` adds the repository-relative target that the existing lexical `QualifiedNameProvider` leaves relative. Build the production `MetadataWrapper` from captured source, supplying the provider cache with its captured module and package names. The probe used `FullRepoManager` only over its temporary fixture. Use Griffe's static aliases and existing re-export traversal to resolve effective interfaces from that same population. Use the existing bounded Astroid inference only where the receiver is closed under the admitted inputs. Ambiguous or uninferable outcomes retain their standing. [AST][ast] · [LibCST metadata][libcst] · [LibCST implementation reference](https://libcst.readthedocs.io/en/latest/_modules/libcst/metadata/name_provider.html) · [Griffe aliases][griffe] · [Astroid inference][astroid]

Use ast-grep `SgRoot` patterns for inventory and structural candidates such as resolving a repeated loader family. A match gives a syntax location, and the binding or owner establishes its meaning. Use `ty` definition, implementation and reference navigation to explore disputed receiver paths during review or development. Stub and otherwise inferred results remain distinguishable from executed implementations. Neither tool needs to be added to the production reuse decision. NetworkX can derive root reachability, path explanations or strongly connected components from the existing typed relation projection if operator inspection warrants it. The direct walk or an existing projection is sufficient for the initial slice. [ast-grep patterns][astgrep] · [ty navigation][ty] · [Official ty LSP reference](https://docs.astral.sh/ty/features/language-server/) · [NetworkX traversal][nx]

Bind bootstrap 01–04 explicitly through the existing authenticated loader and source-custody checks. Where dynamic work is material, reuse the `OpaqueBoundary` pattern and runtime authenticator for the owning operation. Require exact captured members, relevant external resources and versions, and refusal when the loaded origin, binding or resource falls outside the contract. An opaque label or one observed runtime trace supplies no such assurance on its own. Reuse `AuthenticatedSlice` for checking mutable runtime premises where its contract fits. Once migrated, retire the authoritative blanket initializer refusal and syntax-only decision for the supported workloads. A conservative discovery report can still locate unsupported constructs.

<a id="I02"></a>
### I02 · Capture exact generator inputs and identify the rendering workload

**Proposed · UDM-14 D2 and the existing T2 generator preparation.** Make the authoring owner capture a typed, immutable input before evaluating a store key. Include physical sources and LinkML types, the effective compiled model inputs, logical and action/PDF overrides, extra sources, named package resources such as `operation-vocabularies.yaml`, and the runtime versions used by PDF/schema preparation and SQL rendering. `include_producer=False` still prepares PDF lowering and Arrow schema inputs. `running_model()` supplies data even alongside physical overrides. Bind the admitted renderer code, initialization and effective library/runtime identity separately from these data inputs.

`ProgramSetArtifact` contains extensive exact Python and resource provenance from native input capture as well as rendered programs, prerequisites and a manifest. Files captured by `native_products._capture_native_authoring_inputs` and `data_operation_storage._native_protocol_sources` remain determining bytes even when their code never executes during rendering. Move the file acquisition and shared capture before the key, pass captured bytes into rendering, and retain the validated artifact and predecessor checks after hydration. Share this basis between T2 and D2 so the package-wide T2 fallback and separately keyed exact-module D2 sweep can be retired when their consumers have moved. A future split between rendered bytes and provenance could preserve more reuse across source edits, but would change the replay artifact. Revisit if observed recurring changes warrant it. [Artifact and generator contracts][cache] · [Identity and revision owners][identity]

A bounded generator-specific execution envelope is a credible alternative where a finite set of exact code, initialization, resources and external inputs can be enforced sooner than the callable projection. Its wider invalidation is acceptable for material artifact inputs. A worker process earns adoption only if it enforces a real boundary that cannot be handled through typed acquisition in-process. Keep SQL verification, installation effects and authorization with their existing owners. Nominally unchanged generated SQL or catalog can be established through the existing offline candidate comparison.

<a id="I03"></a>
### I03 · Separate deterministic read derivation from acquiring native authority

**Proposed · UDM-14 D4, UDM-15, and the corresponding retained-reader routes.** Use the query/profile contract and verified code that determines the page, including the selected query, row ordering, diagnostics, limits and interpretation of the cursor. Let acquisition supply typed authorization, cut, selection and native support references before any cache lookup. On a miss, acquire and confirm the body under the same authority before passing its typed contents to derivation. Require a complete, authenticated identity for production retention. Verify imported-code drift independently, including bootstrap provenance. A closure refactor must account for `reusable_serving_code` allowing an absent context for lower-level callers, so a new production route cannot acquire reuse by skipping the serving boundary.

Keep contribution facets, normal native demand continuations and other rich profiles on their actual exact cuts unless a query-specific dependency argument supports a change. Exclusion comparisons keep two cuts. Keep the entity witness based on its authorized frontier and exact body and disclosure premise. Fresh acquisitions still supply fresh native pins and per-request diagnostics. Carry exact examined-input and encoded-width semantics through any extraction of the row kernel. Version semantic continuation interpretation when meaning changes and report explicit refusal of incompatible cursors. Keep disk codec and cachetools versions in retention compatibility. Move CLI and MCP callers to the same derivation and custody mechanism and remove duplicated page gate or digest paths made obsolete by adoption. [Cache and content basis][cache] · [Serving custody][adr]

A narrower kernel reduces the design's dependence on whole-program analysis and avoids reading the full rich body on a valid hit. Retaining the current whole-module scan as the eligibility test leaves both real entry-point reuse paths blocked. A better static analyzer alone would still have to explain unrelated orchestration, provider and authoring modules, exact captured artifact resources, and fresh native disclosure. The combination of I01–I03 assigns each of these premises to an owner.

<a id="I04"></a>
### I04 · Explain blocked reuse at the owning CLI operation

**Proposed · UDM-26.** Extend the typed report from the authoring or read operation with a bounded code-identity explanation. Show the entry point, whether derivation or reuse proceeded, the blocking source site and owner, the relationship that brought the site into scope, and the next supported action. Attribute unknowns, runtime observations and proven edges distinctly. Expose the same bounded view in JSON so a later operator can inspect it without parsing a human message. Retain the compact default in public reads and limit source details to the local diagnostic route. Keep cache statistics about their actual owner and invocation, since a fresh statistics process cannot observe other processes' hits. Reuse the existing CLI rendering conventions and remove the standalone first-site/omitted-count formatter once its consumers move to the shared report. [UDM-26 operational projection][cli]

## Qualification and remaining decisions

- **D2.** With an isolated cache root and unreachable database endpoints, run two fresh processes through the installed `ci schema native-candidate` path using actual custody. Verify one render and equivalent validated artifacts and program manifests. Exercise a changed rendering determinant, model/resource bytes, runtime or artifact provenance. An unrelated edit outside both the execution and captured provenance boundaries should preserve reuse. Re-run the existing offline `no_native_change` comparison on the N34 declarations. Keep predecessor and native authoring validation after artifact hydration.
- **D4 and T4.** Use the installed `ci query` command for native demand and rich requests, then resume an issued continuation in a fresh process. Verify expected rows, order, ordinal and bounds independently. Reacquire authority before disk inspection. Changes in selection, pinned support, runtime, disclosure or implementation must prevent a stale hit. A codec change can force rederivation while preserving compatible continuation. Exercise contributor and MCP paths that share the identity, with their actual cache scope.
- **UDM-15 and T14.** Use two fresh native acquisitions of one immutable admitted entity and verify one derivation, identical eligible rows and distinct current pins. Refuse a revoked or differently scoped read before it affects hit counters. The existing authored publication setup in `tests/semantic/record_publication_native_support.py` builds typed entity and proposition packets and commits through a native fixture. `test_native_selected_reader_pages_and_pins_actual_product_and_support` already uses this setup for a cursor journey. Adapt its authored publication to an explicit entity request in two processes against the same private native target. **Feasibility lead · source-inspected.** Verify fixture viability under N34 before relying on it. The separate upstream PDF fixture failure remains open. [Prior evidence][previous]
- **Shared analysis.** Use the captured probes and independent expectations for alias rebinding, type-only imports versus runtime guards, eager initialization, dispatch, copied provenance and verified dynamic loads. A genuinely unknown determinant remains visible with fresh derivation available where authorized. Verification should cover the actual installed entry points, alongside targeted unit controls. [Qualification T4 and T14][qualification]

Sequence the shared bootstrap and authored workload captures first, then qualify D2 and D4 independently. Qualify direct entity reuse after the native fixture establishes its existing witness premise. Wider content reuse and restricted workers are conditional. A production plan amendment should record which closure guarantees are selected, address any consequential contract transition through the existing decision owner, and carry actual entry-point qualification into UDM-22. The review's probes test the current analyzer and a library capability in isolation. The four production closures, private entity fixture and broader UDM qualification are still open.
