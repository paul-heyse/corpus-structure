# Domain Model Operability after the N44 execution slices

**Date:** 2026-11-21. **Inspected source and plan:** `e14ca6f3d` on main, including all four
[DMO companions][plan]. The working tree also had older PDF, M1 and WCE evidence edits and local
library notes. The conclusions use the current implementation, the committed evidence and the
pinned environment. [Status][status] records the dedicated stage at N44 with both applications
admitted and canonical development at N29 with the book on generation 5. The tuple experiment
used a separate private N44 clone.

## Judgment

Keep the existing native reuse, publication, cut, deployment, and managed-result owners. The
remaining difficulty is making each decision at the boundary where its prerequisites can be
established, then carrying that decision to its consumers. The highest product priority remains
the first actual Standard reuse across demands. A complete support read and export can proceed in
parallel. The staged tuple trial and frontier migration supply useful contrasts for routing
changes. Reuse their evidence at its recorded scope. The prior [post-N44 review][n44] supplies
finding lineage and the [design standard][standard] supplies the assessment criteria.

These proposals cover DMO-01 through DMO-09 and the adjacent harness, CLI/MCP, and archive paths
materially affected by them. DMO-00 supplies the baseline. The real three-page Docling spool
resume, native lost-acknowledgement case, and event read each establish a different property.
This review adds source inspection, analysis of retained receipts, and targeted library research.
The proposed integration cases below have their own future verification boundaries.

## I01 · Make Standard attachment decidable before provider startup

**DMO-01/02 and DMO-07. Refines N44 I01/I02.** `pdf_capture_assets` still obtains eligibility
from combined Standard and Integrated lowering analysis. The earlier probe left unresolved
dependencies after removing the explicit Integrated roots. The current worker authenticates the
initialized bindings and resources, reports its profile, and waits for replay acknowledgement
before conversion. That covers the matching spool case. The first demand-independent Standard
capture still needs material correspondence that the parent can establish without starting a
provider. The initialized descriptor observes loaded methods and resources. It leaves transitive
helpers and dynamic bindings to the admitted execution contract. [Capture eligibility][capture] ·
[Worker handshake][stream] · [Initialized report][runtime] · [DMO-02 and scoped receipt][identity]

**Proposed.** Extend the selected-executable acquisition owner to obtain the selected Standard
recipe and options, actual converter/backend/stage selection, code and resource custody, and
streaming, restoration, and lowering behavior that determines published output. Bind the
contract to original bytes, declared scope and output schemas through the existing material
predicate. Where a selected callable closure can account for that surface, reuse the current
external-runtime acquisition. Where ambient imports defeat a credible boundary, isolate the
actual dependencies and resources in a bounded producer package with an explicit contract.
Package identity alone leaves resource, dynamic choice and first-party lowering questions open.
Keep demand-scoped eligibility wherever a determining fact is unresolved. Use the worker's
existing prepare acknowledgement to verify that the chosen executable actually loaded the
acquired bindings before conversion or checkpoint uptake. Retire the combined eligibility gate
for Standard once its consumers use the new decision. Keep broad dependency discovery at its
analysis owner. DP-04, DP-09, DP-10, DP-15.

Pinned Docling 2.148.0 exposes PDF format and artifact options. Installed source shows
`initialize_pipeline` reaches `_get_pipeline`, whose instance lookup keys on class and options.
`StandardPdfPipeline._init_models` builds the model stages through factories using options and
artifact location. That instance key cannot establish the repository's material equivalence.
Use the selected Docling Core 2.106.0 output contracts where they govern serialized meaning.
Python inspection and distribution records supply runtime facts, and ty, LibCST and the existing
NetworkX projection can supply attributed source facts. Cachetools 8.0.1 can retain process-local
prepared observations keyed by already acquired facts. Its cache policy cannot grant durable
attachment standing. The existing native owner should continue to decide that standing.
[Docling tagged converter][docling] · [Tagged pipeline][docling-pipeline] ·
[Runtime acquisition][external] · [Cachetools overview][cachetools]

Keep the implemented shared-host grouping, preflight and declaration path. Check that guarded
reacquisition and startup still consume the same selected inhabitants and recheck mutable premises.
No new host coordination layer is warranted by the present observations. The discriminating case
is a real second Standard demand after transport-only change, with the original derivation and
attempt and zero provider starts. Keep the D1 scope contract for this slice. Challenge a model
file or loaded stage change under identical package versions and recipe text. Preserve the
independent restored-page comparison and refusal of changed replay, live writers and revoked
publication authority. Challenge a stale selected host before claim and a mutation between
preflight and startup. [Host preparation and controls][host]

## I02 · Derive support interpretation from the exported relation and its captured kind

**DMO-03/04/05/06. Refines N44 I04/I05.** The frontier has declared field roles and retains exact
cut member bytes. The selected support row already names its relation and key, but its
`record` allows arbitrary JSON. The non-frontier decoder still classifies by key spelling.
`ops.data_request` has a real contextual `analyzed_scope`. An ordinary field of the same name
inside a `kb.data_product` body does not acquire that role. Parquet currently derives its shape
from ambient relation metadata intersected with observed column names. That can drop an
unrecognized column or change the projection for a historical export. [Open wire shape][wire] ·
[Native support production][projections] · [Projection fallback][wire-code] · [Parquet shaping][export]

**Proposed.** Deliver the request and associated product through one actual selected support
path. Derive the transfer projection from the existing domain and native declarations plus the
exported exclusions. Describe virtual authority/evidence records at their owning declarations.
Dispatch the wrapper by authenticated relation and any embedded body by captured nominal kind.
Pass the prepared interpretation through captured and ambient calls, temporary indexes, detached
verification and Parquet. Reuse the kind capture that export already performs. When a relation
or kind cannot be established, report unsupported semantic interpretation and retain the
authenticated bytes for custody. Keep JSONL as the detached closure and derive Parquet from its
captured shape with explicit column correspondence. A separate maintained relation registry
would duplicate the export authority. The existing generic decoder costs semantic precision.
DP-01, DP-02, DP-06, DP-11, DP-24. [Index and replay][index] ·
[Detached contract capture][export-capture]

Keep the exact bytes and checksums of the captured format separate from interpretation. The
index and export currently encode values received in a native projection. Their output is the
relevant byte boundary and need not reproduce original database numeric spellings. PostgreSQL 18
documents the different representation of `json` and `jsonb`. Preserve D1 equality and strict
integer checks at declared boundaries, with finite ordinary values and no new general exact
decimal requirement. Reuse LinkML 1.12.1 effective slots where LinkML owns the field meaning.
The installed runtime's `class_induced_slots` calls `induced_slot` for the selected class.
Use the existing Draft 7 prepared validator and typed adapters at their own boundaries. Psycopg
3.3.6 connection-scoped JSON hooks remain transport adaptation. They do not select a domain role.
Revisit RapidJSON 1.25 only for a surviving dependency on its bytes or options.
[PostgreSQL 18 JSON types][pg-json] · [LinkML effective slots][linkml] ·
[Wire validation][wire-code] · [JSON library and settings disposition][json]

Verify a real request/product page, ordinary nested `analyzed_scope`, fractional D1 fields,
later-page support, changed cut and live-authority refusal, and detached replay with changed
ambient declarations. Independently check the identities, original cut bytes, manifest checksums
and Parquet shape. Move request reconstruction, index replay, detached payload readers, and
prepared pack and operator consumers to their declared readers in dependency order. Retire
spelling-based branches, wire/row aliases and codec adapters as their last consumers move.
A live authority result must still be reacquired where the consumer requires it.

## I03 · Explain rollout using the changed contracts and acquired target

**DMO-05/06/07. Refines N44 I06/I07.** Frontier interpretation changed in Python and passed the
recorded native and archive selection while the compared wire and kernel digests still matched
N44. The tuple experiment changed three generated facades and the native wrapper. It required
approval of the after-state, capture, forward native install, and independent Standard and
Integrated admissions. An indirect Python edit refused, and Integrated initially refused on a
pre-apply baseline. Recovery resumed the original candidate after migration had committed and
before application admission. [Frontier checkpoint][json] · [Private tuple trial][trial]

**Proposed.** Extend the existing `ChangeEffects` and managed views with independently attributed
generated-source, application material/runtime, native/catalog and target-prerequisite
comparisons. Show which applications need capture or admission and which generation or install
is required. Leave an unobserved dimension explicitly uncompared. A matching digest establishes
only the scope owned by that digest. Preserve the staged deploy controller, release lock,
same-candidate recovery and installed readback. Keep the conservative Python capture deferral
until approved after-state and implementation membership can show that a specific edit does
not reach an application's captured inputs. A separate rollout classifier would have to
reconstruct these facts and rules. DP-01, DP-04, DP-19, DP-21, DP-24.
[Preview effect model][change] · [Deployment custody][deployment]

**Target prerequisite.** PostgreSQL 18 template copies omit database-level grants. A cloned
target can therefore contain a current migration revision and still lack the required TEMP
policy. The test clone owner already supports declared policy replay and verifies the resulting
policy. Use that route when the selected scenario requires an exact seed policy. For a private
trial with a narrower declared TEMP policy, reuse the existing `DatabaseTemporaryPrivilegeOp`
and its admission check. Expose the disposition before expensive authoring or admission. This
is a target acquisition opportunity, with no evidence of a general fixture policy defect.
Keep Alembic 1.20.1's custom operation and revision APIs for
the effects they own. SQLAlchemy and pglast can describe or inspect intended SQL, while the
installed revision, grants and native descriptor must come from the acquired target.
[PostgreSQL template databases][pg-template] · [Test clone preparation][clone] · [Native TEMP operation][temp] ·
[Admission check][admission] · [Alembic operations API][alembic]

Use frontier and tuple as contrasting cases. Add discrimination for an indirect captured edit,
a target-local privilege mismatch despite equal heads, a committed migration with admission
pending, and a second application on the same native revision. Trace validator-family inputs
through deployed wrapper and wire dependencies before reducing any revalidation. Preserve
unaffected-family currency where its determining inputs agree. Evaluate wire partitioning only
if independently deployable consumers and a material reduction in rollout burden emerge.

## I04 · Carry the owner's recovery disposition into operator inspection

**DMO-02/04/07. Refines N44 I03/I07.** The executor already chooses `reconcile`,
`inspect-draft` or `compute` and can settle or adopt before acquiring a physical port. The
settled native intent, draft custody and worker retirement answer different questions.
`ExecutionRecoveryAccount` retains the invocation selection and configured target.
`NextAction` currently offers a resume when those inputs are captured. That fact by itself
cannot tell the operator what resuming can do. [Executor decision][recovery] ·
[Captured invocation][recovery-account] · [Result inspection][inspection]

**Proposed.** Preserve resume as an executable action that rechecks current premises. Attach
the owning disposition and its observation scope when it is available. Let current effect
inspection report the native intent, lease and receipt, the process owner report retirement,
and draft inspection report compatible retained bytes or a regeneration reason. A passive
preview may describe required observations without claiming current readiness. A retained
recovery action should bind the applicable target, invocation, candidate or demand, and effect.
A continuation carries the recorded cut and bounds. A fresh query obtains current authority.
Consume these same facts in human and machine views and remove duplicated diagnostic lookups as
their consumers move. Keep unknown standing explicit when a status or authority fact has
expired. DP-05, DP-18, DP-19, DP-21. [Exact read and action handoff][consumers]

Use Typer 0.28.0 for typed selectors and context, Rich 15.0.0 for rendering with the existing
stderr route, and the installed Typer runner's separate stdout/stderr streams to check delivery.
Preserve the existing structured FastMCP result and actual serialized byte bound. Rendering
depends on the owner-supplied facts. It supplies no grant or recovery authority. Check that a
lost commit acknowledgement leads to reconciliation with one receipt and zero duplicate
submission after retirement. Contrast known rollback, a surviving worker, a missing historical
writer contract, a target mismatch, and changed live authority on a continued query. The
recorded native composite supplies the first bounded scenario. Include that native settled
effect when evaluating whether a new CLI action is honest about prerequisites.
[Typer overview][typer] · [Rich overview][rich] · [Structured delivery decision][mcp]

## I05 · Share stable setup and keep each qualification claim independent

**DMO-08/09 with DMO-03/04/07 and the managed test owners. Refines N44 I08.** The positive event
case independently checks score and issuer plus protected support through the selected cut.
The authored same-kind negative challenges producer identity. The ordinary-purpose refusal
actually reached PostgreSQL's grant and failed the old message expectation. The current
frame-only case asserts that grant independently and tests substituted-use refusal under the
authorized fit purpose. The retained reportlog records 637.56 seconds of setup and about
0.02 seconds of call time for the frame-only selection. The earlier combined selection recorded
1,005.79 seconds of setup for the first test on a different source and fixture selection. That
comparison shows where to investigate setup. It establishes no controlled speedup.
[Event evidence and retained result paths][consumers] · [Fixture and assertions][event]

**Proposed.** Keep a full positive native journey and the independent same-kind refusal.
Reuse the frame fixture for the privilege checks and consider reuse of immutable admission or
prepared infrastructure only when the acquired target, release, state, and isolation support
each assertion. Use the existing `preparation_fixture`, affinity reporting and managed
xdist lane. Where two selected cases share the same safe preparation, place them on the same
worker through the existing grouping. xdist 3.8.0 `loadgroup` co-locates a group. Each worker
has its own fixture cache. An exclusive native fault still owns its separate lane. Use
pytest-reportlog 1.0.0 and the managed test schedule and review views to distinguish setup,
call, teardown and watchdogs. Consider narrower product hydration only where a scoped read
demonstrates the same required semantics. The event evidence leaves lock/transaction and wider
regional attribution open. Apply the same judgment to M1 and regional reads before proposing
set-wise changes, preserving per-intent outcomes and exact cut authority. FP-07, DP-10, DP-23.
[xdist 3.8.0 distribution][xdist] · [Managed evidence owners][qualification]

For DMO-08, assess carry-forward per claim against current source and generated contracts,
acquired target, application/runtime, provider and fixture context. Keep original failed and
interrupted receipts. Use the installed route for claims about operator behavior. Reobserve
affected properties on the final source, including real providers, isolated faults, and the
first Standard cross-demand pass. DMO-09 then uses that readiness for guarded canonical
adoption, original custody and the complete book, with independent stop/recovery and unchanged
repeat checks. Scoped installation or model results cannot supply the whole-book claim.
[Qualification and adoption][qualification] · [Test assessment][test-assessment]

## I06 · Sequence the remaining integrations around complete paths

**DMO-01–09 integration.** Walk a representative region from selected acquisition and
publication to continued read and interrupted recovery. Prioritize I01 on the current D1
contract. In parallel, take I02 across publication, page, index and detached export. Use I03 to
decide which generated and installed transitions that slice actually requires. Add I04 action
views as their owning facts become available. Remove superseded decoders and adapters with
their consumers. Keep dated evidence, and move a one-off operational step into an existing
command or managed fixture when it has a recurring consumer. DMO-08 assembles applicable
observations after consumer retirement and DMO-09 consumes that readiness. [Current queue][plan]

Keep mechanisms local to what changes together. Prepared validators, selected-host checks and
intent deduplication already have owners. Consolidate where inspection finds the same validation
or preparation repeated on the same authenticated input. Retain independent validation where
a different authority or claim requires it. Bounded cache use is an option for repeated local
preparation. A persistent cache or additional coordination plane would need a concrete
unserved workload and a clear lifecycle owner. The review offers proposals for the existing
plan and decision routes. Product checks, provider reruns and database changes were
`not_run` in this review. The recommendations rely on scoped prior results and source
inspection, with the specified discriminating cases left to implementation.
