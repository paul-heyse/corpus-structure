## Context

DDO Domain-model I05/I09 requires replacement of rich record admission and protected evaluation
without old run, task-keyed record or evaluation table facades. The operator authorized the bounded
DDO-09/10 prerequisites for complete retirement. The existing fitted policy separates evaluator
permission to use an exact predictor/calibration instance from correctness checks on each new
production reading. Protected complete-record labels and calibration populations must not become
ordinary producer inputs. The DDO coordinator owns implementation and qualification; this decision
settles the disclosure boundary, not a successful production qualification.

## Options

1. Keep protected products as ordinary transitive producer inputs. Rejected: ordinary support
export includes request bindings, completion intents and all reached episode inputs/outputs; hiding
only label bodies would neither provide complete ordinary provenance nor preserve confidentiality.
2. Store opaque authorizations in a separate table with another publication/receipt protocol.
Rejected: this duplicates generic product, support, revocation, recovery and exact-effect custody.
3. Issue an ordinary policy-authorization product through the existing evaluator native effect and
explicitly represent its protected support boundary in public provenance. Selected. Native validity
and locks retain full support; ordinary readers receive the permitted conclusion and bounded
provenance. This adds a disclosure distinction to existing custody rather than another lifecycle.

The selected approach keeps expensive interpretation and fitting outside publication locks, reuses
indexed native support and generic request settlement, and prevents each rich consumer inventing a
label-filtering protocol. Detached verification must explicitly understand the bounded disclosure;
it cannot claim to reproduce the hidden assessment. These are qualitative expected benefits.

## Decision

Protected reference, complete-record grade, feature-fit and calibration products retain evaluator
universe. Actual feature fitting retains its restricted feature-fit capability; broad evaluator
access is not a substitute for fitter isolation. Existing authored case comparison reports remain
comparisons and do not become whole-record grades or publication authority.

A dedicated evaluator command issues an ordinary immutable authorization for an exact policy
instance, its predictor/calibration, numerical and family interpretation, applicability, event
procedure, threshold procedure and question/rubric basis. Only its authenticated native producer,
effect/factory and committed completion receipt grant this authority. An authored same-kind value,
copied JSON, successful unrelated task or caller-supplied eligibility flag cannot. The issuer has
only the ordinary authorization output; assessment computation precedes this command.

Native support validity, trust-scope locking, reverse impact and revocation retain the complete
protected dependency closure. Ordinary provenance stops at an explicit authority leaf and exports
only the allowlisted issuer/output summary. It excludes protected inputs, request bindings,
completion-intent payloads, other outputs and hidden support edges. Detached validators and graph
consumers recognize this bounded provenance form; protected dependency details remain unknown,
not absent. New effects always reacquire native authority. Ordinary export may report approved
revocation standing, never protected selector payloads or free-text reasons.

Authorization of a fitted instance does not establish a new reading's correctness or scientific
truth. Rich admission separately authenticates each selected reading, source/context, interpretation,
feature input and unique completed final event against that exact instance/procedure; enforces
finite calibrated probability/threshold, complete required field/evidence and unresolved alternative
rules; and verifies the exact accepted output/lowering population. New production readings need not
belong to calibration samples. Applicability is checked subject/context/population membership,
not a caller's subset string. A separate exact-member assessment, if used, has its own meaning and
cannot be passed off as fitted-instance authorization.

Explicit support pins remain immutable. A new reference/adjudication or newer instance does not
silently replace the pinned basis. Direct issuer/recipe/runtime/output revocation invalidates its
authority and downstream admission; equal-value substitution cannot rehabilitate that direct
revocation. No universal latest-reference policy is introduced.

## Consequences

D1 owns authority as a typed assertion with bounded public provenance; D5 owns per-reading admission;
D7 owns protected evidence and fitter isolation. Existing DDO request/attempt/fence/effect receipt
owners retain physical custody. The rich companion specifies affected consumers and refusal cases.
Acceptance records the target choice in force. Implementation, native disclosure/refusal controls,
protected-purpose integration and complete qualification remain open in the coordinator. No persistent
deployment, activation, reset or historical conversion is authorized or performed by this record.
