## Context

The operator approved the unified-model completion-audit remediation and removal of legacy code
on2026-11-02, then explicitly selected resetting all seven identified project-result databases on
port5434. Historical result compatibility therefore has no retained operational consumer. Current
release custody, exact semantic identities, query binding and frozen migration history remain
necessary for new results. This supersedes ADR-0046's older-format support boundary and carries
forward its Core/native/domain-authority decisions below.

## Options

1. Repair and retain every historical reader and the semantic-1 execution route. This preserves
   old results but adds version-specific adapters and a second live execution path without an
   operator-selected consumer.
2. Retain compatibility silently while ignoring its failed controls. Rejected: that misstates
   support and preserves ungoverned alternatives.
3. Reset selected generated results, migrate current callers to composed execution and record
   products, and retire obsolete execution/readers. Selected. This removes migration burden but
   requires fresh intake and porting independent expectations to current fixtures. It does not
   justify erasing source evidence or weakening atomic database enforcement.

## Decision

Effective model references govern comparison roles, operation parameter/result correspondence,
relationship endpoints and invariant enforcement/diagnostic bindings. Generate concrete typed
callables, Core selections, materializers and directional Arrow products from those definitions.
Keep specialized algorithms in ordinary trusted implementations. Resources are invocation inputs;
release-owned scientific meaning remains distinct.

Core is the primary relational execution representation. pglast supplies structured PostgreSQL
native declarations and eligible SQL-standard bodies. Extend existing inventory, catalog,
comparison and Alembic frozen operations with explicit versioned profiles before admitting them;
current procedural/AS and SQL-standard body kinds retain their exact semantics; frozen historical migrations remain self-contained. Exact deployment bytes and server-normalized
comparison evidence have different purposes. No raw catalog OID tree is a portable identity.

SQLGlot provides qualified model-bound projection/dependency analysis for actual impact and
validation consumers. It neither authorizes effects nor establishes scientific provenance or
complete procedural equivalence. Native guard timing, owner/ACL/search-path, atomic publication,
transaction and cancellation guarantees remain in force under ADR-0031/0033.

Query execution resolves an admitted producing/installed compatibility binding before importing
an installed plugin. A query name/version or matching data fields cannot substitute for that
binding. New archived products are versioned; unsupported old named routes refuse rather than
execute arbitrary archived code or silently reinterpret their meaning.

The supported executable runtime is composed semantic releases with the current compiler,
boundary and execution profiles. Schema-only preparation has no operational authority. Remove
historical compiler/result reconstruction, semantic-1 execution fallbacks, aggregate PDF bridges,
old rendition/HTML persistence and superseded installed-model executors after migrating current
callers. Current query compatibility across completed runs remains necessary, even when obsolete
formats are refused. Archived source/products for current runs retain immutable identity and
validation; archived Python never executes.

PDF source authority is the record-backed integrated Docling/RapidOCR plus Nemotron triple-pass
model. SourceView/native positions retain evidence and section hierarchy. Retiring old storage
must not remove current sentence, mathematical, extraction or evidence capabilities. Selected
project databases may be discarded; sourcePDFs, models, frozen migrations, plans, evidence,
qualification receipts and shared caches are preserved. Fresh bootstrap uses the existing
creation-token/migration route, not a second reset framework.

## Consequences

Fewer live interpretation paths localize model changes. Current source contracts and generated
bindings must be migrated before native/physical retirement. Proper forward revisions replace
current functions/views before obsolete tables are dropped; frozen83–90 are unchanged. The fresh
PDF run occurs only after structural integration and focused controls, preserving streaming/batch
ownership and independent native enforcement. Full-book recognition and five-section knowledge
qualification remain distinct. No universal interpreter, new alignment lint, second catalog,
mandatory benchmark or extra validation framework follows.

This is an accepted target, not completed implementation. The UM coordinator owns UM-CA01–12
and qualification. UM-CA01/02 transition to authorized retirement rather than claimed historical
repair. The PDF coordinator retains provider/evaluator scope beyond the approved fresh intake.
