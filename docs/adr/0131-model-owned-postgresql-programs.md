## Context

N3 candidate authoring exposed separate sources for column spelling, upload row shape, temporary
checker relations and migration constraint order. The existing LinkML projection and generated
native call surface already carry the shared domain facts. Function bodies and several migration
effects still duplicate them as maintained SQL.

## Options

1. Retain handwritten SQL and expand database checks. PostgreSQL catches more mistakes before
   deployment, but maintainers still need to update parallel declarations.
2. Encode PostgreSQL and PL/pgSQL in LinkML. This makes schema documents the only authoring format,
   at the cost of a procedural language and compiler in the schema layer.
3. Use LinkML for shared domain and physical facts, Core for relational behavior, pglast for
   PostgreSQL syntax, and narrow typed Python programs for native control flow. This keeps domain
   references shared while preserving PostgreSQL's execution, locks and role boundaries.

## Decision

Select option 3. The captured LinkML import closure, induced slots and resolved value-set
populations govern physical types and call correspondence. SQLAlchemy Core and pglast generate
statements from those references. Typed native programs compose only the procedural forms used
by their owners. Runtime and checker scratch structures derive from the same owned definition.
Exact generated bytes and compiler inputs remain in native custody. PostgreSQL binds the catalog,
checks static PL/pgSQL in context, and independently verifies installed ownership and privileges.

Alembic retains exact predecessor, candidate, registration and deployment semantics. The owned
stage moves from N2 through the first model-built N3 successor. Convert remaining maintained
owners forward and remove their superseded SQL sources and fallbacks. Preserve frozen migrations,
independent control SQL and explicitly submitted read-only SQL under their respective contracts.

## Consequences

A model field or type change propagates to its generated SQL and calls, or compilation refuses
at the unresolved declaration. Model generation does not establish semantic equivalence.
Authorization and actual behavior remain independently checked on PostgreSQL. No change to
dependency pins, driver pooling, original assets or historical result semantics follows.
The [DDO PostgreSQL companion](../plans/declared-data-operations/postgresql-realization-and-retirement.md#model-owned-sql-authoring)
owns implementation and qualification. This decision records the target while conversion is open.
