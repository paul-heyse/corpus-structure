## Context

DDO consumer migration must preserve competing source senses, known-version eligibility and
same-span semantic carriers while deleting the mounted run/contribution readers and arbitrary
policy witness input. The old cue check bound an assertion to anchored occurrences; it did not
establish that a machine or provider inferred the asserted relationship. Current query metadata
also lacks the exact semantic carrier, so distinct contributions on one physical span can collapse.
D4 owns producers, D8 owns selected consumers, and the DDO coordinator owns implementation and
qualification. Existing exact CPU correspondence and native source/trust custody remain required.

## Options

1. Accept arbitrary policy witnesses as computed source facts. Rejected: authored assertions
would gain inference standing, and same-span contributions could qualify one another's edges.
2. Retain only no-witness retrieval. This is coherent but drops required competing-sense and
source-supported relationship consumers. Its insufficient-evidence result remains useful.
3. Add producer-derived inference for every cue family. This can support stronger claims, but
requires additional extraction semantics and provider/scientific qualification beyond the old
consumer's actual guarantee. It is not a prerequisite for faithfully migrating that guarantee.
4. Bind explicitly attributed hypotheses to actual current source carriers. Selected. Existing
products, frozen source sets, native receipts and shared relationship selection provide the needed
scope without another scheduler, cache, legacy reader or universal inference service.

## Decision

**Accepted target; implementation and qualification Proposed.** A contextual query retains its
exact input DeclaredContributionRef/carrier identity, authenticated against its original CPU input
basis. Physical occurrence and vector identities retain their numerical meaning; equal vector
values do not erase which semantic contribution a relationship concerns.

An explicit declared witness-binding operation consumes the genuine query, exact inventory,
actual source, explicitly cited cue members and admitted authored hypotheses. Hypotheses retain
attribution, stable identity, target, relation, asserted basis and exact cue references. The query's
own carrier must be among those cues. Native checks authenticate actual source/cue/query producers,
common receipts, anchors, occurrences, inventory targets and input/support populations. An unrelated
same-span carrier cannot qualify an edge. The output states private authored source-binding
hypotheses with unassessed standing; it does not claim provider inference or accepted scientific truth.

An explicit with-witnesses retrieval consumes that binding and the genuine native score product.
Existing shared relationship selection preserves competing alternatives. The ordinary no-witness
route retains insufficient evidence. Remove arbitrary policy.witnesses acceptance as consumers move;
use a distinct nominal witnessed output with its exact witness input visible to applicability and
selected readers. Acquire source/cue references from the selected query cut and freeze their source
sets through existing APIs. No implicit discovery, fabricated task or legacy run alias is introduced.

## Consequences

Carrier fidelity and hypothesis provenance become explicit across producers, native admission,
applicability and selected exports. The bounded binding adds an operation and subtype because it
has a distinct authority contract, while reusing actual scoring and relationship kernels. Numerical
observations and their original producer support remain separate from semantic carrier identity.
Independently inferred cue rules can be added under their own future contract when needed; these
bindings cannot silently acquire that stronger meaning.

The [DDO coordinator](../plans/declared-data-operations_2026-11-12.md) retains native positive,
foreign-carrier/source/refusal, competing-sense, selected-consumer and retirement qualification.
Acceptance alone closes no implementation or scientific-efficacy obligation. No persistent
installation, activation or data conversion is performed by this record.
