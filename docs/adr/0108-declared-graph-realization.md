## Context

NetworkX I01–I07 already select a shared topology basis, but current effective-model v5 archives
only three static interpretations. Runtime lineage, source hierarchy and protected comparison
have actual consumers and require admitted interpretations. Pure graph closure cannot establish
native selection, trust, completeness or prerequisite sufficiency. The operator authorized full
graph consumer integration and bounded prerequisites, leaving wholesale rich-domain migration separate.

## Options

1. Add independent graph adapters beside existing walkers and matchers. This preserves duplicate
algorithms and leaves projections without a governing interpretation.
2. Replace acquisition/admission with an in-memory graph authority. This discards indexed access,
transactional custody and domain sufficiency while adding global materialization.
3. Extend the governing model and integrate a shared native NetworkX topology/comparison basis,
keeping schema extraction and authentic acquisition with their owners. Selected.

## Decision

Effective-model v6 archives compiled static and dynamic projection specifications. Concrete
snapshots supply exact source/model or native cut/trust pins, qualified nodes and occurrence roles,
order/multiplicity, examined coverage and unknowns. v2–v5 readback preserves original bytes and
interpretation, including v5 compact identities; historical data gains no missing specifications
or current execution authority. Diagnostic source-reference occurrences are outside recipe determinants.

One lazy runtime owner controls native NetworkX constructors, algorithms and nested graph-producing
calls, neutralizing ambient priority settings once. This avoids eager package bootstrap and per-request
global configuration changes. Explicit dispatch remains visible at selected calls. Shared multi-source
traversal, SCCs, paths, boundaries and ordering preserve original typed occurrences. Graph payloads
are owned immutable values; structural freeze is insufficient by itself.

One pure rooted attributed matcher provides exact isomorphism and positive non-induced monomorphism.
Every relevant concrete mapping remains available for domain joint-choice/prerequisite checks.
Protected source/reference/prediction selections remain separate. Native relational admission and
selective PostgreSQL/SQLite acquisition retain authority. Output pagination cannot narrow examined
closure silently; incomplete acquisition withholds exact negative/topological claims.

## Consequences

Current consumers migrate together with superseded walkers, duplicate matchers and compatibility
machinery. Bounded shared snapshots avoid reconstructing a different graph per analysis without
adding a durable graph mirror or service. Core native execution is selected; optional analytics,
accelerators, alternate matchers and codecs have no automatic adoption. Existing library versions
remain pinned. Benefits are Proposed qualitatively and unmeasured.

The DDO coordinator owns implementation, exact functional/native/public/export qualification and
remaining retirement. Forward native guard changes use rollback-only authoring and exact checkout
registration; this decision authorizes no persistent deployment, activation or historical conversion.
