## Context

The operator accepted the original DDO RC01–09 and source-qualified Python-introspection RC01–03 on 2026-11-12. External-only declarations duplicate callable facts for intrinsically coupled Python algorithms. Whole-release/runtime identities obscure which definitions affect a result. DDO-00–02 supplies the replacement compiler foundation; production invocation and native adoption follow later packages.

## Options

1. Keep independent declarations, signatures and manual implementation versions. This preserves duplicated authority and permits drift.
2. Make Python the sole authoring source. This misplaces independently defined domain and native protocol meaning.
3. Compile both admitted authoring routes into one effective model. Selected: semantic facts have one appropriate owner and consumers share normalized products.

## Decision

One immutable effective operation/kind/binding model governs the target. Declaration-owned external/model protocols and implementation-owned typed Python definitions are admitted frontends. Python sources are explicitly captured; extraction does not import target code or acquire ambient dependencies. Colocated domain facts supply effects, support, population, outcomes and numerical meaning that signatures cannot establish. Suitable typed Python invocation surfaces are authoritative; generate required native/wire correspondences, not duplicate wrappers.

Versioned rooted kind/definition/recipe/eligibility identities use complete effective semantic records. Supported implementation profiles admit conservative normalized dependency slices as explicit recipe determinants, including complete opaque asset boundaries. Inference success alone never proves exhaustive targets. Unknown required determinants refuse reusable identity. Exact runtime artifact custody and release-bound execution attestation remain separate. No broad runtime digest is a recipe fallback. Equal resulting values/support can stop downstream recomputation.

Prepare effective facts before final release hashes; canonical references encode finite cycles without hash fixed points. Existing nominal IDs, strict ingress and native effects/admission remain required.

## Consequences

This accepts the target, not completed implementation or native adoption. The
[DDO coordinator](../plans/declared-data-operations_2026-11-12.md) owns package readiness and original
finding dispositions. Current selected protocols and archived interpretations keep their existing
ABI/custody guards until the coordinated adoption package replaces their callers. These records
establish the DDO target; full-record retirement of ADR0063/0060/0027/0081/0082/0084/0090/0033/0014/
0085/0091/0050/0064/0067 is not performed while those records still govern live legacy consumers.
DDO-00 records the scoped replacement route; DDO-11 completes reference retirement at cutover.
No data deletion, migration, activation or provider call is authorized by this record alone.
