## Context

ADR-0109 removes historical compatibility as a target constraint. The qualified current target has97
relations and genuine source/native/ACL/default/trigger/TEMP contracts. Private fresh installation and
an exact frozen-state successor have passed bounded native controls. The historical forward chain
still imports old catalogs, physical declarations and authoring branches. Another intermediate
successor would not eliminate those dependencies. The operator authorized complete remaining DDO
execution and target adoption after readiness and recovery; no new approval boundary is introduced.

## Options

1. Continue the historical upgrade chain indefinitely. Rejected: obsolete metadata, owner bindings,
compiler defaults and test mechanisms would remain installation prerequisites.
2. Keep a selectable target flavor beside historical normal defaults. Rejected: every consumer would
retain a second architecture and its lifecycle; a fresh root alone would not complete the pivot.
3. Promote one current physical/native root and exact frozen successors. Selected. Existing Alembic,
PostgreSQL normalization and native custody mechanisms already supply the required guarantees.

## Decision

**Accepted target; normal-route implementation/adoption Proposed.** Promote the current97 relation
physical source and current PDF action inventory to the canonical declarations. Metadata, preparation,
normal native authoring, registration, database initialization and tests consume that one basis.
Remove runtime target filtering, legacy/default flavors and superseded authoring/compiler/read paths.
Keep genuine generic catalog, normalization, comparison, rendering and frozen-state helpers at their
current owner; they must not import historical series machinery.

The current Alembic directory has an immutable root with down_revision=None. A native revision with
no predecessor requests an explicitly empty root, never an unconstrained predecessor or force stamp.
A successor authenticates complete exact registered native state, physical/catalog/ACL premises and
explicit retire/recreate intent. Empty authoring can reach a registered predecessor only through its
verified current linear ancestry. Normal initialization requires a registered current head and never
replays the historical semantic series. Its immutable files remain historical records, recoverable
with their original code in Git; they are not a selectable current installation route.

Native installation can be authored, reviewed, registered and deployed without an application
release. Such a candidate carries no fabricated release, release digests, capsule or admission
claim. Combined native-and-application changes retain exact real release custody and acquire
ordinary purposes only after a fresh root is installed and verified.

Current admission uses the existing checked DDO model/body-schema and native release guard. Remove
independent realization-trigger hashes, selected-fact expectations and old catalog inheritance from
current verification. Preserve required unsupported-semantics refusals and actual schema/native/
privilege/byte custody. Database TEMP restrictions and publisher scratch capability are explicit
current root effects, not inherited historical assumptions.

Persistent adoption remains a separately recorded execution step: verify the actual target and
supported current consumers, fence/drain old writers, retain a usable recovery route and switch the
development target. Old generated bytes may remain inert. Faithful selected imports are useful when
meaning and custody survive; otherwise regenerate or reassess. No historical reader, fake execution
or changed-basis judgment is retained merely to preserve old data. This record performs no database
creation, rename, reset, deployment, activation or conversion.

## Consequences

One normal basis removes obsolete installation coupling and permits complete code retirement.
Existing useful source, scientific and concurrency controls migrate to current consumers; tests of
superseded mechanisms retire. This is a qualitative maintenance benefit, not a measured performance
claim. Current release and native artifacts retain exact original attribution.

The unregistered intermediate v10 preparation is superseded by this clean-root route; its requests,
previews and failed authoring evidence remain unchanged. The
[DDO coordinator](../plans/declared-data-operations_2026-11-12.md) owns normal-route integration,
current fixture baseline, actual consumer/provider qualification, recovery/adoption and DDO-12.
Bounded fresh/successor passes establish their source/context only and do not close those obligations.
