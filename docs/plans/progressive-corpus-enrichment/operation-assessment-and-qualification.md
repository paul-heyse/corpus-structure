## PCE-03: operation protocols, independent judgments and structural changes

### Assessable units and public meaning

Consume the [contribution/operation contracts](contributions-and-semantic-contracts.md).
An operation assessment binds operation/version, domain/guideline/rubric, source population and
input/context policy; its cases name exact source anchors, inspected scope, expected structures
or permissible alternatives, actual contribution identity when one exists, assessor provenance,
judgment, error category and explanation. A missed source occurrence has no fabricated output ID.

Keep execution outcome, source field state, interpretation choice and assessment separate.
Supported/unsupported/ambiguous/unassessed judgments are per facet. Uninspected is not inspected
absence. An unstated unit is not a missing inspection, and an unresolved attachment is not a
negative source claim. Model confidence, candidate-relative marginal, independent judgment and
population estimate are distinct products with different provenance.

| Operation | Independent question and typical error |
|---|---|
| Reconstruction/segmentation | Fidelity, ordering, membership, geometry; lost source region or wrong page map |
| Discovery | Actual occurrence and exact/permissible boundaries; missing, extra or overextended span |
| Type/role | Meaning in context; correct location but wrong sense/role |
| Candidate generation | Eligible target exists, then survives retrieval/budget; inventory absence vs retrieval miss |
| Selection | Correct target/relationship/direction/scope/version; forced choice vs justified ambiguity |
| Attachment | Correct cue and governing target/extent; negation/condition/note overreach |
| Assembly/workflow | Membership/order/branches/prerequisites; valid constituents wrongly combined |
| Consolidation | Equivalence vs distinction; false merge, missed match or version collapse |

The initial development assessment covers retained table/value/header/row/unit/note questions,
located term/role questions and no-output regions; later packages add their own operation rubrics
before fitting or claiming quality. New rubrics may reuse the protocol without a new evaluator
framework. Source anchors and operation outputs, rather than five fixed families, determine grain.

### Both assessment directions

Select source-first cases independently of emitted records: passages, cells/tables, lists and
document pairs with a declared exhaustively inspected region and question. Preserve successful
empty, failed, skipped, limited, unsupported and never-run inputs in the operation inventory.
These cases support omission/capture questions. Output-first cases select from the frozen
contribution population and support spurious, unsupported, duplicate or association-error questions.
Store both frames explicitly; do not pool their denominators or extrapolate a record-selected
subset to all source opportunities. Repeated windows/producer observations of one occurrence
retain separate execution lineage but do not multiply captured knowledge.

Reference authors receive source/context and the rubric without production candidates or scores.
Preserve independent author passes, agreement/adjudication and assessor assistance attribution.

### Scoring, alignment and mathematical tools

Declare exact vs permissible boundary/role/relationship matches in the rubric before scoring.
One source contribution cannot silently satisfy several reference occurrences; duplicate handling
and permissible alternatives must be explicit. Use canonical source identity and released
correspondence first. When alignment truly is one-to-one, SciPy `linear_sum_assignment` can optimize
the declared matching objective with explicit unmatched choices; it cannot establish semantic truth
or a correctness probability. Many-to-many structures require their actual membership rules.

Use Scikit-learn metrics for an independently supplied local label/event, not a generic accuracy
across unlike questions. For fitted joint features, grouped folds (`GroupKFold` or
`StratifiedGroupKFold`) consume scientifically justified origin/document groups; a library splitter
does not choose leakage-safe groups. Source: [Scikit-learn 1.9.1 grouped validation](https://github.com/scikit-learn/scikit-learn/blob/1.9.1/doc/modules/cross_validation.rst). Representation/threshold development, fitting, calibration and
final assessment remain distinct. A deterministic coordinate check need not acquire a fitted model.
Correlated lexical/model/embedding signals need jointly modeled evidence, not summed calibrated
scores or a metadata-only declaration of dependence. Concrete inference/model choices live in
[parsing and mathematics](parsing-and-mathematical-interpretation.md).

Reuse SciPy through the statistics owner for justified estimands and paired procedures. Existing
finite-population hypergeometric inversion can support its frozen accepted-record claim; a new
contribution frame needs a correspondingly declared scope/selection contract and independent
semantic judgments. Preserve undefined denominators and unestablished intervals. Group resampling
must resample actual source groups and recompute ratios; `paired=True` does not infer clustering,
and a degenerate all-correct bootstrap does not establish unseen-origin reliability. Qualitative
case evidence remains useful when an inferential claim is premature.

statsmodels GEE is conditional on a population-averaged error question, credible clusters and
adequate independent groups; mixed effects address a different group-variation question. PPI
requires a defined estimand and valid independent judgment sample. Neither is needed to count
observed misses or qualifies an individual assertion. Activate their bounded investigations only
when the question/data exists, resolving exact versions and assumptions before use. Sources and
API-level realization are retained in the mathematical companion and the review's O03 references.

## PCE-11: assembled qualification and deliberate adoption

PCE-11 starts after all required selected functional behavior and references are integrated.
Earlier packages use relevant targeted checks; they do not launch whole-system qualification.
Freeze source/runtime/model/profile/operation/rubric/context/inventory identities and selected

### Capability manifests and release standing

Each delivered capability names operation/version, domain distinctions, source population,
input policy, rubric/frame, evidence, actual findings and unresolved limits. Its manifest separates:

1. Implemented behavior and actual functional/native/provider checks.
2. Independently assessed semantic distinctions, errors and omissions on declared cases.
3. Population estimates only where sampling and assumptions support them.
4. Public eligibility under operation-specific witnesses/policy, distinct from retention.

Source custody, truthful outcome reporting and protected publication are functional requirements.
Every selected input has a disposition; unprocessed or unavailable regions remain visible.
An assessed term boundary does not certify alias identity. Candidate-relative probabilities are
not calibrated correctness. The release can expose attributable proposals with their actual
standing while independently qualified local assertions use common admission. Complete-record
claims keep the old stronger path and historical numerical targets at their original grain.

There is no universal 0.99 cutoff, mandatory logistic fit, mandatory five-family acceptance or
single completeness percentage. Initial public local policies may be conservative deterministic
or explicitly reviewed rules appropriate to the operation, with their evidence attached. Any
numerical performance promise must be predeclared for its exact event/population and supported
by suitable evidence; absence of such evidence restricts the claim rather than manufacturing a
passing percentage. Failed quality claims remain failed; exposing useful proposals does not
make them correct. A required capability lacking references/actual execution remains open.

| Lifecycle | Actual CPU model lifetime, repeated calls, replay/reuse/invalidation, interrupted work and fenced atomic visibility; no DB transaction held during unrelated model computation |

Keep provider tests actual: a mock cannot qualify GLiNER, encoding, protected publication or a
managed runtime. Reuse valid predecessor source/intake receipts where premises match; rerun
PDF/OCR/recognition only for a specifically missing/changed consumed prerequisite. Exact embedding
neighbor agreement is separate from correct semantic target recall; ANN, reduced precision,
rerankers or native inference replacements add only their affected obligations when selected.

Run `just test-all` and applicable `just hygiene` for the final required scope, retaining classified
native/provider/nonfunctional receipts and accounting for their union and final-source applicability.
Root maintenance `just turn-end` precedes final qualification. Record rustc version with Rust
results; Python commands use `uv run`. Required unavailable providers are blocked with the missing
prerequisite, never passed by static inspection. Preserve every failed/interrupted receipt. Broad
recipe success alone does not establish independent semantic quality or an operating envelope.

Operational measurements cover the actual selected host/profile: CPU/wall time, peak memory,
latency where relevant, bounded model residency, export size/working set and reuse/recovery.
Do not impose an invented cost model or count records per resource as the sole useful output.
Compare performance only at equal semantic/support scope; report useful structural contributions
and assessed gaps alongside resources. A restricted measured capability does not establish
whole-book, new-domain or unseen-origin quality.
