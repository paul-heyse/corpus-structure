## CLD-05 interfaces and selection

Extend `ci schema diagnostic RESULT` with `--view summary|correction|document`. Without an explicit
view, human output selects correction and `--json` preserves the existing document payload.
Explicit views produce the same owned selection in human/JSON form. Document remains the full
existing envelope, subject to its byte/raw gates. Existing JSON consumers/tests remain meaningful;
migrate callers that intentionally select a projection rather than silently changing their data.

Summary contains outcome, release/product/operation binding, counts/availability and next reads.
Correction adds selected observations: category/severity, violated constraint, typed instance and
declaration addresses, known source/contributors, original-engine reference, omitted-detail status
and owner-backed next inspection. Preserve same-path multiplicity and nested alternative branches.
Selection does not turn a bounded examination into a complete inventory. Reuse existing error/depth/
byte bounds; an oversized item gets an explicit located omission, never a shortened identity.

Immediate correction-detail requests use the same presenter before the original expected failure
is translated to process exit. Retained retrieval leases and authenticates the original artifact
and its digest. Direct requests must not acquire a result store merely to render. The default
compact refusal remains available; detailed output is requested rather than forced on every error.

Render with Rich Group, literal Text, Table.grid and selected Tree branches. A semantic Theme can
share actual status vocabulary; colors never carry unique meaning. Syntax receives an already
selected source/diff excerpt and its true starting line. Read retained authenticated source where
available; a checkout source must match the report's digest before it is identified as the diagnosed
input. Changed/unavailable source is reported as such. Logical declaration path is useful without
physical lines; multiple contributors do not imply a unique winner. Excerpt reads obey their own
byte/line limit and raw-disclosure rules. Never use formatting/ANSI decoding as sanitization.
[Rich Text15](https://github.com/Textualize/rich/blob/v15.0.0/rich/text.py),
[Syntax15](https://github.com/Textualize/rich/blob/v15.0.0/rich/syntax.py),
[structured rendering overview](../../libraries/python_introspection/rich.md#4-structured-renderables-and-responsive-terminal-layout).

## Unexpected defects and destination ownership

CLD-06 owns safe structured unexpected-exception capture. This presenter consumes its distinct
typed selection: exception type, cause/context, notes, grouped children, bounded frames and actual
invocation/stage. It never labels that product original-engine validation evidence. Locals are off;
messages/source/notes still require normalization. Preserve original exception/cancellation identity,
exit outcome and native settlement even when diagnostic publication fails. Do not turn a caught
programming defect into success because its diagnostic document was written.

Typed expected refusals continue through existing report owners. Cancellation is interruption,
not another validation category. The safe exception product is useful even without retained raw
traceback objects; do not pickle exceptions or reconstruct them by rerunning the producer.

The completion audit identifies two remaining actual schema boundaries. CLD-CA01 requires optional
diagnostic publication failure after successful pack compile/check or released check to preserve
the successful report, requested output and outcome while disclosing unavailable custody.
CLD-CA02 requires unexpected retained schema defects to reach the distinct typed exception
product rather than the generic validation-report fallback. Existing original-refusal isolation
and standalone exception-renderer controls do not exercise those producer boundaries.
[Exception transformer26.1](https://www.structlog.org/en/26.1.0/api.html#structlog.tracebacks.ExceptionDictTransformer).

Final machine results remain on stdout, diagnostics on stderr, MCP stdout protocol-only. Reuse
existing delivery hooks, including exit74 for otherwise successful incomplete delivery and original
status for known failures. An explicitly scoped presenter is permitted where several components
share lifetime; no process-global Console or generic render registry is selected.

## Replay and conditional export

Pure presenters accept decoded retained typed selections. Reopening old data uses its declared
supported decoder; incompatible/corrupt/expired evidence becomes unavailable without recompilation,
validation or provider execution. Elapsed managed expiry blocks new dependency acquisition and
makes unheld data eligible for collection; existing retained reads remain available until the owner
actually retires that custody. Test unavailable expired data after authorized collection rather
than introducing immediate read revocation. Filters/views cannot recover observations omitted at collection.
Pin binding/outcome/coverage once and carry them into every representation. Use the same selection
for immediate/retained text/JSON; do not rerun per-field validation to enrich display.

Text/JSON replay is selected delivery. CLD-I04/09 considers HTML/SVG only for a named sharing/review
consumer. Its decision must name format, controlled width, byte bounds, custody/dependency and
sensitivity. If selected, create a derived presentation under a new managed invocation linked to
the original; do not mutate a settled original. Existing holds/delivery protect required inputs.
Rich Console capture/record and export may supply mechanics; recording retains segments and export
defaults may clear them. Do not persist every format at producer execution time. A saved rendering
declares omitted scope and is never promoted to original evidence.
[Console15](https://github.com/Textualize/rich/blob/v15.0.0/rich/console.py),
[export controls](../../libraries/python_introspection/rich.md#102-additional-html-and-svg-export-controls).

Custom rendering protocols are conditional on repeated layout that built-ins cannot express.
Global hooks, custom Markdown elements, interactive Text metadata, pager/alternate-screen/notebook
interfaces remain retained with the coordinator's concrete alternative-consumer trigger.
