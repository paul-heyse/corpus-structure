## Foundation and target

Baseline `8578710` includes documentation only since product `ad4593f`. Trusted LinkML contracts,
SchemaView normalization, frozen cattrs products, Pydantic adapters, fixed physical MetaData,
SERIALIZABLE COPY, native fences and exact archives are reusable. The completion audit shows
missing behavioral consumption, not a need for a second workflow engine.

Target 100% model governance with zero disconnected behavior: authored meanings govern actual
applicability, input/result dimensions, invariant placement, effects, projection and dependencies.
Ordinary handwritten kernels remain implementations, with model-bound interfaces and enforcing
composition. Resolving a symbol, hashing a body or generating an expected output from that same
body cannot independently establish its meaning. No exception category closes a gap.

A new domain subtype should change definitions and derived products, rather than add literals
in a source adapter, SQL guard and reader. A changed trusted edge should regenerate its finite
projection for a reviewed forward migration. A changed scientific policy has its own explicit
binding and does not mutate existing runs.

## SP-I01 — Effective semantic binding, phases and projection contracts

**Owner:** semantic model/compiler integration with producer, operation and graph owners.
**Inputs:** SP-C01/C02 products and original supported semantics; no new native admission claim
until SP-I02/SP-I03 enforcing boundaries exist. **Supplies:** resolved immutable contract products
and actual current consumer adoption; addresses CA-01/02/04/05/06/11.

Compile effective statement/qualification bindings, typed reference positions, normalized
constraint placement, operation phases/results and graph contracts once from contextual induced
LinkML definitions. Validate explicit binding class/ancestry, required properties, identifier,
kind vocabulary, multiplicity/inlining and range before archive/admission; retain the explicitly
supported older-profile base protocol. Use same-release hierarchy, never an unrestricted
SourceStatement-descendant exception. Source synthesis, proposal models, entity-source and
occurrence guards consume the resolved product.

Separate structural submission checks from selected/accepted-value conditions. One normalized
conditional product supplies local validators, archive fragments and native rows. Public owned
validation purposes must be explicit. Prefer structural and accepted-projection entry points;
Pydantic ValidationInfo.context can be an internal carrier only if omission cannot authorize
publication or incorrectly strengthen submitted-shape validation. Native publication remains
mandatory for all persisted-state/concurrency obligations.

Model readiness, task protocol, hold decision, submission disposition, assessment finding,
selection and transaction results as distinct dimensions. Correct execute_source, hold_submission,
scientific_policy and raw read return/error translations; do not union all observed strings.
Build result adapters from those normalized contracts and invoke them where real results are
constructed. Bind check_submission to the actual session/read/packet/native-attempt composition;
a pure locator is a subordinate check, not its enforcing owner.

Resolve graph ProjectionContract from the bound execution model before construction/validation.
Check actual source universe, kinds, collection semantics, precision, omissions and lifetime.
Retain explicit qualified occurrences, reference closure, ordered/bag positions and missingness;
never infer bare triples. Translate PySHACL reports into located typed diagnostics and distinguish
nonconformance from invalid shape/runtime failure. Focus-node filtering cannot shrink required
closure. Retain RDFLib, inference none, imports disabled and non-mutating validation.

Use existing Diagnostic/preparation/admission error owners for contract ID, authored location,
consumer/enforcer, expected/actual distinction and repair action. Expose check/derive functionality
through existing schema/db CLI owners, with explicit candidate-versus-archived release selection.
A check is read-only; emission writes only an explicitly requested new output, never deployed
history. Final verb/flag spelling is local implementation detail, but these effects and binding
rules are required. Unsupported required behavior refuses its dependent operation/admission.

**Acceptance:** independently specified narrowed/base/unrelated/malformed statement cases through
public preparation, archive and activation rollback; source synthesis narrowed ranges; submitted,
unselected and selected conditional cases; every finite actual result alternative; stale packet/
attempt/read obligations; unknown/wrong-release graph contract and omitted related nodes. A model
edge/role/result change must reach its consumer or produce an actionable refusal. Preserve original
packet/task/cut identities when the existing failed source journey is later continued.

**Profile investigation:** settle CA-11 against actual required workflows. Current native pattern
and occurrence/context grouping refusal is safe, but is not delivery of the initial promise.
Provide faithful lowering for required behavior; retain explicit unsupported diagnostics for
outside-profile syntax. No general OWL/regex/grouping interpreter or silently narrowed obligation.

## SP-I02 — Native authoring, correspondence and forward reconciliation

**Owner:** native/schema integration. **Inputs:** SP-I01 finite products, shared physical model
and current routines. **Supplies:** retained deterministic emitter, new frozen migration products,
model/deployment correspondence and native adoption; addresses CA-01/06/07 and CBO-008/014.

Derive PostgreSQL table/index/constraint DDL through SQLAlchemy CreateTable/AddConstraint/CreateIndex
and dialect quoting. Use Core-derived CreateView at the installed 2.1.5 pin for fixed views where
representable. Extend the existing transport emitter with explicit relation order and disposal
policy; derive finite edge/state projections, descriptor inputs and expected body digests from
reviewed products. Specialized invariant/effect kernels remain owned implementations consuming
the relevant model rows. Preserve attempt/holder, source/proof authority and terminal atomicity.

Emit bytes into a new frozen forward revision; historical migration execution imports no newest
compiler. Preserve committed old revisions. Reconcile earlier same-head CHECK-expression edits
and naming drift through the forward revision, including a database with the older reference-split
CHECK and a fresh current bootstrap. Renaming an equal-name CHECK does not repair its expression.

Use Alembic command.check as a bounded physical comparison. Its name-based CHECK support does
not establish expression equality or cover native function/trigger/grant meaning. Retain explicit
catalog/deployment checks and independent behavioral examples. Narrow comparison of nondeterministic
server defaults; do not disable all default comparisons to hide one expression.

Maintain derivation/correspondence for finite model products. The currently matching 38 ordinary
edge tuples do not discharge this maintained route. Reference lifecycle kernels retain their
separate protected contracts. Delete obsolete deploy_routines only after checking callers and
extracting retained helpers; current absence of a caller is not a new live-writer bypass finding.

**Acceptance:** deliberate model-edge, CHECK expression, fixed-view, relation disposal, function
body and privilege changes are detected at the correct boundary. Actual invalid edges and effects
refuse natively. Upgrade earlier and fresh schemas to equal intended constraints/answers. Generated
parity checks supplement independent expected transitions, values and effects.

## SP-I03 — Immutable meaning, restricted admission and exact native value contracts

**Owner:** protected publication/admission with runtime and codec owners. **Inputs:** SP-I01/02
products and accepted principal decision; decision/ADR work precedes changed authority.
**Supplies:** enforced immutable closure, non-owner admission, purpose-safe runtime and typed
codec contract. Addresses CA-06/08 and supports SP-I04/I05/I07.

Enforce immutability over meaning-affecting closure: refuse UPDATE/DELETE/TRUNCATE of finalized
release/admitted content and prevent meaning-changing INSERT extensions to finalized releases
or children of existing admitted values. Preserve existing parent-value child-insertion refusal.
Keep project/realization/selection and legitimate operational/reference transitions explicit.
Attest guards and narrow grants; PostgreSQL owner/superuser maintenance remains administration,
not an application exception.

Introduce a restricted admission login with no schema ownership/superuser/migration authority.
Archive publication/finalization is atomic and replay-safe through controlled protected operations;
the login cannot append arbitrary sem rows or become publisher. The trusted compiler/verify contract still establishes source-to-product derivation; a protected
routine does not prove the semantics of arbitrary supplied compiler products. Close intrinsic
inputs/artifacts/definitions atomically. Model deployment-specific SQL/native admission separately:
it legitimately occurs after archive publication, is immutable/replay-checked for the exact release
and physical/deployment contract, and must be revalidated against live posture during activation.
Do not freeze those legitimate admission inserts by treating every sem child as intrinsic meaning.
Native admission compares exact candidate products/constraints and finalized release identity. Activation uses the existing
parent/generation CAS. Keep operator-only migration/provisioning separate from normal regenerate.
Do not grant broad sem INSERT merely to make the existing Python persister work.

Make runtime purpose explicit, derive restricted read credentials even when the base URL is an
owner, and check effective role capability/non-owner posture after pool readiness. Permit alternate
login names with the required role. Keep one psycopg pool per sequential authenticated phase lent
to SQLAlchemy NullPool; share target/purpose resolution with ADBC. Retain one root Settings and
constructor/environment/default precedence. Validate contradictory endpoint declarations rather
than redirecting a bound operation; secret masking remains mandatory.

Preserve the accepted no-generic-writer-TEMP boundary. Provide a publisher-owned fixed inference
workspace with protected creation/disposal and only required payload access, reusing staging
ownership principles. Use protected begin/end routines, reject preexisting names, verify ownership/shape and use
ON COMMIT DROP. Grant only SELECT/INSERT and qualification UPDATE needed by the existing algorithm;
revoke writer TEMP in the same forward revision that supplies the replacement. Its authorization
must bind operation/run/snapshot and close with its owner.
No new general temporary-table service. If actual inference needs broader authority, obtain an
explicit owner decision before depending on it; do not silently retain the contradictory grant.

Own one exact Python qualified-meaning/value-codec specification with the necessary native mirror.
Preserve current lossless numeric representation/identity while specifying observational lexical
versus canonical meaning explicitly; do not claim recovery of authored text from Decimal alone.
Any intentional format/identity change requires an explicit transition decision. Retain lexical
fallback, float signed zero and PostgreSQL NUMERIC opaque metadata; no silent bounded-decimal/float
cast. Use shared Python meaning in identity/evaluation, with independent expected fixtures.

Only after closure-level immutability is enforced may redundant checks of unchanged admitted
meaning be removed. Keep cumulative membership/applicability/cardinality/selection/proof checks.
Affected-subject optimization requires a demonstrated dependency closure, not merely staged rows.
Persisted qualification keys remain conditional on an actual consumer; generated columns cannot
substitute for a value whose meaning reads other rows/release definitions.

**Acceptance:** real restricted principal denial including truncate and append-after-finalization;
first-time/replayed/conflicting archive publication and CAS; owner URL cannot silently read as owner;
alternate valid login succeeds; private workspace cannot substitute for protected staging; later
membership/selection still revalidates affected state. Hypothesis/native differential cases plus
independent pinned decimal/exponent/zero/Unicode/nested-role vectors challenge the codec. One bulk
case set is preferable to a database per scalar.

## Mechanisms, fit and integration

Selected mechanisms and exact-pin limits are retained in improvement review I01–I03/I07/I09 and
its primary sources: LinkML 1.12.1 induced_slot/class_induced_slots/class_ancestors; Pydantic 2.14.1
create_model/TypeAdapter/ValidationInfo and finite-float fields; jsonschema 4.26.0 located errors;
cattrs 26.2.1 strict frozen-product conversion; SQLAlchemy 2.1.5 Core/DDL; Alembic 1.20.0 explicit
shared-connection deployment; psycopg 3.3.6 typed COPY on that connection. Reuse the review's
Context7/installed-source results; refresh consequential API details when premises change.

Compile stable products once, cross boundaries in typed batches and keep relational predicates
optimizer-visible. The work adds compiler/native integration and forward migration burden in
exchange for one semantic decision owner and less repeated validation. No measured speedup,
new workflow interpreter, proof service, graph authority or benchmark obligation is claimed.
Required native admission closes only when its enforcing implementations work; preparing contracts
and generating SQL are earlier usable milestones, not permission to admit an unenforced release.
