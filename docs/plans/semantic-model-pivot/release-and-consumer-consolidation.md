## SP-I04 — Acquisition, composition, runtime opening and verification

**Owner:** compiler/archive and release runtime integration. **Inputs:** SP-I01 effective products;
SP-I03 finalized meaning protection before removing projection coherence checks. **Outputs:**
complete archive-backed boundary recipe, one builder/index, pure composition and deliberate
compatibility transition. Sources: I04; CBO-002/003/009/013/021.

Acquire named immutable PackInputs with explicit origins/core/rules/source profiles. Compose one
root from those bytes, refusing collisions/reserved names; do not fully prepare each pack merely
to harvest its inputs. Caller pack order is already normalized; preserve that property. Finish
SchemaView induction before products are shared and isolate generator input mutation. Minimal
compiler tests can still author minimal inputs.

Factor one boundary builder used by preparation and open_release. Archive all required effective
native primitives, aliases, scope, conditional fragments/options, reference positions, operation
bindings and projection/arithmetic policy. Build an immutable non-identity ReleaseIndex for
lookups/adapters; do not serialize caches into semantic identity. Reuse adapters on actual demand
rather than eagerly create an unused class/property universe.

open_release verifies archive identity, supported product/boundary ABI and relevant snapshot
coherence, then opens from products. verify_release performs full exact-source/product re-derivation
at persistence/replay, activation, run start and explicit verification. A cached open cannot turn
failed verification into admission. Runtime validator compatibility is explicit: identical JSON
Schema does not establish unchanged Pydantic/conditional acceptance.

Memoize pure products by database identity, release/content digest observed in the current snapshot,
compiler/product ABI and validation runtime context. Never cache mutable pointers, live privileges,
native deployment or facts. Use one determinant owner distinguishing byte-producing libraries,
acceptance behavior, runtime semantics and deployment identity; retain provenance and add SymPy to
math operation dependencies. Exact-pin dependency changes remain narrow, reviewed lock moves.

**Transition investigation and exit:** first establish access to required compiler-10 answers via
a supported product reader or the preserved compatible loader environment. Preservation includes exact native read functions,
required database snapshot/data and dependencies, not Python packages alone. Prefer retaining the
existing verified loader until the new reader is demonstrably sufficient; do not assume old archives
contain missing alias/primitive recipes. Produce a compatibility matrix and corruption/runtime-change
cases before switching dispatch. Unavailable old-reader support blocks dependent cutover, not
permission to reinterpret old products. Coordinate compiler/archive/rule-view changes into one
regeneration boundary; new preparations get deliberate identities and existing rows remain immutable.

**Acceptance:** deterministic composition/cold-warm opening; corrupted inputs/products/registry;
alias/nested type reconstruction; changed validators with equal JSON Schema; wrong database/cache
key; old selected answer during new activation; failed verification leaves selection unchanged.

## SP-I05 — One read boundary, reference traversal and refusal meaning

**Owner:** semantic read primitives and serving/evaluation consumer integration.
**Inputs:** SP-I01 contract/reference products; SP-I04 builder/index can be consumed once ready;
finite-float/object/coverage corrections need not await the entire release transition.
Sources: I05/I07/I09; CBO-001/012/013/016/025; CA-03/04/05.

Expose public scoped selection, hydration, values/entities/context loading and binding lookup
from semantic ownership. Serving retains named parameters, labels/modality, pagination/demand and
query policy. Remove private helper imports and duplicated adapters. Use one SQLAlchemy REPEATABLE
READ/postgresql_readonly opener with realization/completed-result binders, keeping ADBC imported
snapshot ownership explicit. Consolidate continuation deliberately, preserving query/parameter/
release/revision/profile identity and machine-readable stale/wrong-binding distinctions.

Resolve coverage against the required modeled universe: an applicable global witness or every
required member. Complete A with missing B remains unknown. Output filtering/page completion cannot
prove absence. Exact object predicates use native typed fields or a proven exact residual;
unsupported interpretation refuses, rather than substitute one lexical/text column for all values.
Fix the nonexistent typed_value.lexical access without silently changing numeric semantics.

Build one release-derived reference-position classifier and collect/rewrite visitor over validated
models. Plain string lookalikes remain strings; non-Entity class refs, inlined subtypes, keyed
collections and multivalued fact roles remain explicit. Preserve deliberately different collision/
sequence policy with named consumer choices. Protected reference inputs use their own admitted
release, never the current active project interpretation. Repair known-input key-name heuristics.

Use field adapters preserving annotations/metadata and finite-float policy; strict mode alone is
not finite mode. Centralize typed domain refusal/DBAPI transient/fencing/defect mapping at CLI/MCP
adapters; preserve proposal hold/correction accounting and cancellation. Do not call infrastructure
or programming failure a semantic caller refusal. A future MCP read/golden profile is not a hidden
migration requirement; migrate the current implemented routes.

**Acceptance:** complete/missing unit and document members, incompatible witness, empty selection,
exact decimal variants, unsupported predicates, active-pointer/token changes, unresolved endpoints,
nonfinite input, nested/keyed/multivalued references, archived reference releases, real CLI/MCP
error dispatch and bounded explanations. Preserve independent primitive-query expectations.

## SP-I06 — Scientific evidence and semantic rule views

**Owner:** domain/scientific and evaluation policy owners. **Inputs:** SP-I01 actual outcome dimensions
and SP-I03 codec meaning; old dependency retirement waits for working consumers.
Sources: I06/I07; CBO-005/006/015/016; CA-04/07.

counterexample/agreement, exact units/assumptions/macros/bindings/conditions, grammar status and
timeout/unsupported reason. Ordinary SymPy/numerical functions remain owned implementations.

pinned and bounded; result_type does not provide a general public AST visitor.

**Acceptance:** canonical exact values/units, symbolic success, numeric counterexample versus
agreement, no valid points, unsupported restrictions, macro/context change, argument reversal,
timeout and every policy mapping. Independent examples challenge the model and kernel; generated
self-agreement is insufficient. Test rule-visible literal/enum/keyed/nullability behavior and
