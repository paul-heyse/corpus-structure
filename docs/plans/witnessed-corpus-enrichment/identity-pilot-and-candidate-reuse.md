## 1. The selected identity question

Select **controlled-artifact lineage identity within a declared issuer/domain and artifact kind**. Examples are references to a procedure, form or policy whose name/code and revision can vary between documents while referring to the same maintained artifact lineage. This is useful for WCE06's procedure-step → controlled artifact → prerequisite composition. The pilot proposes pairs of source-bound artifact mentions/records for the existing exclusion-aware identity owner; it does not merge entities or publish an identity fact.

Keep three grains separate:

| Grain | Meaning in this pilot |
|---|---|
| Source occurrence | This exact mention or record, its source realization, located evidence and extraction/binding revision. Repeated mentions remain distinct records even when their strings match. |
| Controlled-artifact lineage | The maintained artifact under the declared issuer/domain and artifact kind. Two stated revisions can belong to one lineage when independent source evidence supports that relation. This is the selected pairwise pilot event. |
| Immutable artifact version | An exact declared revision/content identity. Different observed revisions or content are not the same immutable version; unknown revision is not equality. Lineage evidence cannot establish immutable-version identity. |

An exact code under a known issuer/kind may provide a strong lineage key when that code's uniqueness is an explicit declared source contract. It is not globally unique merely because it looks structured. A revision difference is not by itself a lineage cannot-link, and an identical title does not establish either grain. The alternative scoped-parameter pilot is not selected here: parameter identity needs its own binding-site/scope semantics and independently labeled cohort. Its references may later reuse the mechanisms after defining that different event, without reusing artifact probabilities as parameter truth.

Known incompatible issuers/domains or artifact kinds are hard exclusions only when the frozen identity policy declares them incompatible and source evidence authenticates both values. Known distinct immutable input anchors and explicit cannot-links remain protected by the existing resolver. Missing issuer/type cannot be converted into a hard mismatch or guessed from a similar title; keep the pair unresolved or in a separately declared unknown-scope stratum. The initial scored cohort requires enough source-established scope to apply the selected event honestly.

### 3.2 Fields and missingness

Each projected input row has a stable occurrence/record ID, source dataset/realization ID and exact retained evidence references. Keep raw lexemes alongside the normalized comparison representation. Field definitions and transformations are versioned production functions with independent expectations; protected labels never enter normalization or candidate preparation.

| Field | Selected role | Required distinctions |
|---|---|---|
| Issuer/domain and artifact kind | Source-established cohort/eligibility scope and hard exclusion premises where justified. | Known incompatible values, unknown, malformed/unresolved and genuine scope change. Similar names do not establish the same issuer. |
| Controlled code/identifier | Exact-key baseline and a separately retained comparison where its namespace/uniqueness is declared. | Valid exact agreement, observed valid disagreement, absent value and malformed lexeme. No global code equality across scopes. |
| Canonical title/label | Lexical control and substantive title comparison. | Source spelling, declared normalization, truncation and incomplete extraction. Repeated generic titles are hard negatives. |
| Alias array | Multivalued exact candidate generation and `ArrayIntersectAtSizes` comparison. | Source-authenticated aliases, distinct alias occurrences/provenance, empty versus unknown array, common/generic elements and normalization revision. A derived title token must not masquerade as an independent authored alias. |
| Revision/date/content reference | Preserve version evidence and diagnose lineage/version confusion. | Different stated revisions can share lineage; equal unknowns cannot establish a version. An explicit replacement/successor relation may connect different lineages rather than prove identity. |
| Source/procedure context | Bounded qualified context for interpretation and error analysis. | Related document family, local scope and already-known input anchors. Candidate provenance is not identity evidence. |

Use Splink `NullLevel` before ordinary comparison levels; `valid_string_pattern` can route malformed identifiers to unavailable comparison evidence. Keep the owned original state/reason outside that neutral numerical level so malformed and genuinely unstated inputs remain distinguishable. Regex extraction is not a general validator: ensure a substring from a malformed code cannot acquire a valid full-code meaning inadvertently. Valid observed disagreement must reach its mismatch level rather than be converted to null.

Splink's null level contributes neutral evidence and does not estimate m/u for that level. This is an explicit initial missingness assumption, not a discovered property of artifact data. If a source systematically omits codes or invalid extraction is informative, compare a named missingness feature/model only with independent support; avoid counting the same source condition twice. No person-name, postcode or date-of-birth template is selected for artifact semantics.

Mechanism evidence: [addendum §2](../../libraries/scientific_compute/Splink.md#2-missing-value-semantics-invalid-data-and-neutral-evidence), [tagged comparison levels](https://github.com/moj-analytical-services/splink/blob/v5.0.0/splink/internals/comparison_level_library.py), [tagged settings](https://github.com/moj-analytical-services/splink/blob/v5.0.0/splink/internals/settings.py). ## 4. Candidate arms and the common scoring model

### 4.1 Separate candidate discovery from evidence strength

Freeze source-valid hard eligibility before candidate generation and retain all independently labeled eligible pairs for coverage evaluation. Compare these arms on the same cohort and scoped identity question:

1. **Exact keys and lexical control.** Exact scoped code keys where justified, plus the existing normalized-label/lexical candidate route. Record which rule nominates each pair and the lexical-only selection outcome. This is the simple baseline to beat or retain.
2. **External existing candidates.** Materialize actual eligible occurrence pairs nominated by current retrieval/contextual/procedure composition, deduplicate by the exact ordered/canonical pair identity appropriate to `link_type`, and preserve all generating provenance separately. Register the library-format `SplinkDataFrame` via `table_management.register_blocked_pairs_for_predict`, then `inference.predict` to score that fixed universe. The projection must satisfy the tagged blocked-pair input schema, including source IDs for multi-dataset linkage; validate it before using the registered relation.
3. **Native alias-array blocking.** Use `block_on("issuer_scope", "artifact_kind", "aliases", arrays_to_explode=["aliases"])` for the known-scope cohort, with additional justified exact-code/title rules separately named. Compare alias overlap using `ArrayIntersectAtSizes("aliases", [2, 1])` where those levels have distinct meaning. Blocking discovers pairs sharing an alias element; intersection comparison only scores already generated pairs. An array score cannot recover a pair that never entered the universe.
4. **Justified candidate union.** Union external and native candidate pairs, retain complete provenance and score each pair once under the same frozen comparison model. Report which valid pairs were uniquely added and which extra false proposals arose. A larger candidate set is not automatically a better interpretation method.

Use one frozen `SettingsCreator` comparison/parameter instance across candidate arms for the primary candidate comparison, so changes in weights cannot masquerade as candidate coverage gains. Separately compare the exact/lexical score baseline and the fixed Splink scoring challenger on common candidate support. Only then combine discovery and scoring into the automatic journey. `match_key` identifies one generating route in deduplicated prediction, not all corroborating rules or an extra likelihood contribution. Keep external provenance as an owned side relation keyed by pair/recipe/revision, not a single overwritten string.

The WCE09 neighborhood contract can supply external candidates when scope, inventory, encoder/metric, source split, self/duplicate rules and query/training mapping exactly match. A reusable CSR graph is heuristic candidate structure; it never supplies artifact identity or a protected truth label. Do not rebuild it inside every linkage consumer, but do not share a transductive all-source graph with a held-out inductive assessment. The [mathematical companion](mathematical-interpretation-and-reliability.md#43-shared-candidate-neighborhoods) owns those common reuse semantics.

### 4.2 Fixed parameters before optional EM

Select a **fixed or partially fixed parameter challenger first**, using explicit m/u probabilities, match prior and comparison levels justified from development evidence or declared assumptions. Freeze values and sensitivity alternatives before final assessment. Use comparison-level `.configure(m_probability=..., u_probability=..., fix_m_probability=True, fix_u_probability=True)` where that level must remain fixed. Merely supplying initial probabilities does not promise they will remain fixed during training. Do not invent calibrated numerical values while the cohort is unavailable.

Prefer a small interpretable model over multiplying correlated title, normalized-title, alias and embedding votes. If alias strings are mechanically derived from the title, either use one of those evidence contributions or specify a compound comparison that models the shared basis. Common aliases need explicit nonmatch-frequency scrutiny. Retain model assumptions, `gamma_*` comparison levels, individual `mw_*` contributions and available `tf_*` values; these are model evidence, not independently corroborating source facts.

EM is conditional within the pilot, after enough representative cohort information exists to identify a useful question. If selected, use existing training estimators (`estimate_u_using_random_sampling`, justified `estimate_m_from_pairwise_labels`, `estimate_parameters_using_expectation_maximisation`) with recorded candidate/training populations, seeds where supported, prior treatment, fixed-parameter masks, `max_pairs`, `max_iterations`, `em_convergence` and term-frequency settings. Random pairs are not certainly nonmatches in a high-duplication packet. Blocking-conditioned training changes which comparisons are estimable. `estimate_m_from_pairwise_labels` treats supplied pairs as positive matches; uncertain clerical scores cannot be reused as fractional positive labels without a separate justified transformation.

Convergence means the configured numerical stopping rule was met; an iteration limit and unconverged fit remain explicit. Session-wide `fix_m_probabilities`/`fix_u_probabilities` and per-level fixed flags have distinct scope. Record the actual final prediction model, including whether session-estimated priors were propagated. A training shortcut `estimate_without_term_frequencies=True` changes the training calculation and is not a claim of numerical equivalence. Compare any trained challenger against the frozen fixed model on untouched groups; retain the fixed model or the simple lexical route if added machinery does not support a useful improvement.

## 6. Independent evaluation and revealing cases

Evaluate candidate coverage before score discrimination. For independently labeled eligible positive pairs, report which generator found them and which missed them; keep unresolved labels and field/capture failures separate. For scored eligible pairs, report supported positives preserved, incorrect positives corrected, newly lost positives, new spurious pairs and unresolved cases. Compare arms at a common model and at explicit output/review budgets when relevant. A larger score or denser graph is not identity benefit. Independent pair truth must not be derived by applying the exact same keys, blocking or normalization whose correctness is in question.

Use `evaluation.accuracy_analysis_from_labels_table(..., output_type="table")` and `prediction_errors_from_labels_table` to retain relational threshold/error results. A `clerical_match_score` cutoff defines binary truth inside the accuracy API; it is distinct from a prediction threshold. In the error API the similarly named prediction threshold controls predicted positive/negative decisions. Store both meanings explicitly and keep unresolved clerical cases out of invented binary truth. Threshold rounding such as `match_weight_round_to_nearest` changes evaluation resolution, not the scoring function; record it. Optional charts cannot replace the tables and source-level error ledger.

The label table can expose missed candidates only if its membership and assessment scope actually include them. Independently reconcile eligible labeled pairs against all generated/scored arms; do not infer blocking recall solely from the output of a high-score prediction table or from a library chart. Label sampling, selection and group limitations travel with every aggregate. No population/generalization claim follows from the bounded packet unless its design supports it.

Required countercases include:

| Case | Independent expected distinction |
|---|---|
| Same controlled code under different known issuers/domains | Exclusion or separate scoped entities under the declared policy; no global equality. |
| Same lineage, two stated revisions | May support lineage identity while refusing immutable-version equality. |
| Similar titles/codes, explicitly distinct artifacts | Retain nonmatch despite lexical/alias similarity. |
| Shared generic alias and duplicate aliases within one array | Common evidence cannot manufacture strong corroboration or duplicate pair/likelihood votes. |
| Unknown code, malformed code, valid observed disagreement | Original state/reason stays distinct even where null numerical evidence is neutral. Two identical malformed values must not become exact valid agreement. |
| A valid pair found only by an external generator; another found only by alias blocking | Separate coverage gains; alias intersection alone cannot recover an absent candidate. |
| One pair found by several generators | One scored pair with complete external provenance; `match_key` is not exhaustive evidence attribution. |
| A–B/B–C scores with an A–C exclusion or distinct known anchors | Existing resolver refuses the forbidden bridge under every input ordering. |
| Missing source scope or unknown revision | Unresolved applicable identity grain, not a silently asserted match/mismatch. |
| Related revisions/duplicate source material crossing a proposed split | Group assignment catches the shared evidence; final held-out claims refuse the leaking partition. |

These expectations come from independently authored source contracts/literals, not from Splink's own cluster output or the production canonicalization under test. Small constructed inputs can verify interfaces and exclusions; authentic independent held-out source groups are required for efficacy.
