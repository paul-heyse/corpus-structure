## Source and release adoption

Use a fresh explicitly selected realization where new contracts or segmentation require it.
Archive source/profile/grammar/library/implementation bindings through the existing release
route. Deploy only forward native revisions; do not edit frozen migrations, mutate completed
runs, overwrite old anchors or delete old databases/results. Preserve the full rendition content
digest: text, complete segments/sentences, attributes/states and macros, not text alone.

Same content may share rendition identity while builds retain distinct decomposition/provenance.
Select the producing run/task/build through PP-09; never read current defaults into historical
answers. Required native support must exist before activation. A failed acquisition, attempt,
publication or interrupted qualification remains recorded with its actual outcome.

At cutover, verify actual CLI/MCP defaults and requested source queries select the intended
realization. Frozen historical reads must still describe their original support and coverage.
Do not impose new fidelity/grading targets merely to make the changed implementation pass.

## Independent acceptance scenarios

Use small independently specified source examples for meaning, then representative actual-source
journeys. Calling the production validator for both actual and expected is not an independent
semantic check. Reuse production enforcement when testing its consumers without duplicating it.

| Case | Required distinction |
|---|---|
| Omitted tags, implied tbody and malformed nesting | Original spelling versus HTML5-generated/reordered structure; original file remains intact. |
| Duplicate attributes, comments, script/style and excluded navigation | Every original piece categorized even where structural/canonical projection omits it. |
| Entities, CRLF, invalid bytes and combining Unicode | Byte/decoded/canonical spaces and mapping coverage explicit; no guessed exact offsets. |
| Tables/lists, references and inserted separators/quotes | Ordered edges and synthetic origins, full canonical partition including whitespace. |
| Nested scripts, text arguments and macro defaults/fallback | Lexical/composite occurrences plus definition/invocation origins remain connected. |
| `x+x`, `f(x)` and conflicting/absent declarations | Two occurrences survive value sharing; distinct authorized contexts cannot collide. |
| Bound/free variables, unevaluated integral and unknown assumptions | Binder identity and mathematical question govern native operations; unknown is not false. |
| Decomposition-only then stronger request | No hidden earlier symbolic work; compatible preparation reused, new conditions invalidate the affected result. |
| Isolates, parallel relations and cyclic references | No edge collapse, fabricated reading order or global acyclicity requirement. |
| Cancelled worker/timeout then replay | Attempt-dependent failure and bounded resource cleanup; no partial product published as complete. |
| Content-identical builds and historical release reads | Correct build-specific provenance, immutable anchors and archived meaning. |
| Independent reference journey | Extraction cannot consume references; numeric agreement is not promoted to symbolic proof. |

Exact HTML mapping is a mandatory target obligation. If PP-02 has not qualified a route,
that scope remains open. Publishing explicit partial coverage can be useful, but cannot close
the complete target. Conditional library candidates instead have a recorded select/defer/reject
decision and trigger; a rejected optional mechanism is not a missing required capability.

## Verification and completion claims

During implementation run targeted compile/type diagnostics and functional/native checks at
coherent capability boundaries. Do not run integrated qualification after each package. After
all selected functional scope is implemented and final source is prepared, root runs the required
`just test-all` functional union and applicable `just hygiene` checks, repairing failed scoped
checks without rerunning unrelated work. `just turn-end` is the final maintenance step of changed
turns. Lint-only maintenance does not erase applicable earlier test/type results.

Qualification covers pure adapters, actual restricted native publication and source/CLI/MCP
consumer journeys where those are required. Preserve failed/interrupted receipts, missing
prerequisites and exact final-source applicability. Report passed/failed/blocked/not_run; no
mocked provider or documentation check supplies product qualification.

Assess execution fit qualitatively for large sources, heavily ambiguous math, many occurrence
edges, repeated reads and concurrent cancellation. Any throughput/latency/memory improvement
claim needs a representative measured comparison with a decision purpose. Existing recognition
measurements are historical bounded evidence, not savings promised by this series. No permanent
benchmark campaign, cost model or new alignment gate is required.

Completion updates the same coordinator's packages, O01–O07 dispositions and remaining
obligations. Carry enduring accepted meaning into its architectural owners, with required ADR
routes; retain plan/evidence documents. Do not change another plan's completion status or claim
full-domain completeness beyond the implemented and qualified parsing boundary.
