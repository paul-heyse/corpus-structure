# Semantic evidence and references

**Status:** Proposed; [coordinator](../test-architecture-and-evidence_2026-11-02.md) owns TA-07–09 and scheduled DTA state.

## Target and useful foundations

Strengthen particular assurance claims, not all assertion syntax. Retain hand-authored value/PDF
identity vectors, independently specified native tuples, exact graph closure/scientific definedness,
current CLI/export journeys, deliberately invalid inputs and frozen source provenance. Production
validators enforce valid downstream setup; expectations assessing their meaning are independently
stated. Missing literal hashes, truthy assertions or copied constants are leads, not standalone
proof of a defect. Resolve each example against its supported obligation before changing it.

## TA-07 — Discriminating guard, diagnostic, set and work assertions

Start with the audited publication/Arrow/PDF binding refusals, contract catalog mutations, composed
explanation/serving checks, statistics filtered-all and hydration spy. Follow their current consumers
rather than bulk-rewriting every raises()/assert expression. For a selected refusal, first establish
an independently valid accepted baseline, then vary only the intended invalid relationship/value.
Verify the expected boundary was reached, the native cause and absence of partial effects. An
unrelated admission/privilege/FK failure must not satisfy the named test.

Use existing invariant/report identities where available. Psycopg3.3.6 provides `Error.sqlstate`,
`Error.diag.message_primary` and `constraint_name`; SQLAlchemy's DBAPIError exposes the driver
exception as orig. Prefer these to regex over SQL/parameter/context-rendered prose. SQLSTATE23514
alone does not distinguish many protected guards, and constraint_name may be unavailable for RAISE.
An exact bound invariant diagnostic or primary message can discriminate there. If the production
contract lacks a promised stable mapping, extend its existing model/enforcer/report correspondence;
do not create a second test-only error taxonomy or compute expected reports with the report producer.

Address catalog definitions by stable id, not position. Each parameterized mutation states its
independently expected diagnostic at the grain promised by the consumer: relevant code/location/
outcome/contract_id/consumer/expected/actual/remedy, without brittle unrelated full-output equality.
Reordering valid declarations must not retarget cases or make a different generic error acceptable.

For preservation claims, independently specify expected fact/occurrence/support/evidence/source
identities, multiplicity and qualification through query/explain. Add a revealing wrong/extra/missing
member control where needed; keep existence checks where existence is the full contract. Use
pgTAP results_eq/set_eq/bag_eq only if TA-01 selects it and their order/multiplicity meanings match.

Materialize a filtered property subset and assert its intended members before universal comparison.
Observe required eligible IDs positively before a no-noise hydration claim. The generated math
property only promises equivalence for values the grammar reads: no minimum acceptance percentage
or arbitrary case floor follows. Decide whether its current restricted claim already has sufficient
fixed controls. If a distinct admitted-input coverage requirement exists, use Hypothesis constructive
strategies/composite/examples for that separate purpose and preserve arbitrary-string robustness.
No blanket health-check policy or mutation-testing campaign is introduced.

Acceptance is a discriminating success/refusal pair for each changed claim, stable mutation identity
under reorder, and a positive observation when observing work is the claim. Native test tools,
structured diagnostics and independent expectations must agree through actual maintained consumers.

## TA-08 — Current semantic keys and composed aliases

Pin complete `semantic.identity.fact_key` and `occurrence_key` preimages/outputs. Use hand-authored
bytes and literal full fact:/occ: expected digests, with transparent stdlib hashlib/json derivation
independent of production canonical_bytes/value_meaning. Cover release/realization scope,
subject/predicate, exact numeric/negative-zero behavior, qualification meaning and source/item
occurrence distinctions. Evidence/confidence must not become semantic qualification. Carry representative
vectors through assemble, native publication and ReadSession, preserving existing independent PDF
scalar/record/fold vectors. A producer/native agreement alone is insufficient.

For aliases, use at least one actual statistics prepare_pack(s)→consolidation→query example with
independent head-word/rewrite expectations. Resolve authored local class keys through the existing
compiled namespace/name authority once into immutable released alias policy. Do not add a second
fallback interpretation to normalize_label. Preserve articles, rewrite order, case, nonempty result,
archive custody and exact identity semantics. Test multi-pack namespace ambiguity/collision, not only
one prefixed spelling. Existing synthetic core tests remain useful isolation.

Phase0 X2-01 owns the broader authored→prefixed finding; reconcile its exact current scope in TA-00.
This package supplies the bounded correction/evidence and links to that owner. If correcting current
alias meaning changes a release-affecting artifact, use existing version/derivation and forward
native admission where required; never mutate an admitted release or frozen migration. Actual alias
policy corruption is not repaired by changing the expected test spelling. Coordinate model/generator/
consumer ownership and qualification with UM rather than opening another operational migration route.

## TA-09 — Reference counterparts, authority and deliberate evolution

First settle the obligation-to-current-contract correspondence for each toy/trace reference family.
Classify each outcome as supported and already challenged, supported needing a current counterpart,
or deliberately outside current support with its reason/owner. The input is fixtures/toy README,
trace positive/negative patterns/questions and their existing schema/scorer consumers. Evidence is
not an instruction to restore historical writers or blindly transplant the old nine/seven counts.
For example Alpha/Beta attribution identity must be settled under the current domain model before
choosing its expected fact grouping. Unresolved semantics constrain only their dependent tests.

Implement selected small source-authored counterpart journeys through current production pack
composition, proposals/assembly/publication and served queries/explanations. A locator/type check
alone cannot establish negative outcomes. Preserve independently authored source quotes, target
mapping, selected must_not patterns and questions. Use the current released source-view route;
no historical HTML writer/result reconstruction or provider campaign is needed merely to transfer
semantic assurance. Keep coverage scopes explicit where a mechanism test already carries an outcome.

For macro/offset/math/LLM/ingest/archive reference families, declare at the existing reference owner
whether it is a lasting independent oracle, frozen historical witness or current configuration
consumer. The math helper's frozen macro configuration may intentionally differ from today's pack;
resolve the LLM helper's temporary-copy wording accordingly. Share mechanics if useful but do not
replace independent expected values with production outputs.

Document deliberate change beside existing builders/READMEs: source paths/records, meaning and
applicability, independent adjudication authority, proposed difference and affected consumers.
Regenerating current production output is evidence to inspect, not authority to approve a new oracle.
Keep frozen original artifacts/evidence; add a new explicitly selected reference or correction under
existing contracts rather than silently changing their meaning. Use docs/pins.md only for concrete
oracle holds with reasons/revisit conditions; normal exact pins remain ordinary judgment.
Correct tests/fixtures/semantic/README.md to current-only support while retaining its source lineage.

Acceptance includes an independent authored current journey with a revealing negative, explicit
resolution/deferment for each selected reference obligation, a documented hypothetical intentional
reference change, and current archive/refusal controls. No resurrection of DTA-014/020 or deletion
of plans/evidence follows. Report unresolved meaning with a trigger instead of declaring it closed.
