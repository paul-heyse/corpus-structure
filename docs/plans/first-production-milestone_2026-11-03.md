## Qualification and completion

Targeted compile, invariant, numerical and consumer tests run with each coherent implementation
slice. Actual CPU inference qualifies selected operations; mocked children do not establish that
provider result. Once all selected functional scope is implemented, the root runs `just test-all`
and applicable `just hygiene` for the final source/context and required union. Preserve failed and
interrupted receipts. M1-14 owns actual CPU/publication/CLI/MCP/export, resource/recovery and release
assessment beyond the functional union. Follow existing evidence record/finalization conventions.

The proposed family gates retain ≥90% candidate recall, ≥97% full-record precision with a one-sided
95% lower bound ≥95%, and the operator-selected70% accepted full-record recall floor for each family. Zero known
broken required anchors and complete routing/coverage accounting are separate obligations. Freeze
final policy, finite held-out source cut and assessment method before grading. Under ADR-0053,
use census or predeclared SRS without replacement over the complete accepted-record frame with
exact hypergeometric precision bounds. Origin partitions remain isolated and grouped resampling
is descriptive; it does not replace the finite-cut gate or establish unseen-origin performance. A whole-record error includes
wrong unit, role, polarity, condition or evidence. Support-subset restrictions are explicit.

Measure actual CPU/RSS, thread coordination, cold/warm behavior, dense/long contexts, decoding and
persistence. The initial16-thread/32GiB envelope is a proposed pilot control, not measured capacity.
Calibration applies to evaluated final events, not automatically to head scores. Changed schema,
context, ontology, rejected evidence or model profile invalidates affected results and qualification.

Full completion needs all five released subsets, independent reference/metric evidence, actual
consumer use, explicit unsupported/candidate-only boundaries, replay/interruption/atomic-publication
controls and a release manifest naming dependencies, guidelines, policies and resource envelope.
Conditional deferrals can remain deferred without falsely claiming their implementation. An
unavailable required reference or failed gate keeps the corresponding release obligation open.
