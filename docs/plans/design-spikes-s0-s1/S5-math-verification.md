# S5 · Math parsing and verification: plan

**Status: Proposed (2026-10-28).** Part of the [spike plan series](../design-spikes-s0-s1_2026-10-28.md),
which owns shared decisions (§3.5), the execution queue (row 29) and spike-execution findings. The
question is the [S5 brief](../../design_review/evidence/2026-10-28_design-spikes/S5-math-parsing-and-verification.md)'s;
this document says how each brief step now runs after the text-and-math research and the
2026-10-28 design revision, in which order, and which phase 0 package each result feeds.

## 1. What S5 must establish now

The [text-math note](../../design_review/evidence/2026-10-28_library-text-math/README.md)
(2026-10-28) found two defects in the spike grammar and macro reader, and D4 was amended from it
(M01, M09, M11, M13; §3 decision 13 of the [phase 0 series](../phase-0_2026-10-28.md)):

- SymPy's shipped `%ignore` lines for `\left`, `\right` and spacing commands match prefixes, so
  `x \leftarrow y` parsed `ok` as a product of letters. Lark's `edit_terminals` makes every
  control-word literal whole-name; on the spike pages no parsed span changes. The coverage figures
  measured before the fix overstate `ok`.
- The spike's macro reader misses `\renewcommand`, which defines `\P` on 22 pages.
- The token form that keys use (ADR-0012) is built by a TeX-rules `regex` tokenizer in `core`, not
  by the grammar, with one drop list shared with the grammar, no `*` in control words, and
  whitespace inside `\text{}` collapsed.

S5 measures the grammar on the whole first pass with those fixes, extends it where failures
concentrate, and checks the property keys rest on (KEYS-01): wherever the grammar reads a span,
the tree printer agrees with the token form. **S5-A comes first** because the phase 0 ingest-and-math
grammar port and the foundations `core/tex.py` wait on it (single home after a port, §3.5). Then
scoping beyond the core units (OPEN-D4-5, OPEN-D1-2), equivalence tiers for evaluation
(OPEN-D7-2), and, lowest priority, z3 and the verifiers, whose consumers are phases 2 and 4.

**Coverage is a reported figure, not a gate.** The brief's "≥ 90%" reading is how a result is
interpreted; a lower figure changes which spans M11 can type and convert, not whether the grammar
is used, because keys never depend on parse success (D1 §6.2).

## 2. Brief steps as they now run

| Step | Now |
|---|---|
| 1 Macro tables | With a macro reader on the shared TeX tokenizer that covers `\newcommand`, `\renewcommand`, `\providecommand` and `\DeclareMathOperator`; report what the spike reader missed, page by page |
| 2 Coverage | Run twice: the spike grammar as it stands, then with `edit_terminals` and `ordered_sets=True`; report both, so the defect's effect on earlier figures is visible. Failure categories from the exception class, the TeX token at the error position and the `allowed` set. Parsers cached per macro classification in each worker process; timer-based timeouts in single-threaded processes. Pages beyond the stored seven are regenerated by `s1_adapter.adapt` under contract R1, with the parser recorded |
| 3 Extensions | An extension is kept when it gains spans and turns no `ok` span `failed` or `ambiguous` over all 28,956; stop when the largest remaining failure construct covers fewer than about 50 spans. `ambiguity="forest"` only if ambiguity blows up |
| 4 ANTLR check | In `build/spike-antlr-venv` (SymPy 1.14 with `antlr4-python3-runtime` 4.11, without linkml), on the spans Lark still fails; report only what decides OPEN-D4-3's revisit trigger |
| 5 Token form | Under I-R2 (row 24): the token form from the regex TeX tokenizer with the shared drop list and the `*` and `\text{}` rules; the property check `tree_canonical == tokens_canonical` over every span the grammar reads, plus generated tests: strings drawn from the grammar itself (Hypothesis `from_lark`, explicit strategies for the macro terminals) and metamorphic rewrites of the token form (sizing commands, spacing, brace-equivalent forms), as D9 §4 states for the product test; the token form wins every disagreement and the tree printer changes (KEYS-01) |
| 6 Sets | As the brief |
| 7 Symbols (M09) | As the brief, with the grammar's `occurrences` |
| 8 Scoping (M13) | As the brief, with two binder variants: the spike patterns, and the refined ones (`Matcher(validate=True)`, `PhraseMatcher(attr="LOWER")` for multi-word phrases, "again" tied to the binder's sentence). The sample of assignments on the twenty math-heavy units is judged by a fresh Sonnet subagent with instructed blindness and transcript audit, not by the root (§3.5) |
| 9 Equivalence | As the brief, with the numeric points drawn from a generator seeded by the two claims' keys (D7 §5.3) and timeouts measured per tier (OPEN-D7-2) |
| 10 z3 | As the brief; untranslatable leaves recorded; unsat cores through `assert_and_track`; a per-check timeout with `unknown` reported as such ([z3 overview](../../libraries/z3-solver.md)) |
| 11 Verifiers | As the brief |
