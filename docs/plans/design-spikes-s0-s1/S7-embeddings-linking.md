# S7 · Embeddings and linking: plan

**Status: Proposed (2026-10-28).** Part of the [spike plan series](../design-spikes-s0-s1_2026-10-28.md),
which owns shared decisions (§3.5), the execution queue (row 32) and spike-execution findings. The
question is the [S7 brief](../../design_review/evidence/2026-10-28_design-spikes/S7-embeddings-and-linking.md)'s;
this document says how each brief step now runs, which variants could change the phase 1 M04 and
M14 configurations, and which phase 1 method, OPEN item or package each result feeds.

## 1. What S7 must establish now

S7 fixes `halfvec(n)` for the phase 1 migration that creates `kb.embedding` (D3 §5, OPEN-D3-2),
the M04 configuration, and which M14 candidate steps earn their place; whether vectors enter
linking in phase 1 or stay in phase 2 is the roadmap's phase 1 question for S7. It settles:

- **Runtime.** `sentence-transformers` in process is primary: the `encoder` worker already holds
  M05–M07 in one process (D6 §3.2), and vLLM's documentation says its pooling runner is a
  convenience with no performance guarantee over SentenceTransformers
  ([vLLM overview](../../libraries/vllm.md) §6.3), while a second vLLM process reserves its own
  `gpu_memory_utilization` share beside the generation server. The pooling runner is variant V2.
- **Dimension.** Candidates are 0.6B at its native 1024 and 8B truncated to 1024 or 2048. The 8B's
  native 4096 is never a candidate (HNSW on `halfvec` indexes up to 4,000 dimensions, D3 §5); its
  untruncated vectors are kept only as the ceiling the truncations are compared with. Each model is
  encoded once per prompt and text form at native dimension, then truncated and L2-normalized in
  numpy: both cached checkpoints end in a `Normalize` module (`modules.json`), so a truncated
  vector is no longer unit length, and one code path serves every configuration (D4 M04's order).
  Similarities are also computed on float16-rounded vectors, what `halfvec` stores, and rank
  changes counted. 0.6B at 1024 is chosen unless an 8B configuration is better on linking (d) or
  retrieval beyond the bootstrap interval of the difference.
- **Prompts.** The checkpoints store a generic web-search `query` prompt and an empty `document`
  prompt (`config_sentence_transformers.json`); the model card asks for a one-sentence task
  instruction, `Instruct: {task}\nQuery:{text}`, on the query side only. S7 writes one for linking
  (a mention to the entity it names) and one for retrieval (a statement to statements of the same
  kind about the same object), passed as `prompt=`; the stored prompt is variant V3.
- **Fuzzy scorer.** `fuzz.token_sort_ratio`, the scorer the instruments accepted as a graded
  similarity, replaces the brief's and D4 M14's `token_set_ratio`, which the instruments rejected
  because it scores a label contained in a longer one as identical ("normal distribution" against
  "standard normal distribution"; [instruments](comparison-instruments.md) §5.1,
  [rapidfuzz overview](../../libraries/rapidfuzz.md) §3.3). The instruments also found that every
  v0 global class's identity can turn on a prefix or one word ("normal" / "lognormal" 92.7), so the
  aligner never accepts a fuzzy-only match (`FUZZY_TYPES` empty in `code/instruments/align.py`). S7 measures whether any cutoff
  separates spelling variants from distinct entities; if none does, fuzzy matches stay candidates.
- **Parameter names (PARAM-01, RG-7).** Cross-unit parameter mentions are linking cases of their
  own, gold under B2 (D2 §10.4). They are judged apart from S2's recall: cases are S2's mentions
  plus the reference's parameter occurrences that S2 did not find (I-R3's occurrences, S2 §1),
  marked by source.
- **No trivial matches.** M14 links against entities proposed elsewhere (D4 M14, reference run), so
  aliases contributed only by a mention's own unit are withheld when that mention is linked.

S7 scores with I-R3 (I-R2 plus the mention alignment) and runs exclusively on the GPU; co-residency
is G1's (§3.5).

## 2. Brief steps as they now run

| Step | Now | Mechanism (owner) |
|---|---|---|
| 0 Segments (new) | The 78 first-pass pages regenerated by `code/s1_adapter.adapt` with the S1 configuration and libxml2, parser recorded, into `results/s7/segments/` (contract R1); the seven stored pages must reproduce their stored segment keys, else S7 stops | §3.5 renditions; §4 |
| 1 Embed | `SentenceTransformer` per checkpoint (bf16, left padding as the model card recommends); `encode` at native dimension, documents without a prompt, queries with the task instruction; then truncation and normalization (§1). Unit and paragraph segments of the 78 pages and every alias of the gold inventory with its class description (document side); the core units again with the retrieval instruction and the linking cases with the linking one (query side) | D4 M04; `SentenceTransformer.encode(prompt=…)` (Context7 `/huggingface/sentence-transformers`); the checkpoints' model card |
| 2 Link gold | The gold inventory merges the v1 reference's global entities across units by their D1 §10.1 entity key (instruments `keys`), with page titles as seed entities and family parameters keyed under B2 to the defining unit's entity; where the v1 reference differs from B2, the rule decides and the difference is a row. Cases inside reference units take their entity from I-R3's occurrence alignment; every other case is labelled by two fresh Sonnet labellers independently, blind to linker outputs, disagreements to a third, with `labeled_by` and agreement recorded | §3.5 labelling independence; D2 §10.4 |
| 3 Cross-unit parameters | As the brief (the normal's across T2, T3, U5, U6; the lognormal's in U9 against T4; the gamma's across U10–U12; others the labellers find), each to the defining unit's `FamilyParameter` (family, canonical name) whatever symbol or role word the mentioning unit uses | RG-7; PARAM-01 |
| 4 Linking | (a) exact after D1 §6.2 normalization; (b) plus the D2 §12.1 alias rules (the aligner's `alias_norm`) and spaCy lemmas; (c) plus `process.cdist(cases, aliases, scorer=fuzz.token_sort_ratio, processor=…)` per class at three cutoffs (`cdist` defaults to `fuzz.ratio`, so the scorer is explicit); (d) plus cosine neighbours per embedding configuration. Candidates ranked in that fixed order (D4 M14 before a fitted model). acc@1, acc@5, new-entity precision and recall at three thresholds, over all cases and the cross-unit parameter cases; distinct labelled entities that a fuzzy cutoff admits listed as hazards | D4 M14; instruments §5.1; rapidfuzz overview §3.3, §6.1 |
| 5 Retrieval | As the brief, by exact cosine on the stored-precision vectors. Neighbours of every configuration are pooled, deduplicated and shuffled, then labelled relevant or not by two fresh Sonnet labellers who do not see which configuration retrieved them; precision@5 per configuration | D4 §4.2; §3.5 |
| 6 Cost | Throughput and peak memory (`torch.cuda.max_memory_allocated`) per model and dimension, exclusive on the card; the co-residency check moves to G1 | §3.5 GPU; D6 §5 |
| 7 Index check (new) | Where a `vector` database exists (S6's, or a `pg_virtualenv` cluster): the chosen configuration's vectors as `halfvec` (`register_vector`, `HalfVector`) with one partial HNSW index per `target_type`; top-k of the linking query (aliases of one class) and the retrieval query (units, own page excluded) with `hnsw.iterative_scan = relaxed_order`, against the exact results | D3 §5; [pgvector overview](../../libraries/pgevector.md) §5.5–§5.6 |

## 3. Variants

| Variant | Alternatives | What it would change |
|---|---|---|
| V1 model and dimension | 0.6B@1024 · 8B@1024 · 8B@2048 (8B@4096 as ceiling only) | OPEN-D3-2: `halfvec(n)`; 8B means exclusive GPU mode for `embed` (D6 §5) |
| V2 runtime | sentence-transformers in process · vLLM pooling (`LLM(runner="pooling")`, `llm.embed`, `PoolingParams(dimensions=…)`) in `build/spike-vllm-venv` where it exists | D4 M04's realization and D6 §5's placement (encoder worker or a second server); only if its vectors match (cosine ≥ 0.999 on a sample) and it lowers memory or the encoder worker cannot hold the model |
| V3 query prompt | task instruction · the stored generic `query` prompt · none | The instruction in M04's configuration |
| V4 case text | mention alone · mention in its sentence | Whether M14's vector step needs context, so what M04 embeds for mentions |
| V5 segment text | raw LaTeX · Unicode-rendered math (S1 variant d) | M04's input form for segments (the embedding counterpart of OPEN-D2-2) |
| V6 parameter candidates | every `FamilyParameter` · only the parameters of the case's family (from the unit's `has_distribution` claims or the page's family) | Whether RG-7 is a linking problem (scoping solves it) or needs the representation (OPEN-D2-18); M15 stays phase 2 conditional |
| V7 fuzzy cutoff | 85 · 90 · 95 | Whether a fuzzy score may decide a link, or fuzzy stays a candidate and near-miss signal as in the aligner |

## 6. Choices left to execution

- The two task instructions and the alias-with-description text, fixed before any scoring.
- How the four candidate steps merge into one ranking before a fitted model exists, as long as
  the order is fixed in advance and recorded.
- The three new-entity thresholds per step, as long as each lies on the step's own score scale.
