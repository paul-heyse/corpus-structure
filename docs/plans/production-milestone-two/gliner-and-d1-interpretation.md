## PM2-07 · Retain grounded extraction and add bounded interpretation

**Tested · 2026-11-09.** `ci run interpret` resolves named question definitions
from the archived release. It accepts exact source selections and retained
contribution or frozen list references. Only the authorized source field can
yield literal evidence. d1 batches compatible requests on the staged CUDA
profile and retains typed answers, scope and coverage under the existing claim
and result owners. Current statistics questions are [release inputs](../../../domains/statistics/interpretation-questions.yaml);
the implementation does not read textbook terms or reference answers.

an independent definition function and a binary relation observation, returned
no match for the fair-coin host, and returned missing candidate on the gambler
referent with a grounded candidate available. Preserve those gaps as development
findings. The [protected paired interpretation](../../design_review/evidence/2026-11-09_pm2-interpretation-pair/README.md)
supports the v2 change to exact source-backed probability normalization of
`1/8` as `0.125` and preserves the definition control. v1 remains the default
for the current private runner. Roulette loss, condition host and local referent stayed
unsupported. The changed-candidate diagnostic kept the attachment misses separate
from candidate availability. A like-for-like GLiNER/spaCy comparison, a real
d1 run from a qualified frozen retrieval list, and the successful composed
attachment and selected-family consumer journeys remain open.

task parameters under the release's governed authority with the resolved operation
version, source scope and roles, ordered question definitions, stable option identities and
criteria, allowed evidence fields, renderer, native answer kind and interpretation policy.
Use the existing contribution and candidate ownership. An invocation has an exact source
scope and named coverage, even when there are no candidates or the provider could not
complete the request. An option that was never offered cannot be treated as rejected.
Support a change in domain vocabulary, labels, or comparator definitions through release
data and the same adapter, renderer, validation and witness route. Freeze source-only
and candidate-centered results independently, and reuse compatible native work only
under PM2-01's identity determinants.

For source discovery keep an immutable source-only state and its exact reversible map.
Candidate-centered questions separate `source` and `candidates` fields. Prefer a
source-only read for an evidence witness, especially when a paraphrase in a candidate
can copy the literal. If a mixed read is allowed by the release, map the half-open
native span inside one allowlisted source string, confirm its JSON Pointer, decode its
exact substring and reconstruct it through PM2-01 to the source. Require analogous
exact reconstruction on plain text. A pointer to a candidate, split JSON field,
escape sequence with no exact inverse, ambiguous substring or inconsistent offset
remains a diagnostic. Record exact rendered state or a reconstructible representation
and its map. Use `engine.render(state, engine.ask(question))` for inspection. The rendered
state text and string map, with their own coordinate space, govern pointer interpretation.
Treat document instructions as source data and use the provider strictly as a read-only
producer. Retain prompt structure without relying on escapes to grant authority.

Native typed reads offer one contiguous span, bounded to 512 tokens for text and 32
for number/date. Model withholding can erase endpoints before native answer calibration.
Lowering an application threshold cannot recover those endpoints. Scope repeatable
fields into independent requests when appropriate and distinguish no returned span,
invalid mapping, an exact literal with no usable normalization, a grounded normalized
candidate and a separately supported judgment that a source omits a field. Prefer
existing validators and deterministic date/number processing for application semantics.
A number, date, unit or locale obtained from the rendered candidate description does
not qualify source evidence.

3. Verify the full pathway with real configured provider calls and the release-bound
   task and witness semantics. Include the retained GLiNER prefix reproduction and
   repaired literal occurrence, duplicate source spellings and sibling pack controls.
   For d1 exercise source-only detection without any upstream result, misleading candidate
   text that duplicates a source literal, Unicode and JSON escaping, exact source and
   cross-field refusal, valid spans with failed normalization, missing hosts, orthogonal
   qualifier meanings, ambiguous antecedents, and independent versus sequential questions.
   Check reordering and grouping at the boundary, over-limit and cancelled work, and
   the preservation of existing contributions on provider failure. Verify an accepted
   witness and an unresolved alternative through PM2-08's consumer.
4. Compare discovery, proposal availability, answer selection, grounding, normalization
   and contribution acceptance on the same independently reviewed source opportunities.
   Use oracle candidates to isolate selection errors and retain an ordinary source-only arm
   to expose omissions. Freeze the applicable rubric and threshold evaluation population
   under PM2-11. Require evidence for every enabled task family and leave unavailable
   tasks explicit. A calibration result on Grinstead–Snell applies to that defined
   population. Alternate serving runtimes, compilation, typed fine-tuning and wider
   context or media remain separately qualified options. Revisit them only when
   qualified eager inference exposes a task-specific quality or operating gap.
   Check required answer types before comparing a GGUF endpoint or another runtime.
   A route that omits typed reads or multilabel answers cannot replace this profile.
   Measure score and calibration differences on the same cases before reusing policy
   thresholds across runtimes.
