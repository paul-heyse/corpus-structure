# Protobuf projection and wire-semantics investigation

**Partial evidence, 2026-11-03.** Consumed by the
[functional review](../../../functional_reviews/protobuf-capabilities_2026-11-03.md) and
[capability assessment](../../../library_leverage/libraries/protobuf-ecosystem_2026-11-03.md).
Question: does native generation already preserve the semantics required for an application
interface? Commands:

```sh
uv run python docs/design_review/evidence/2026-11-03_protobuf-capabilities/probe.py
uv run python docs/design_review/evidence/2026-11-03_protobuf-capabilities/product_probe.py
```

Python 3.14 project environment: LinkML1.12.1, protobuf6.33.6, grpcio1.85.1,
Pydantic2.14.1; protoc36.2, Buf1.75.0. Rust version was recorded, not a Rust build result.
`raw/source-manifest.json` identifies exact inspected inputs and concurrent source state;
it is not a product qualification or a claim that the active tree stopped changing.

**passed, bounded:** corrected `probe.py` assertions and actual-core `product_probe.py` generation.
Raw results retain individual commands. The actual core compiles, but synthetic reorder changes
wire tags/enum numbers. Required scalar absence is accepted, integer2**40 refuses, binary unknown
fields survive the fixture and are lost through JSON. Dynamic descriptor construction works for
this fixture without importing generated Python. The initial failed probe log remains: YES/NO
were parsed as booleans and expected enum names differed; final fixture uses ACCEPT/REFUSE and
an explicit xsd prefix. It is a fixture correction, not evidence of a library defect.

**failed candidate checks, expected by the passing probe:** Buf rejects reordered declarations;
modern generated Python refuses the locked older runtime. No version check was bypassed and
no dependency was changed. These negative observations constrain recommendations.

**passed:** `just ready` after the observed environment-shaped incompatibility; log in raw/ready.log.
**not_run:** production integration, database/native application tests, external RPC, alternate
runtime/validator, cross-language SDK, descriptor extraction/reconstruction and performance.
They do not have selected delivery scope in this review. No stores or services were changed.

**failed, outside review pages:** `just docs-check` reports unresolved existing library targets;
raw/docs-check.log retains the complete output.

No speed/capacity inference follows. Decimal-to-string, fallback, inheritance and optional-field
limitations were inspected in installed generator source; compilation alone does not validate
those mappings. The accepted record is partial because production-equivalence and candidate
integration remain unresolved.
