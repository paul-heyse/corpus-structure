# Protected passage-function comparison

**Tested · 2026-11-09.** One native GLiNER2.5 CPU run and the retained d1 run
preserved the supported definition classification in protected set 36, unit 54
(d1 evaluation 40, run 431/cut 531). They used the same released independent
choice question, instruction, ordered criteria and exact Standard and Nemotron
view 383 extent `[811,907)`. GLiNER selected only `definition`. This exposed
development control shows parity on the one facet; it does not justify a default change.

The [read-only driver](compare.py) authenticates the source and historical
release, reconstructs the exact scope, and uses the pinned local CPU profile.
The diagnostic classification adapter binds the released family digest, question,
prompt, label order, source and provider profile to the shared GLiNER request
and observation digests. It preserves native scores and withholds labels below
the separately declared GLiNER threshold. It does not emit a literal span, public
assertion, or confidence calibration. The inference request never reads the
protected judgment; the driver reads the existing C pass and immutable d1 grade
after the worker closes, validates the same frozen reference and compares the
accepted keys with its exact allowed alternatives. The [receipt](raw/comparison.json)
retains both the model envelope and the protected case identity. The same driver
also checks that an altered source digest refuses before decoding.

The earlier [native diagnostic](../2026-11-09_pm2-passage-function/README.md)
did not verify the GLiNER reply through the located model request/observation
custody or compare against the protected C pass through its native reader.
The present result still does not register a managed GLiNER arm. The existing
`structure.clause_classification/2` method and native replay bind a predicate-frame
focus and a different released vocabulary; substituting it for the source-only
question would change the comparison. A managed arm needs its own released
producer binding and versioned native/detached replay for the existing protected
evaluator. An equivalent deterministic-cue arm and more independently frozen
opportunities are still open. There is no production code change. No database
effect, GPU request or recognition ran.
