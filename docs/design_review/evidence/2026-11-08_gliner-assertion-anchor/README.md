# GLiNER assertion anchor replay

**Tested · 2026-11-08.** The retained failure was in the default M1
assertion pack at context 435 of run 401, task 1866, source view 356. The
probe rebuilds the 33-byte context from two exact source slices and a
separator. It verifies the projection digest, the consumed-text digest
from the preceding definition request and the effective model profile.
The same slices from run 378, view 327, give byte-identical context.
The definition replay matched its retained output. The assertion replay
reproduced the recorded exception with both span output settings.

## Why the assertion fails

GLiNER puts the record's categorical choice tokens before the source
tokens. For this request, the prefix occupies positions `[0, 24)` and the
character maps cover eight source tokens. The packed shared-candidate
decoder admits prefix positions to the literal `predicate` query. Natural
record formation accepts a candidate from that query as the record seed
without checking its source range. In the replay the selected candidate
had score 0.51585 and pointed to the prefix spelling `positive` at `[6, 7)`.
The source text also contains that spelling at a different token position.
[Processor](https://github.com/fastino-ai/GLiNER2/blob/v2.1.0/gliner2/processor.py#L692-L732) ·
[Packed record routing](https://github.com/fastino-ai/GLiNER2/blob/v2.1.0/gliner2/models/boundary/records.py#L443-L496)

The formatter resolves the per-record `polarity` classification from the
same prefix token. A source interval must first fall wholly within the
source segment of this request's combined sequence. Its bounds are then
rebased by the request's prefix length and looked up in the source start
and end character maps. The application separately resolves those context
characters to native source pieces. Here the formatter attempted the
conversion with a prefix anchor, so the offset helper rejected `[-18, -17)`. The
ordinary literal-span formatter and the later literal-choice path have
range checks before conversion. This earlier enum branch performs the
conversion before consulting the span output option.
[Enum formatter](https://github.com/fastino-ai/GLiNER2/blob/v2.1.0/gliner2/models/boundary/engine.py#L1241-L1319) ·
[Offset helper](https://github.com/fastino-ai/GLiNER2/blob/v2.1.0/gliner2/inference/candidate_decoder.py#L33-L50)

A process-local diagnostic restricted only the natural predicate anchor
query to source positions before record assignment. It excluded 172
out-of-source candidate spans, including the one chosen in the baseline,
and returned zero assertion records without a decoder exception. This
isolates the fault for the retained request. Correctness across other
inputs, preservation of valid record classifications, and full-book
qualification require separate controls.

## Version and runtime history

- GLiNER2 v2.0.0 used a document-level enum fallback when formatting
  dropped prefix choices. Upstream change `d9b26b2`, shipped in v2.1.0,
  preserved each record's choice and added the unchecked anchor conversion.
  The checked upstream `main` commit `ca4f68235b50` retains it.
  [Per-record choice change](https://github.com/fastino-ai/GLiNER2/pull/158) ·
  [Checked decoder](https://github.com/fastino-ai/GLiNER2/blob/ca4f68235b50/gliner2/models/boundary/engine.py#L1210-L1269)
- v2.1.0 separately introduced packed record decoding and widened
  Transformers compatibility to 5.x. The replay used the pinned base
  checkpoint on CPU with standard attention, GLiNER2 2.1.0, Torch 2.15.0,
  Transformers 5.22.1, Tokenizers 0.23.3 and Safetensors 0.8.0. The observed
  exception comes from GLiNER's Python record formatter after inference.
  [Packed decoder change](https://github.com/fastino-ai/GLiNER2/commit/879fc2d4d3e9ef481dcc1368a0eebe462e0d802d) ·
  [Transformers compatibility change](https://github.com/fastino-ai/GLiNER2/pull/189)
- The repository has pinned GLiNER2 2.1.0 since `a96a6d700`. Run 401 is
  the first Grinstead–Snell full-book run in development to reach M1
  candidate tasks. Version 9 admitted the current method configuration and
  exposed the failing context under the existing provider pin.
