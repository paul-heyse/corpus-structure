# Native HanLP roles on the retained binomial definition

**Tested · 2026-11-09.** The [read-only probe](compare_hanlp.py) uses the
[frozen binomial input](../2026-11-09_pm2-adoption/raw/target-inputs.json), the exact
source pin shared with the [retained spaCy comparison](../2026-11-09_pm2-definition-prerequisite/README.md),
and the admitted analysis release. Native validation authenticated run 407, cut 517,
view 387. The authored target spans projected characters `[52066,52355)`; its
covering canonical sentence scope is `[52043,52499)`, so it also includes the
heading and the immediately following sentence. The comparison below addresses
the original target's exact source pieces, without treating the extra text as
defining content.

The HanLP 2.1.7 Large worker used its pinned model and tokenizer, native UD and
constituency, and its ordinary SRL head. The [canonical CUDA result](raw/hanlp.json)
retains native outputs and the same typed, located products the ordinary parser
would derive. The syntax-only reading examines the UD and constituency portion
of the same native call; the SRL reading adds its retained roles. This controls
the input and encoder but does not measure cost or outputs of a separate
checkpoint call with fewer heads.

| Exact obligation | Canonical HanLP result |
| --- | --- |
| Opening declarations for `n` and `p` | UD gives `n` the subject of the integer copula, where the retained spaCy token was `ADV/cc`. The `p` copula's projected UD complement stops at `0`; the SRL argument retains `a real number between 0 and 1` in full. |
| Complete `B` counting definition | UD locates the counting predicate, its object and the parameter phrase. That phrase ends at `n and`; the canonical layout presents `p.` as a separate sentence. The SRL output does not attach it. |
| Direction of naming | UD and SRL locate `the distribution b(n, p, k) of B` and `the binomial distribution` on opposite roles of `called`. They do not establish that the earlier declaration and both parameter roles bind to this use. |

The existing [named-rule production result](../2026-11-09_pm2-adoption/README.md)
is an explanation. That supported reading and the `definition-scope-1` witness
remain unchanged. No extraction, recognition, native write, schema migration or
activation was done for the comparison.

The [same-device CPU pair](raw/hanlp-layout.json) uses the same source, model and
heads. Its only input change is the exact prior `p`/period split and join of the
orphan sentence to the `B` declaration. The probe requires that the split lie
between two native text pieces and not cut a protected atom. The separately
identified diagnostic recovers `p` as a UD conjunct of `n`; the SRL complements
and the retained argument span include both parameter occurrences. The passive
naming still has the same two roles. This isolates an upstream layout loss;
adding a head to the canonical orphan would not connect the sentences.

**Blocked: eligible definition target.** These are local candidates. No released
rule establishes the cross-sentence declaration-to-use bindings, including both
parameters and the unique `B` antecedent, or identifies the whole act as a
definition with the required scope. Neither ordinary parser yields all the
needed located roles at the selected layout. The split was supplied from the
previous diagnostic, and the prior constant-density control showed that indiscriminate
splits can alter a naming antecedent. An ordinary route needs a bounded, released
boundary policy and a reviewed declaration-chain binding, then matching producer,
native and detached positive/refusal cases. This work does not add or authorize a
new definition witness, promote the diagnostic layout, or populate retrieval's
eligible target inventory.
