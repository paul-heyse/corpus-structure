## Workload eligibility

`uv run python docs/design_review/evidence/2026-11-19_udm-workload-custody/probe.py` inspects the
installed source for the generator, native demand, rich read and contributions entry points.
The recorded result distinguishes broad discovery sites from required workload blockers.
The authenticated package handoff can account for its fixed loader without promoting the
broad module walk. Analysis withholds all four production identities at unsupported
initializers and external initialization contracts. The early check avoids building the full
source-slicing model when one of those required premises is already unresolved.
[Observations](raw/workloads.json)

The bounded tests cover the indirect-load counterexample, an uncalled function's import, a
rejected eager effect, exact source custody, and missing or mismatched serving identity.
They also exercise continued authorized fresh reads and the existing typed disk codec. An
injected complete identity qualifies the controlled cache behavior for that fixture only.
The focused control selection passed all 92 identities (`0f91dae04a0347719c8f999dedb102cc`).
The initial selection reproduced a PDF lowering tuple-arity error (`4a6c0b6fb431486186377cab2053f08d`).
The corrected consumer reads the boundary's single source collection.

The first private native run failed in fixture setup after an observed Python source edit
(`ecca9bb40bbf442eb05a1955d6b98daa`). A separate authored entity fixture uses a committed private
clone and skips upstream PDF discovery. Its first model assembly lacked the native definition
projection (`1ce60ad601f943ed9e2cf03c025dae5d`). Adding the native projection reached the
admission guard, which refused unchecked required semantics (`99446d69a099463b888184cee61a3d22`).
The fixture now uses the existing publication recipe and preserves its compiled native inputs
while omitting PDF data acquisition. That attempt failed when the publication recipe combined
primary source collections that disagreed on a captured module (`f724c1dd7f584f998420183fcecc298a`).
It stopped before entity publication. The fixture and real reuse journey have separate outcomes.

Both private qualification tests are opt-in with `CORPUS_RUN_UDM_T14=1` and the matching
`uv run ci test --native-host private` selection of `test_record_publication_native.py`. The
cross-process T14 test requires a real second-process cache hit
under fresh code custody and native authority. It was not run under the incomplete identities
observed above.
