# DDO operation and consumer inventory

**Interface-checked by static source inspection, 2026-11-12.** The reusable inventory reads the
owned execution YAML and Python syntax without importing application/provider implementations.
It records all 101 existing declared protocol operations with their actual inputs/results/effects,
implementation binding and call metadata, plus constructor evidence from the phase0 registry,
local method candidates, six descriptor bypass sites and domain-pack configuration identities.
Exact examined-file hashes are retained; this is a source snapshot, not live runtime introspection.

Command: `uv run python docs/design_review/evidence/2026-11-12_ddo-operation-inventory/inventory.py`.

The protocol inventory is declaration-owned. Method candidates are implementation-owned migration
subjects; constructor evidence is distinct from dynamic runtime registry validation. Inventory
profile classifications guide DDO-00 review, never production readiness or effect permission.
Native publication/request consumers belong DDO-04; method/descriptor replacement belongs DDO-07/08;
inspection and reference consumers belong DDO-10. New DDO-01/02 compiler facts are not automatically
selected by existing production registries.

The original partial record remains intact. The [consumer reconciliation](consumer-reconciliation.md)
and expanded [V2 inventory](raw/inventory-v2.json) settle the missing M1/inheritance/descriptor/
authoring-path and immediate-consumer questions. Their new record reports **passed** for that
bounded metadata inquiry. Actual target compilation, native admission and adapter migration retain
their own package acceptance. No provider execution or protected reference body was inspected.
