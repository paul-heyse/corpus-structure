# Bounded resident/spooled capture investigation

**Measured and scoped Tested,2026-10-30.** This investigation exercises real PostgreSQL,
ADBC1.13.0, PyArrow26 and DuckDB2.0. It is a representation/capacity decision, not a
full-corpus throughput comparison or a process-memory ceiling measurement.

Run from the repository root:

```sh
uv run python docs/design_review/evidence/2026-10-30_data-capture/probe.py
```

The probe runs the independently asserted native capacity case. It creates a full26-relation
projection containing1,024 evidence rows with4,194,304 source-text characters, inserted in reverse
identifier order. Resident capture refuses at a configured1 MiB retained-Arrow limit. Spooled
capture completes, DuckDB consumes the files, and full export retains the evidence row count and
all spine relations. Resident capture with16 MiB admission and31-row batches has the same logical
digest and exact evidence values as spooled capture with64-row batches. Closing the disposable
capture removes its backing directory while the explicit export remains.

The observed spooled capture interval was0.0747s in this one run; it includes PostgreSQL/ADBC
retrieval, normalization, logical hashing and Parquet closure. Model/store setup and subsequent
analysis/export are outside that interval. These operations are functionally asserted but their
latency is not claimed. The result does not establish512 MiB default capacity, whole-process RSS,
a throughput speedup, or performance of a dense scientific relationship graph.

Selected execution defaults are65,536 consumer rows, an8 MiB ADBC batch-size hint,512 MiB retained
resident Arrow admission, and explicit spooled CLI export. The driver hint is not a hard batch-byte
bound. DuckDB's memory_limit is not a Python/Arrow/process-memory cap. Oversized resident capture
refuses and requests spooled mode; there is no automatic estimator or mode switch.

Structured detached state is selected for its bounded live representation and released database
scopes. Source primary-key order supports streaming logical hashes without global Python sorting.
File hashes retain physical integrity independently of logical content. This record informs PE-09;
assembled production/provider/nonfunctional qualification remains PE-12.
