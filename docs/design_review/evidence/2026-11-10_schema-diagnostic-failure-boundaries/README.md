# Retained schema diagnostic failure boundaries

Completion-audit probe of two accepted CLI contracts: optional diagnostic publication preserves
the original operation outcome, and unexpected defects retain a distinct exception product.
The CLI and domain preparation are real; only the publication failure and unexpected preparation
exception are injected. No database, provider, activation or production repair is involved.

Run from the repository root:

```sh
uv run python docs/design_review/evidence/2026-11-10_schema-diagnostic-failure-boundaries/probe.py
```

The probe uses temporary result stores and reads the actual retained diagnostic through the CLI.
Its JSON output reports observed route outcomes separately from the expected contract checks.
Nonzero exit means at least one accepted product contract was not delivered. The owning
[CLI/logging coordinator](../../../plans/cli-and-logging_2026-11-10.md) consumes the result;
its completion audit owns finding disposition. Product source baseline is `0da4f8e614b1`.

**Failed product-contract checks, 2026-11-10.** Python3.14.10, Typer0.28.0, Rich15.0.0 and
structlog26.1.0 are recorded in `result.json`. The normal retained check exits0, settles passed
and returns a CompileResult. With optional publication alone raising OSError, it exits1, settles
failed and returns no CompileResult. An injected ExceptionGroup retains its original exception
and failed outcome, but its replay is a report5 `validator_failure` with no observation journal.
These observations confirm CLD-CA01/02; they do not establish future complete exception-content
acceptance. The coordinator specifies independent group/cause/notes/frame closure expectations.

The [finalized result](records/schema.failure-boundaries.json) hashes the source and observed
output. Result stores are temporary and never committed; no external model or native database
execution is represented as passed by this probe.
