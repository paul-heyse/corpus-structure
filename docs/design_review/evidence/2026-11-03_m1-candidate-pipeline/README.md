## Implemented route and scope

`ci run --extraction-policy m1-candidate` requires all three explicit
`--integrated-product-task`, `--integrated-product-key` and
`--integrated-product-digest` fields. A validated exact retained integrated pin is
required before a run can be created. The graph selects retained adoption through
the existing PDF producer, then `extract.m1_candidates`; it refuses re-conversion.
Its registry/guideline/configuration are separate `m1-methods.yaml` and
`m1-guideline.md` owners. The existing phase0 default graph/registry dispatch and
its invocation identity remain unchanged. The M1 invocation records the explicit
policy identity and exact method-pack bytes; the existing run manifest records
resolved configuration, guideline and relevant library versions.

The M1 registry contains no agent or general LLM method. It loads no predecessor
agent policy/configurations, and has no hosted, specialist or re-conversion
fallback. The terminal state remains existing source readiness. Private candidate
records do not establish accepted knowledge, calibrated scores or selected output.

Preparation preserves one shared pinned source frame, compact context/region
descriptors and reusable linguistic columns. Actual native inline parentage groups
split pieces into coherent paragraphs; native table cells retain separate
linguistic blocks. Mathematical, display and reference atoms retain source-owned
positions. Whole-sentence windows bound long prose; an oversized coherent sentence
or structure has an explicit limit. Native worker word/subword admission remains
worker-owned. Every selected native item retains a disposition, including unknown
labels, no canonical projection, empty and limited regions. Unknown text receives
the broad definition/assertion/measurement packs. Native table/formula structure
triggers their routes independently of classifier scores.

Native table metadata supplies explicit row/header paths; incomplete or ambiguous
paths remain unresolved. The native formula adapter consumes the existing
`FormulaOccurrence` without inventing original/canonical equivalence. Related-source
contexts, recognition-alternative anchors and declaration/note widening remain
unsupported in this initial canonical same-view route and are visible exclusions.
This denominator concerns the selected native view, not an independent original-PDF
intake audit or a released population.

One run-owned worker serves serial source phases and single-context requests. The
parent annotation phase uses a controller discovered after the relevant NLP/native
libraries load, and restores its limits. The child owns Torch CPU limits. This route
does not execute DuckDB analytical work. Every request receives the parent lease
check; existing orchestration closes owned resources. An inference failure marks
remaining context work `not_run`, retains diagnostics and refuses automatic
restart/fallback. Raw decoder JSON remains exact; input text reconstructs from its
shared source/context descriptor, consumed-text digest and synthetic suffix.
Effective runtime profiles are stored once per source result.

`UnitResult.records=None` preserves predecessor report absence; explicit `()` records
an inspected empty candidate collection. Nonempty records require a produced result.
The semantic runner forwards this collection to existing
`complete_unit_result(records=...)`. Actual native database custody/fencing for this
new route remains an integration obligation after the coordinator's provenance and
native freeze; the detached controls below do not qualify that boundary.
