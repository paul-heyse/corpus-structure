# CLI agent usage from Codex session logs (2026-11-16)

Empirical track for the `ci` CLI functional-extension review: what coding agents actually ran, from Codex rollout logs.

**Data window.** `~/.codex/sessions/2026/11/{14,15,16}/`, files whose first `session_meta` has `cwd` `/home/paul/corpus-structure`
(88 sessions: 1 root, 35 executor, 25 code-mapper, 10 implementation-reviewer, 6 design-reviewer, 5 library-research, 3 test-agent, 3 explorer).
Many executors worked in sibling worktrees (`/home/paul/ddo-*`, `/tmp/ddo-*`) while the log `cwd` is the main checkout.
Raw logs stay in `~/.codex`; this folder holds only aggregates and short (<=200 char, masked) command examples.

**Rerun.** `python3 extract.py` (stdlib only, ~20 s; options `--sessions-root --days --cwd --out`). It rewrites every file here except this README.

**Files.** `summary.json`, `command_mix.csv`, `command_mix_by_role.json`, `ci_subcommands_top40.csv`, `ci_all_subcommands.json`, `ci_pipelines.json`,
`ci_exit_codes.json`, `output_size_distribution.json`, `largest_outputs_top30.csv`, `output_extremes.json`, `capture_then_reread*.{json,csv}`,
`inline_scripts.json`, `discoverability.json`, `usage_errors.csv`, `repeated_commands_top40.csv`, `most_read_paths_top40.csv`, `session_start_reads.json`,
`source_navigation.json`, `test_loop.json`, `ci_test_launches.csv`, `long_running_commands.json`, `mechanical_edits.json`, `repeated_replace_pairs.json`,
`env_and_waiting.json`, `per_session.csv`, `tables.md`.

**Method notes.**
- Commands come from `tools.exec_command({cmd: ...})` string literals inside `custom_tool_call` inputs; edits via `tools.apply_patch`; polls via `tools.write_stdin`.
- Forked subagents replay inherited parent history stamped within ~0.5 s of their own start; those records are skipped (`REPLAY_WINDOW`).
- Class = first non-trivial statement of the command after stripping `cd`, env assignments, `uv run`, `timeout`, `bash -lc`. Counts "anywhere" are in `summary.json`.
- Output size is the delivered (post-cap) string; `orig_tokens` is the pre-cap count; "over cap" = original token count above that call's `max_output_tokens`.

**Limits.**
- `cmd` built from JS variables (`cmd:cmdFor(0)`, template concatenation) is not parsed (189 of 26,159 execs); stage splitting is a heuristic shell tokenizer, not bash.
- Exit codes exist only for calls that finished within the first yield; ~3,400 calls returned a running session id and were completed through `write_stdin`, whose later exit codes are tracked only for the long-running table.
- Multi-command scripts: results are matched to commands by order; mismatches leave a command without size/exit data.
- Inline-script classes are regex heuristics (priority: file-edit, code-intel, ci-output parse, database, docs, other); an edit script that also parses output is counted as an edit.
- The logs do not show agent intent, wall time spent thinking, files viewed through other tools, or whether a command's output was used. Reasoning records were not read.
- One root session holds 27% of commands (30 context compactions), so aggregate shares are dominated by executors and that session.
