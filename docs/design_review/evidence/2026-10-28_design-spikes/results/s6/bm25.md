## Syntax that worked, and observations (2026-10-28)

- **Working form** (OPEN-D3-1): `ORDER BY s.text <@> to_bm25query(:q, 'kb.segment_bm25') LIMIT :k` with the index predicate repeated as `s.kind IN (…) AND s.ts_config = 'english'::regconfig`; the schema-qualified index name is required (V8: `42704: index "segment_bm25" does not exist`). The planner uses an ordered `Index Scan using segment_bm25`, and the rendition condition is a post-filter on it (V1). A narrower kind predicate implied by the index's (V9) also uses it.
- **D3 §5's query as written fails** (V2: `22P02: invalid input syntax for type oid: "english"`): the F1 cast is needed in the repeated predicate.
- **The implicit string form fails** on the partial index, with a bound parameter (V5: `42704: no BM25 index found for text <@> text expression`) and with a literal (V6: `42704: no non-partial BM25 index found for this column (1 partial index(es) skipped)`): an error, not a silent seq scan.
- **Repeating the predicate matters for results, not only for the plan.** Named index without the predicate (V4) or with a predicate the planner cannot prove (V7, `ts_config::text = 'english'`): no index scan; rows are scored standalone with the index's statistics and sorted, and V4 returns rows the index does not hold (kinds heading, paragraph, section, unit).
- **Prepared statements** (`$1` inside `to_bm25query`): custom and forced generic plans both use the index ({'custom_index': True, 'generic_index': True, 'generic_rows': 5}).
- **Boolean and phrase filters** (`@@ to_tsquery('english', …)`) return their matches; at this size the planner evaluates `@@` as a filter over `segment_kind`. The probe shows `segment_bm25` can serve `@@` alone (`Index Cond: text @@ …`), but not combined with BM25 ordering: then the filter is evaluated on scanned rows and the matches scored and sorted, as the overview (§2.3) says.
- **The kind list overlaps.** D3's list indexes `math_display` segments that are children of indexed `paragraph` and `list_item` segments: 71 nested pairs, 6552 of 54826 non-space characters indexed twice. Without `math_display` there is no overlap; adding `caption` covers the remaining 48 characters (the Gamma page's figure caption). Display formulas outside a paragraph are already `paragraph` segments (D1 §3.2 orphans), so `('paragraph','heading','list_item','caption')` covers every character once on the four pages.
- Index: 587 rows, rebuilt in 7.5 ms, 73728 bytes on the four pages; scores negative and ascending in all five queries.
