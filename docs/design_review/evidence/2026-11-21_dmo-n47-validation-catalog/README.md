# N47 generated and installed schema validation sites

On 2026-11-21, `uv run python docs/design_review/evidence/2026-11-21_dmo-n47-validation-catalog/inventory.py`
compared the native generator on source `5d2ba51e5` with the read-only catalog on the dedicated
N47 stage `corpus_structure_ddo_stage` (OID 130661481).

The probe renders the current typed native program declarations and reads PostgreSQL
`pg_proc.prosrc` for the same application schemas. It counts direct, schema-qualified calls to
`public.json_matches_schema`. It compares the qualified routine population and call counts.
The [raw result](raw/generated-and-installed.json) includes each routine's generated source owner,
argument types and installed signature.

Both populations contained 43 routines and 54 direct call sites. Every named routine had the
same count in source and catalog. Four routines contained multiple calls. These are
`ops.adopt_pdf_companions`, `ops.ddo_body_kind_contracts`,
`ops.ddo_install_product_context` and `ops.ddo_validate_parameters`.

These counts cover the selected function and direct call syntax. The separate limits include
transitive callers, other validators, indirect checks, and which validation is redundant under
a current authority and custody guarantee. DMO-06 uses the named inventory when migrating
those validation boundaries. [Validation and retirement plan](../../../plans/domain-model-operability/json-contracts-and-settings.md#validation-generation-and-cutover)
