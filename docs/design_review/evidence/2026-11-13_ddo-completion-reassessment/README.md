# Captured builtins recipe and runtime-authentication escape

**Tested as a defect reproduction · 2026-11-13.** The completion reassessment found that
source closure treats lexical builtins as standard while runtime authentication checks module
globals rather than the function's captured builtin namespace. The
[DDO coordinator](../../../plans/declared-data-operations_2026-11-12.md#completion-audit--2026-11-13)
owns the current DDO-CA-01 disposition and repair scope. This folder is bounded probe evidence,
not a separate completion report.

`builtins_probe.py` compiles two captured modules. Each module replaces its own `__builtins__`
mapping before defining the operation. Only the uncaptured `fake_len` result changes, from 7
to 8. Both slices are complete, have no unknowns, contain only the entry function and the
interpretation node, and receive the same recipe. Independently acquired original-callable ports
return `"7"` and `"8"`. Changing each acquired function's isolated builtin mapping then makes
the same admitted port return `"9"`, without any source or module-global change.

The temporary modules and their mappings are confined to the probe process. The process-wide
Python builtin module is not modified. No provider, database, protected data, production write
or cancelled test campaign is involved. `source-baseline.json` records relevant implementation
hashes and source/checkout boundaries; `builtins-result.json` retains the observed results.
