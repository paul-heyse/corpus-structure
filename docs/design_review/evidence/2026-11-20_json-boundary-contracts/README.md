# Library contracts at this repository's JSON boundaries

**Tested · 2026-11-20.** These probes establish how the pinned libraries behave at the points
where the JSON design depends on them: python-rapidjson 1.25, jsonschema 4.26.0 with
referencing 0.37.0, pg_jsonschema 0.3.4 on PostgreSQL 18.7, pydantic 2.14.1 with pydantic-core
2.50.1, pydantic-settings 2.16.1 and psycopg 3.3.6, on CPython 3.14.10 and Linux x86_64. The
[JSON boundaries review](../../../functional_reviews/json-boundaries_2026-11-20.md) consumes
the results.

## What the probes show

**python-rapidjson.** Plain `loads` keeps the last of two duplicate keys. A `Decoder` subclass
whose `start_object` returns a list refuses duplicates at any depth and keeps `NM_DECIMAL`.
An embedded NUL ends the document without an error in 1.25. Nesting beyond the interpreter
recursion limit raises `RecursionError`, which is not a `ValueError`. Output differs from the
stdlib canonical recipe only in the hex case of ten control-character escapes and in Decimal
spelling. The encoder accepts tuples, iterators and container subclasses by default; its
strictest modes still pass `str`, `int`, `float` and `Decimal` subclasses. `RawJSON` inserts
text unvalidated. A byte bound cannot be enforced by raising from a stream's `write`.
`rapidjson.Validator` implements Draft 4: on the repository's 72 wire schemas it accepted every
mutated `const` value and rejected 13 of 91 valid instances holding integers of 2⁶⁴ or more.

**jsonschema and pg_jsonschema.** jsonschema's `integer` rejects every `Decimal`; a float
schema constant compared with a `Decimal` instance fails `minimum` and `const` and raises
`TypeError` in `multipleOf`. The default registry retrieves a remote `$ref` over the network;
`registry=Registry()` prevents it. Python's `pattern` accepts a trailing newline before `$`
and PostgreSQL's does not. pg_jsonschema assumes Draft 2020-12 when `$schema` is absent,
asserts `format` under Draft 7 and compiles the schema on each call. Twenty-seven of 56
schema-and-instance cases give different answers across the two engines.

**pydantic.** `validate_json` reads a JSON number for a `Decimal` field through a float:
`1.10` becomes `Decimal('1.1')` and digits beyond about 17 are lost. A JSON string stays
exact, and so does `validate_python`. Strict JSON mode accepts strings for `Decimal`, dates,
enums and UUIDs where strict Python mode refuses them; no single call reproduces that on
decoded data. A `GenerateJsonSchema` subclass reproduced the repository's hand lowering to
Draft 7 on a sample model.

**pydantic-settings.** A section model built on its own ignores the environment. A source
placed last can read the documented `settings_sources_data` to report which source supplied
each value. A JSON file source can be added per call and sources merge by key.

## Running

From the repository root, with the project environment:

```sh
uv run python -I docs/design_review/evidence/2026-11-20_json-boundary-contracts/rapidjson_probe.py
uv run python -I docs/design_review/evidence/2026-11-20_json-boundary-contracts/rapidjson_limits_probe.py
uv run python -I docs/design_review/evidence/2026-11-20_json-boundary-contracts/rapidjson_validator_probe.py
uv run python -I docs/design_review/evidence/2026-11-20_json-boundary-contracts/rapidjson_psycopg_probe.py
uv run python docs/design_review/evidence/2026-11-20_json-boundary-contracts/schema_models_jsonschema_probe.py
uv run python docs/design_review/evidence/2026-11-20_json-boundary-contracts/schema_models_pg_probe.py
uv run python docs/design_review/evidence/2026-11-20_json-boundary-contracts/schema_models_pydantic_probe.py
uv run python docs/design_review/evidence/2026-11-20_json-boundary-contracts/schema_models_settings_probe.py
```

Each file under `raw/` begins with the command that produced it. The PostgreSQL probe reads
the development database on port 5434 with `SELECT` statements only and writes the statements
it ran to `schema_models_pg.sql`. The limits probe runs its crash cases in child processes.

## Limits

The probes use constructed values and the assembled wire contracts. They show library
behaviour, and they do not show which values production paths carry. Nothing was timed. The
1.26 release of python-rapidjson was read from its changelog and not run.
