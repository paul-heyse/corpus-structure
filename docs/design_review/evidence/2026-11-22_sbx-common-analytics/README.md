# Shared analytical population controls

**Tested · 2026-11-22.** This experiment informs the [common analytical basis review](../../../plan_improvement_reviews/set-based-execution-common-analytics_2026-11-22.md). Source baseline `d884fa8a2`. Linux x86-64, CPython 3.14.10, DuckDB Python 2.0.0, DuckDB CLI `d54cbbe3df`, PyArrow 26.0.0.

Run `uv run --no-sync python docs/design_review/evidence/2026-11-22_sbx-common-analytics/probe.py`. The probe constructs synthetic typed Arrow rows, writes Parquet in a temporary directory, and runs small control queries through the existing analytical owner and the CLI.

- Arrow's full structural validation accepted a table with a duplicate ordinal and out-of-range span. A set query found those exact violations and distinguished a pending population from a closed empty population.
- Four independent expectations matched on both inputs. They cover validation, current placement for equal local spans, absent member addresses, and typed decimal, UTC timestamp, and explicit-null versus absent values. The last distinction used an explicit presence field.
- A typed window worked through the existing expression owner. CLI `DESCRIBE` returned the expected shape and `EXPLAIN` showed both a projection and a filter at the Parquet scan. This is plan evidence for the fixture.
- The exact UTC nanosecond sample survived Arrow and Parquet scans and conversion back to Arrow on this build. During exploration, the alternative Python scalar timestamp fetch required an unavailable `pytz` import. The retained probe exercises the Arrow result path.
- An unfinished result blocked another query on the connection until drained. Both readers refused a truncated Parquet footer.

These are library and fixture observations. PostgreSQL, production schemas, permission and claim behavior, actual crash recovery, and performance are outside the probe. The review compares those responsibilities from implementation and existing evidence.
