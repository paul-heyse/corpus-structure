# Native reference import considerations

**Inspected2026-11-06; recommendations for the root's existing native import responsibility.**
No protected reference or database mutation was performed by these assessment adapters.

The production owner is `evaluate/operation_assessment.py`, with protected native operations in
`semantic/sql/operation_assessment.sql` and the existing eval set/unit/pass/frame/evaluation store.
`OperationEvaluationFrameV2`, `OperationSourceOpportunity`, `OperationCase`, `encode_frame`,
`decode_authored` and `score_cases` already distinguish source-first opportunities from output-first
correctness. Use those contracts; these JSON evidence adapters are not a replacement reference store.

A suitable import route is:

1. Freeze versioned operation question, rubric, guideline, inspected scope and source pins before
   candidate/output filtering. Use `source_group=grinstead-snell`, an authorized development or
   feature-fit partition and actual exposure history. The same120 pages are permitted for fitting
   and assessment; no held-out interpretation follows.
2. Authenticate source quotes through the existing source context and `evidence_anchor(...,
   native=True)` owner. The normalized files retain exact projection slices and unchanged native
   pieces, including product/pointer/native offsets and parent-page maps. These support independent
   anchor construction; an intersecting produced anchor must not become the source expectation.
3. Build source-first opportunities before consulting emitted IDs. Each protected unit has one
   named operation question and version, a primary pin plus any related pins, and explicit source
   opportunities. An absent projected page is uninspected; it cannot acquire an unsupported truth
   label about the original PDF. Inventory omission is also not source absence.
4. Retain A/B/C authoring separately. The broad source inventories are different selected case
   populations, so they are not automatically three votes on identical questions. A common-case
   adjudication needs explicit author scope, disagreements and independently authored alternatives.
5. Author exact `OperationCase.alternatives` for each assessed role or relationship. Supported,
   stated cases require nonempty alternatives. Prose such as A's `semantic_distinction`, B's
   `expected_roles_relationships` or C's relationship descriptions is useful source evidence but
   cannot be copied into machine equality fields without a semantic mapping decision. Preserve
   alternatives, missing facets, uncertainties and unassessed cases rather than inventing labels.
6. For output-first correctness, freeze actual contribution IDs and the exact completed cut.
   Relationships need complete endpoint closure and independently authored endpoint-role anchor
   sets. Use each narrow facet explicitly: source location, role, direction, endpoint, scope,
   value and relationship meaning are different questions. Their labels cannot be promoted to
   whole-record correctness or independent publication eligibility.
7. Submit exact authored bytes through the existing A/B/C pass route and grade under that same
   frozen frame. `score_cases` already preserves source-first physical deduplication versus
   output-first emitted identities, unmatched cases, uncertainty and explicit absence detection.

Current compatibility limits:

- The812 normalized author cases do not form812 exact protected machine alternatives. They remain
  selective independent source inventories until the authoring above is supplied.
- The account's593 source cases with physical intersections are not593 supported captures. The219
  with no intersection are location gaps under these quoted scopes, not proven concept misses.
  Unmatched outputs are not automatically false positives.
- The proposed WCE09 event fitter inspected in the interpretation worktree consumes a protected
  `defined_by_correctness` output-first grade for emitted `relation.defined_by` contributions.
  Supported alternatives must bind both `head` and `tail` endpoint scopes. Baseline139 contains
  no contribution of semantic type `relation.defined_by`; its generic definition fields and nine
  separate structural components cannot be relabelled into that event. A suitable actual producer
  run and correctly authored event population are prerequisites, or fitting must report unavailable.
- Raw provider payload retention is separate from accepted task-result custody. The current capture
  records accepted immutable envelopes; a rejected completion's truncated error-log parameter is not
  evidence that the rejected full payload is retained.
