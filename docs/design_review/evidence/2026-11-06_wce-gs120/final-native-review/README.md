One specific execution-fit concern remains to reconcile with the actual measurement: `dossier_contributions.sql` lines76–82 emits `sources_`, including source projections, in every per-reference result. The same source projection can therefore occur in many rows of the batch result. PostgreSQL18 documents that PL/pgSQL set-returning functions materialize their entire result before returning, potentially spilling to disk ([RETURN NEXT documentation](https://www.postgresql.org/docs/18/plpgsql-control-structures.html#PLPGSQL-STATEMENTS-RETURNING)). This is a concrete intermediate duplication, not evidence that the 120-second target fails. Retain the actual complete-member timing and any available spill evidence; if that run fails, moving per-member projection inside the custody-binding loop is a focused way to avoid materializing repeated source projections while preserving the single validation owner. No wider SQL redesign is recommended by this review.
