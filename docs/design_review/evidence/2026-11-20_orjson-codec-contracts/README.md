# orjson and msgspec against this repository's JSON recipes

**Tested · 2026-11-20.** On generated values, orjson 3.13.0 writes the same bytes as the
stdlib identity recipe (`canonical_bytes`) for strings, 64-bit integers, booleans, null,
Decimals and nested containers with string keys. It differs for floats whose decimal exponent
is −9 to −5, refuses integers beyond 64 bits, writes `NaN` as `null`, and writes `Enum`, `UUID`
and dataclass values that the recipe refuses. Its decoder turns an integer beyond 64 bits into
a float without raising and has no decimal mode.

msgspec 0.22.0 matches the identity recipe on the same non-float domain when given a callable
`decimal_format`, and differs for floats in the same band and from 1e16 upward. Its
`decimal_format="number"` encoder matches the rapidjson exact-decimal recipe (`json_bytes`) on
integers, finite Decimals and text from U+0020 upward; it differs on control-character escapes
and writes non-finite Decimals as invalid JSON. `Decoder(float_hook=Decimal)` reproduces
`NM_DECIMAL` decoding except that it accepts `1E400`.

The [probe](probe.py) ran on Linux x86_64 with CPython 3.14.10. It installs the libraries
ephemerally and changes no manifest or lockfile. Run it from this folder:

```sh
uv run --no-project --python 3.14.10 --with orjson==3.13.0 --with msgspec==0.22.0 \
  --with python-rapidjson==1.25 --with hypothesis python -I probe.py > raw/probe.txt
```

The values are synthetic. The probe establishes library behaviour on them; it does not
establish which values production code hashes. The
[functional review](../../../functional_reviews/orjson-json-codec_2026-11-20.md) consumes this
result.
