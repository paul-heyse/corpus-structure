# Local diskcache-community storage contracts

**Tested · 2026-11-20.** Two spawned writers competing for one key installed one
winner. A read-only opener returned the winner and refused deletion. A writer
blocked by another connection surfaced `Timeout` with `retry=False` and left
its key absent. File-backed bytes round-tripped through an explicitly closed
stream and the entry could then be deleted.

The [probe](probe.py) ran on Linux x86_64 with Python 3.14.10 and SQLite 3.53.1.
It used temporary local cache directories and imported the extracted
[diskcache-community 5.8.5 source](https://github.com/secondwindoss/diskcache-community/tree/6c48b163bcdcfb6e82d4ec6068045c295b4f2d1c)
through `PYTHONPATH`.

```sh
source_dir=$(mktemp -d)
curl -fLsS https://codeload.github.com/secondwindoss/diskcache-community/tar.gz/6c48b163bcdcfb6e82d4ec6068045c295b4f2d1c | tar -xz -C "$source_dir"
PYTHONPATH="$source_dir/diskcache-community-6c48b163bcdcfb6e82d4ec6068045c295b4f2d1c" \
  uv run --no-sync python docs/design_review/evidence/2026-11-20_cache-backend-contracts/probe.py
```

The timeout result applies to an established connection. Cold open during
contention, physical space and large production artifact hydration remain
implementation decision inputs. These synthetic values exercise the storage
interface. Actual D2, T4 and T14 qualification stays with UDM. The [functional
review](../../../functional_reviews/cachetools-and-diskcache-community_2026-11-20.md)
consumes this result.
