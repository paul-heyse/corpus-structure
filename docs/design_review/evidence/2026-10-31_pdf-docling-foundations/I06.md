# I06 — Native schema, geometry and PostgreSQL JSONB

**Tested, bounded scope · 2026-10-31.** Native Docling/core 2.103.1, Pydantic 2.14.1,
jsonschema 4.26.0, SQLAlchemy 2.1.5 and psycopg 3.3.6 in the isolated full-Docling
investigation environment. No application dependency, schema, migration, publication or
operational database was changed.

## Method and outcomes

`schema_probe.py` constructs an independently specified native document with a section and
subsection, heading, two distinct equal-text formula occurrences, explicit page/region
provenance and a one-cell table retaining the string `12.3400`. It generates both native JSON
Schema modes, checks their Draft 2020-12 metaschema, and uses a closed in-memory
`referencing.Registry` with an explicit dialect. It then challenges an invented text-item
label, a dangling child and a wrong parent. The same probe also ran on the actual page-85
Heron conversion supplied by the coordinator, without invoking inference again.

Commands, both **passed**:

```sh
uv run --project docs/design_review/evidence/2026-10-31_pdf-docling-foundations python docs/design_review/evidence/2026-10-31_pdf-docling-foundations/schema_probe.py
uv run --project docs/design_review/evidence/2026-10-31_pdf-docling-foundations python docs/design_review/evidence/2026-10-31_pdf-docling-foundations/schema_probe.py --document docs/design_review/evidence/2026-10-31_pdf-docling-foundations/raw/heron-85.document.json
```

Results are in `raw/schema-results.json` and `raw/schema-real-results.json`, with generated
schemas/documents and command logs. These are native/datatype probes, **not** protected
application-publication qualification.

## Consequential findings

- The native fixture and real converted document pass validation-mode and serialization-mode
  JSON Schemas and native model/tree validation. The document's `version` is `1.10.0`, separate
  from core package version `2.103.1`.
- **Serialization-mode schema is weaker for this acceptance use:** it accepts an invented
  text-item label that validation-mode schema and native Pydantic reject. Archive the exact
  native validation schema for accepting this export shape; do not treat serialization schema
  alone as equivalent validation or hand-edit the upstream schema to conceal the distinction.
- Both schema modes accept dangling/wrong-parent references in these cases. Native validation
  rejects them, but raises `IndexError`, not a Pydantic `ValidationError`. Shape validation alone
  cannot establish reference integrity, and a boundary that handles only `ValidationError`
  would miss this specific malformed-reference outcome. Qualify the adapter's handling against
  the pinned native behavior rather than broadly relabel every exception as invalid input.
- Mutating the fixture's box to `l=-50`, `r=800` then invoking `validate_document()` changes it
  to page bounds `l=0`, `r=612` and emits warnings. Validation is a normalizing operation here.
  Finalize the resulting representation before identity/publication; validation on a read must
  not silently change the stored meaning.
- A document with one picture referring to a nonexistent local PNG reloads structurally with
  that picture still present by default. Trusted `allow_local_images=True` reload fails with
  `ValueError` naming the missing file. Structure and payload availability are distinct;
  absent raster bytes must not become absence of the picture.
- Actual SQLAlchemy Core `JSONB` insert/select and native reload preserve the tested document
  structure, array order/pointers, region values and lexical numeric strings. A missing property,
  explicit JSON null and SQL NULL remain distinguishable. JSONB retention is semantic JSON
  retention, not original source-byte/serialization retention.

## Scratch database custody and retained failure

Each successful run creates a uniquely named `corpus_pdf_i06_*` database on `18/corpus:5434`,
stamps an ownership comment, inserts only probe data, disposes connections and removes that
same database after checking its marker. No such scratch database remained after the final run.

The initial run's teardown used PostgreSQL `obj_description` for a shared database object;
its marker check refused deletion. The correct lookup is `shobj_description`. The original
failed receipt remains `raw/schema-run-initial-failed.log`; the exact owned database was then
verified and removed, with receipt `raw/schema-initial-cleanup.json`. The corrected source uses
`shobj_description` and all later runs completed and removed their databases. No earlier failed
invocation is relabeled passed.

## Decisions supplied and limits

PDF-02/03 should bind the native validation schema and native reference-validation behavior,
normalize before identity, keep the native schema version separate, and preserve qualified
original/native/derived identities. PDF-08 must expose unavailable image payload distinctly.
The selected Core/JSONB path is compatible with these native payloads without an ORM or a
competing document schema.

No complete source-fidelity guarantee, rich-cell math enrichment, image renderer, all-format
native schema coverage, cross-product custody enforcement or application admission result is
established. Full-book and actual protected-write/read acceptance remain in PDF-03/09/11.
