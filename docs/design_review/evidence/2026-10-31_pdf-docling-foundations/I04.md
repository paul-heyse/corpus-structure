# I04 — Actual heading levels and derived section containers

**Tested, bounded structural mechanism · 2026-10-31.** Uses the coordinator's actual Heron
conversion of physical pages 20–45, core 2.103.1. No additional inference, chunking, production
model/schema change or source-document modification was performed by this probe.

## Observed native output

The stable input is `raw/heron-20-45.document.json`, copied unchanged to
`raw/hierarchy-input.document.json` before derivation. Its hash and exact physical page coverage
are in `raw/hierarchy-results.json`. The converted document has **83 section headers**, all
parented directly to `#/body`, and **zero native SECTION groups**. Header levels range below
its two top-level headers, `1.1: Sets` and `1.2: Functions`; heading-level recovery therefore
supplies information without itself producing section containment.

## Derivation and independent preservation checks

Command, **passed**:

```sh
uv run --project docs/design_review/evidence/2026-10-31_pdf-docling-foundations python docs/design_review/evidence/2026-10-31_pdf-docling-foundations/hierarchy_probe.py
```

`hierarchy_probe.py` loads a separate native document, keeps all original collection indices and
item `self_ref` values, and walks the original body's ordered child references. Each header
opens a `GroupLabel.SECTION` container through public `add_group(parent=...)`; a level stack
selects its parent. Existing items are reparented through public model `parent`/`children`
fields. No source text, native collection item identity, pre-existing group children, label,
provenance or page geometry is rewritten. New grouping is explicitly derived/inferred, not
additional author text or a claim of authoritative source section boundaries.

The result has **83 derived section groups**. The two level-one groups are body children;
subsection groups are lower-level children. All **1,093 original collection nodes** retain
identity, with old→derived qualified pointer mappings and per-container heading basis in the
result record. Exact all-layer content traversal order is checked before/after, original
node fields other than intended `parent` changes are compared, page data are equal, and native
validation plus serialized reload succeeds. The original input file's bytes are unchanged.
Output: `raw/hierarchy-derived.document.json`; command receipt: `raw/hierarchy-run.log`.

One revealing initial probe failure is retained in `raw/hierarchy-run-initial-failed.log`:
using default `iterate_items()` to index all body children missed a hidden/content-layer item.
The corrected probe indexes native collections, and its preservation traversal explicitly
includes all content layers. Consumers must choose layers intentionally rather than assume a
default body iterator enumerates every native node.

## Selection decisions supplied

- Direct content selects a section's child content and pre-existing native substructures,
  excluding newly derived child sections. Descendant content traverses those child sections in
  order. Each method must declare which it consumes.
- Extraction chooses non-overlapping section units. Ancestor context is referenced as context,
  not an extra extraction pass over the same descendants.
- Content-layer filtering remains explicit: grouping does not turn furniture/background into
  source narrative merely because it has a tree parent.
- No size/token split or chunk product is introduced. These containers organize existing intact
  source content; physical page breaks do not force new sections.

## Limits and dependent work

This proves a native-model construction/preservation route for the given converted document,
not source-fidelity of all inferred heading labels/levels. The native header list includes
`Proof` and `Answer` labels and repeated labels; faithful domain statement versus organizational
section interpretation still needs attributed recognition rules and source inspection. Do not
use this structural pass alone to infer variable scope or proof relationships.

Page-range inference is not whole-book hierarchy equivalence. PDF-05 must qualify section
organization and layer/selection policies against its source requirements; PDF-07 must retain
forward declaration applicability. No hidden `_hierarchize` API or new schema meaning is relied
on. The preliminary native source inventory used a filename later overwritten by a one-page
comparison run; no conclusion relies on that transient file. All final claims above use the
uniquely named, preserved 26-page input and its recorded hash.
