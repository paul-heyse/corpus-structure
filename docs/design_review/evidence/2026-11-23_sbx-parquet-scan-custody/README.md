# SBX Parquet scan custody

**Tested · 2026-11-23.** PyArrow 26.0.0 and DuckDB 2.0.0 on x86-64 Linux. The
synthetic probe asks whether a lazy scan reads the same bytes the verifier acquired
when the Parquet path is atomically replaced before the first result.

Run `uv run --locked --no-sync python docs/design_review/evidence/2026-11-23_sbx-parquet-scan-custody/probe.py`.
The fixture writes two small Parquet files in a temporary directory. It hashes and
retains an open handle to the original, constructs a DuckDB relation with a filter
and projected columns, and then replaces the pathname. The replacement changes both
the selected label and a witness column excluded from the projection.

The command passed the stated fixture and held-reader assertions. The lazy DuckDB
relation returned the replacement label. The Arrow `ParquetFile` opened on the held
`NativeFile` returned the original label and original witness. The replacement had
a different full-file digest. Holding an open file on this filesystem kept the
original across pathname replacement. In-place mutation, other filesystems and
replacement after partial consumption are outside the probe. This result does not
establish production archive behavior or a performance difference.
