A graph field assertion means a particular reading has a declared field/state. It does not assert
that the underlying statistical proposition is scientifically true. Author polarity, modality,
condition and scope stay reading fields; do not transfer them into the core qualification of the
assertion that the field exists. Exact source occurrence identity, coordinate precision, literal

and applicability, not a release or quality certificate. Reference accepted standing is evaluator

at target strength; actual implementations must preserve them.

## Existing boundaries and selected composition

Current relevant code remains candidate-only. M1Candidates emits private records;
record_interpretation is pure; record_projection advertises accepted=False; PolicyDecision lacks
the proposed whole-record admission result. These are unfinished M1 obligations, not implemented
corrections or new defects in closed AC behavior.

The proposed sequence is sealed annotations → owned product/context consumption → candidate
assembly/reconciliation and bounded private interpretation → private field-assertion preparation →
ordinary and whole-record policy evaluation → explicit public admission overlay → common atomic
publication, finite inference and terminal settlement. Model execution, fitting and numerical
search remain outside publication locks.

Every record-produced fact must be capped by its whole-record decision. Ordinary rule validity
cannot promote a provisional record or accept successful individual fields around a failed
qualifier. Native publication independently checks the allowed overlay, applicable instance and
complete expected membership, including omissions and extra members.

Current closure.sql requires AgentStoredBatch for its existing native observation support branch;
attribute guards authenticate each attribute's own assertion and evidence. New support must add
origin task → sealed record → field/set → anchor custody directly. Do not fabricate Agent
observations or weaken attribute guards. Current RecordAssertionRow has only record/interpretation/
fact IDs; the target appropriately requires finite occurrence/field/evidence-set support linkage.

The composition reuses tasks, immutable evaluator results, Arrow publication and common reads.
It avoids another store, reference lifecycle, policy service, per-field entities and general graph
regex engine. More records/bindings necessarily create more retained field/evidence rows. The
bounded numerical route and private preparation are credible qualitatively; actual CPU/RSS and
ordinary workload fit remain unestablished. Safe refusal alone is insufficient.

## Revealing changes and failures

- A downstream GLiNER schema change preserves annotations only when their actual source/profile/
  recipe and relevant implementation dependencies remain unchanged. Retain the full run manifest
  as provenance, while candidate extraction changes.
- Compatible formula bindings use formula plus first primary symbol-use anchors. Repeated uses
  of one binding count once; conflicting interpretations remain alternatives. Related declaration
  text supplies evidence, never invented primary occurrence identity.
- Shared predicates and shared numeric strings do not merge distinct clauses: primary subject/
  predicate/object or referent/property/value memberships distinguish compatible readings.
- Refitting changes immutable run instances and affected results while preserving exact release/
  reference meaning. Final grading verifies the actual frozen instance, not only algorithm name.
- A fitting implementation substitution preserves feature order, positive-class meaning and
  parameter/application contracts; changed semantics require a changed algorithm contract.
- A changed note/countercandidate invalidates affected computation, including negative retrieval
  dependencies. An interrupted new publication cannot replace part of the prior accepted cut.

## Findings and preservation requirements

### F01 — Annotation reuse requires operation-scoped determinants

Related diagnostic: [DA-054](../audit/execution-fit.md#da-054).

Orchestration hashes the whole run dependency digest, including downstream configurations,
GLiNER libraries, extraction policy and guideline. Python twin selection separately requires the
same digest, and native ops.valid_reuse requires exact run dependencies. A separate annotation
method improves custody but alone cannot establish schema-independent reuse.

The corrected Proposed target narrows only this declared annotation operation's determinant
projection. Complete source, release, profile, recipe, operation/configuration and relevant spaCy/
model dependencies must govern all three checks consistently. Other methods keep the existing
exact-binding default. Actual native reuse/invalidation controls remain required.

### F02 — Decoder anchors do not distinguish every compatible reading

The initial formula-only occurrence anchor conflicted with several compatible symbol readings
and the evaluator's one-accepted-interpretation-per-occurrence rule. A shared predicate or shared
numeric value exposes the same cause for assertions and measurements.

The revised statistics-reading-occurrence-2 policy uses complete primary role memberships;
formula-symbol-first-use-1 distinguishes bindings without changing generic anchor-membership
identity. This is a coherent Proposed correction. Required unavailable primary locations stay
unresolved. Related evidence and synthetic text cannot manufacture identity; old archived policies
retain their meanings.

Independent controls must cover two formula symbols, repeated one-symbol use, related declaration,
shared-predicate conjunction and shared-value clause.

### Admission and calibration preservation

Exact enumeration is not proof of reading correctness. Binary supervised feature scores are
compatibility potentials when used by the interpreter, not automatically LLRs or structured-
likelihood estimates. Production coupling requires the fixed-universe benefit comparison.
Calibrate the whole-record event after constraints/coupling.

Calibration uses a predeclared complete eligible scored-event frame, including low-score and
unaccepted candidates. Existing accepted-only alignment drops other predictions and cannot alone
supply that frame. Native custody binds exact score membership; independent evaluator readings
supply correctness labels. No-output units remain in coverage/capture accounting and receive no
invented event probabilities. Native authorization does not establish good calibration or accuracy.

The M1 coordinator owns implementation disposition and closure evidence for F01/DA-054 and F02.

## Library fit and alternatives

Pinned scikit-learn1.9.1 LogisticRegression supplies regularized binary fitting, sample weights and
public finite coefficient/intercept parameters. This replaces a bespoke optimization objective
for the selected binary responsibility. Production applies the finite released contract rather
than a pickled executable. Retain positive class, feature order/scaling, weighting, regularization,
solver and convergence meaning; weight scaling affects effective regularization.

A separately fitted final-event sigmoid map uses disjoint held-out calibration data. Documented
FrozenEstimator/CalibratedClassifierCV illustrate that responsibility; the finite exported map
need not introduce their estimator lifecycle into production. Optimizer success grants no quality
claim. Consider a custom SciPy objective only if actual structured likelihood becomes necessary.

## Authority impact and verification limits

current native SourceView rule permits conservative recomputation and requires complete recorded
binding. The target keeps full run provenance and uses the declared annotation operation's complete
dependency scope consistently. This real bounded refinement is already authorized by accepted

and D6 carry it. It is no blanket dependency waiver and requires no additional approval flow.
Other changes extend authorized M1 responsibilities without weakening graph fences, historical
compatibility, proof semantics, quality targets or operational-default policy.

**Reviewer checks: not_run.** Static source/document inspection and Context7 lookup only; no
tests, database/providers, actual extraction/fitting/calibration, benchmarks, test-all or hygiene.

Implementation must establish annotation reuse and dependency refusals; exact record support with
substitution/omission/extra/wrong-origin negatives; rule-success admission bypass refusal; F02
identity cases; wrong instance/partition/digest/applicability/final-instance refusals; provisional/
limited/failed/interrupted outcomes; and actual pinned query/CLI/MCP/export journeys. Independent
source readings and tiny numerical expectations remain necessary; reusing a production validator
for a consumer does not independently validate that validator.

not implemented or tested closure. The enclosing M1 architecture remains unqualified for accepted
family quality, calibration, CPU/resource behavior, complete journeys and release adoption. AC
acceptance remains AC evidence.
