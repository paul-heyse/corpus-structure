## 3–4. Composition, resource and request contracts

The inspected foundation carries explicit verified preparation and canonical regional bodies, but
orchestrate/characterization still comprehends regions sequentially; orchestrate/semantic still
waits synchronously at method execution. Characterization resources still use ContextVar plus
nonblocking exclusive-borrower refusal. These cannot become overlap merely by wrapping complete
demands in threads: readers, builders, main-thread deadlines and effect ownership would cross
together. Select incremental preparation/submission/reduction at the parent boundary instead.

Keep actual stage-run boundaries. Register dependent tasks only once exact predecessor pins and
result-affecting inference identity exist. Advance independent regional/stage work by completion,
not input order. Submit/wait(FIRST_COMPLETED) provides completion coordination, while explicit
admission provides byte/item capacity and existing native lifecycle provides settlement. Use
ordinary bounded invocation state, not a second durable queue or general cross-run DAG.

The shared method seam is an incremental parent-owned `method.plan` generator: it yields tuples
of lazy PreparedWork and receives private replies. PreparedWork.try_submit is a parent callback
returning an admitted WorkHandleProtocol with future/collect/cancel/retire operations. The
standalone synchronous driver consumes this same plan; no second algorithm remains. A physical
slot releases when its future is terminal/drained and collected, independently of whole-method
settlement. Reply credit remains charged through reduction; output draft credit transfers to the
parent claim/region until native settlement or retirement. Holding every intermediate physical
slot until method settlement would deadlock D1's dependent question stages and is not selected.
The parent drains completed replies/reductions before waiting for capacity needed by new work.

The early CPU operating slice admits two natural regions, two CPU workers in one pool, two stage
runs and four logical claims; it retains256MiB encoded owned-state,64MiB CPU input and8MiB CPU
reply bounds. One foreground DB operation progresses alongside independently owned renewal and
bounded dedicated supervisors. Each provider/profile has one resident/exchange and at most one
pending native batch. Ownership/byte reservation precedes hydration,
serialization and enqueueing; replies retain reservations until reduction/consumption. A full
capacity is a wait, while an indivisible input that cannot fit explicitly refuses without
truncating its semantic scope. No claim that these are optimal counts or interpreter RSS limits
follows. PM2 children use explicit four intra-op/native threads and one inter-op thread, applied
inside child startup before native work; GLiNER retains its selected profile's supported controls.

CPU request cancellation uses fixed shared slots plus generations and cooperative checkpoints,
with existing parser deadlines bounding an uninterruptible parser section. Cancel one request
without poisoning the useful sibling's pool. Retain its physical slot/reservation until the old
future is terminal or successfully cancelled before execution; do not recycle a logical slot into
an unbounded executor queue while old computation still occupies workers. A stale generation can
never return a usable completion. Pool termination belongs to invocation cancellation or broken
pool recovery, not an ordinary single-member cancellation. Future.cancel alone does not stop an
executing kernel. These conditions use the selected [Python3.14 futures contract](https://docs.python.org/3.14/library/concurrent.futures.html),
with explicit [spawn context](https://docs.python.org/3.14/library/multiprocessing.html#contexts-and-start-methods).

Provider lanes hold their actual existing PM2/GLiNER child lifecycle. Compatibility includes
profile/runtime/artifacts/device and inference options. Replacement drains or retires the old
resident before startup; full queues backpressure the coordinator. Check a batch's usefulness over
all current logical borrowers: one stale member loses publication rights without raising its
cancellation through the shared exchange while useful siblings remain. Drop uncommitted cancelled
members before forming the actual envelope; after dispatch never relabel ordinals or invent a
replacement population. Stop a physical exchange when no borrower remains or the invocation stops.
All closers run, and existing native retry/uncertain-completion policy remains the only retry owner.

Detached spaCy annotation runs in owned compute placement and returns immutable positioned evidence;
no live Doc, mutable pipeline, reader or region builder becomes a cross-thread/process shared
resource. Preserve native Language.pipe prepared-Doc batching, exact layout/protected-atom checks
and complete/missing annotation statuses. HanLP delivers bulk sentence admission using actual native
subword/padded lengths. I1 chooses supported prepared-sample reuse or retains native inference
preparation explicitly. D1 keeps native system_one_batch length packing, exact prior answers and
candidate dependencies. Maverick/DiPO overlap independent lanes; multi-document batching is
conditional on a supported native contract.
