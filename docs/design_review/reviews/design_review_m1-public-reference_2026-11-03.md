publication, read and evaluator authorities. Released family roles govern the finite public

## 2. Responsibilities, dependencies and semantic ownership

The dependency direction is:

effective released definitions → finite projection and archived contracts → authenticated sealed
reports → existing protected publisher → immutable completed result → common reader →
presentation/export/evaluation.

Independent references enter through source-only population/frame preparation and protected
evaluator operations. They do not enter extraction. Fitting receives a restricted feature-fit
capability, with held-out partitions excluded by the access owner.

| Component | Owned responsibility and decisions | Consumer contract and reason for change |
| --- | --- | --- |
| Effective observations/reference declarations | Families, roles, states, requiredness, meaning-changing fields, value/address shapes and reference report structure | A semantic role or supported family changes here; generic consumers consume the released definitions |
| `semantic/record_projection.py` | Finite lossless lowering, reconstruction and invocation-owned row indexing | Projection ABI or representation changes; family instances reuse existing relations |
| Private source custody and `record_publication.sql` | Actual selected-source authentication, structural validity, exact sealed-cut correspondence and public candidate admission | Custody or publication invariants change at their trust boundary |
| `semantic/record_queries.py` | Immutable completed-result binding, root selection, bounded bulk hydration and detached row ownership | Read-selection or physical access changes without changing family meaning |

The finite row model is a representation authority. Family meaning remains with the released
definitions. Native validation is independent enforcement at a trust boundary; it must preserve

## 4. Composition and execution

The inspected design separates private preparation/model work from the publication transaction.
The final native boundary authenticates the source and reconciles exactly what becomes visible.
Reader mechanisms then consume immutable products rather than rerunning extraction or compiling
today's declarations.

| Stage/question | Projection and semantic universe | Method/model and settings | Work, reuse and limits | Output/evidence linkage |
| --- | --- | --- | --- | --- |
| What did the sealed source reports contain? | Selected cut reports, exact record and field/evidence membership | Released family-driven finite lowering; exact representation | One bulk private-report read and common lowering; no per-family store | Public report/record/field/anchor/alternative relations |
| Is this the authorized public candidate projection? | Complete staged projection against actual sealed reports | Shared structure/custody checks and symmetric multiset difference; exact | Existing publication transaction; source model work stays outside it | Existing receipt and completed-result boundary; accepted links remain unavailable |
| Which records answer this inspection request? | Completed result and source report scope; family/standing/identity/keyset restrict record roots | Narrow relational root selection before payload hydration | Fixed finite relation queries; bounded detached data; source reports retain their distinct scope | Selected records preserve complete own field/evidence closure |
| How is a record reconstructed? | Selected record/interpretation and its positioned children | One `PreparedRecordProjection`, grouped by record, role, set and alternative | Convert/group once per invocation; reuse in presentation and evaluator loop | Same immutable record content, without repeated population scans |
| What do independent references say? | Frozen source-only sample, primary/related frames and credible origins | Independent authored A/B/C; strict source-occurrence comparison | Full eligible sample retained, including missing output; common index reused | Immutable bytes/frames and per-unit contributions |
| May fitting read these labels? | Adjudicated feature-fit partition only | Actual-principal and partition checks; exact protected access | Existing reference authority; one additional restricted login, no second store | Explicit feature-fit reference capability |
| What is exported? | Bounded full completed projection and captured semantic packet | Existing JSONL/Parquet and atomic export composition; exact lexical transport | Detached reads; bounded Arrow row chunks; full-population export remains explicit | Relation schemas, checksums, source/report map and release/projection manifest |

Root selection reduces expensive hydration without deleting evidence required by a selected record.
It is safe here because listing/inspection does not compute a global graph metric. Matching counts
still inspect the relevant narrow root population; preserving exact counts is legitimate work.
Evaluator and full export callers intentionally retain the whole selected population.

Report rows and coverage can remain broader than one returned record because they explain source
scope and missing output. Their row/byte cost is included in the bounded read/response contract.
A large diagnostic population may require a narrower source scope; there is no whole-corpus
capacity claim.

The eighteen relations are shared across families. Adding a role or family does not automatically
create eighteen new sets of tables or operations. Their normalization purchases field-addressable
joins, explicit optional presence and shared export/evaluation semantics. It does add coordinated
mapping and migration obligations; future new scalar/address kinds require an explicit ABI change.

The initial repeated reconstruction and late-selection defects were avoidable amplification.
The re-inspected index and root-selection changes remove those mechanisms. No speed, latency or
RSS improvement is claimed without measurement.

## 7. Findings and applicability

The following stable IDs preserve the findings discovered during this engagement. The dated
source correction is separate from native qualification or plan closure. Current execution
disposition belongs to the M1 coordinator.

<a id="F01"></a>

### F01 — Native grade counts did not bind the reported population

**Original diagnosis: source-established.** The initial
`validate_source_record_reference_evaluation` checked the number of contributions, top-level
binding and the correctness of the supplied frozen snapshot. It did not bind each
`result.units[].unit` or origin/version metadata to that snapshot. A duplicate or foreign
contribution could replace an eligible empty unit without changing the array length.

This violated FP-04/FP-05, DP-02/03/08 and A2/G3/G6: the independently frozen population did not
fully govern its admitted derived report.

**Re-inspected correction: Implemented source, 2026-11-03.**
`semantic/sql/record_references.sql` now requires unique reported unit identities and exact
correspondence through snapshot, reference unit, eligible-unit metadata and frozen frame.
Origin, release, guideline and both policy versions are checked independently of array order.
Both protected entry and shared insert guard consume the same validator.

Preserve this narrow boundary. Native validation need not reimplement the scorer's arithmetic.
Closure evidence for actual enforcement includes same-length duplicate/foreign substitutions,
wrong origin/version, an eligible empty unit and a valid reordered report. Those native controls
remain qualification work.

<a id="F02"></a>

### F02 — Reconstruction repeatedly processed unrelated detached rows

**Original diagnosis: source-established.** Each nested `selected()` call in reconstruction
converted and filtered the complete relation, repeated for every role, set, alternative and record.
The evaluator also rebuilt population/report lookup work per unit. Larger unrelated populations
therefore amplified work for unchanged record content.

This violated FP-07, DP-10/16 and A4. A returned-data bound did not remove the repeated work.

**Re-inspected correction: Implemented source, 2026-11-03.**
`PreparedRecordProjection` and `index_record_projection` convert/group each row once per invocation.
Reconstruction uses indexed record/role/set/alternative groups. `CompletedRecordProjection`
owns the invocation index; presentation and the evaluator reuse it. Task-to-view and population
maps are prepared outside the evaluator unit loop.

The correction preserves the existing reconstruction contract and adds no durable cache, service
or invalidation authority. Independent round-trip expectations must continue to protect optional
presence, ordering, alternatives and lexical values. No measured speed or memory claim follows.

<a id="F03"></a>

### F03 — Serving applied narrow selectors after full record hydration

**Original diagnosis: source-established.** The initial serving adapter read and indexed the
whole bounded run/source projection before applying family, standing, record identity and page
position. Inspecting one record or successive small pages repeatedly moved unrelated payloads.

This violated FP-07, DP-08/10/20 and A4. Presentation bounds described returned output rather than
the work needed to produce it.

**Re-inspected correction: Implemented source, 2026-11-03.**
`RecordReadSelection` now applies released family/standing, identity and keyset selection to the
narrow root query before hydrating finite record relations. Exact matching count remains separate.
Source-scoped reports retain their own declared scope; evaluator/export full-population reads remain
available. Cursor release/realization/revision/query identity validates before its position is used
to select roots.

The correction must preserve empty reports and the full evidence closure of every selected record.
Native reader controls should independently check selected-root membership, paging, unknown selectors,
wrong/stale cursor identity and unchanged report/coverage semantics.

<a id="F04"></a>

### F04 — Table-cell anchors produced incompatible native item handles

**Original diagnosis: source-established.** The first presentation adapter emitted
`view="item"` with the complete `#/tables/N/data/table_cells/M` pointer. The existing native
reader resolves table cells through their parent table pointer and `cell_index`; its item lookup
does not make that full cell address an indexed native item.

This defeated the required table evidence journey under FP-02/FP-04, DP-02/08 and G2/CI-G2.

**Re-inspected correction: Implemented source, 2026-11-03.**
The source owner exposes `source_record_address`. Presentation retains the complete authoritative
anchor while issuing `view="cell"`, the parent table pointer and exact cell index. Ordinary item
context uses its existing route. The source handle does not change the anchor's coordinate space
or precision.

Independent handle expectations can establish the adapter contract; actual native cell/header/note
retrieval remains consumer qualification.
