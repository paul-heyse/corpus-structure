## 7. F01 — repeated semantic assurance, scheduled as PCE execution F27

**Initial diagnosis source-inspected2026-11-05; correction independently source-inspected.**
The initial final validator called `local_semantic_grade_evidence` inside every assertion loop,
recanonicalizing the complete evaluation, current reference snapshot and adjudicated units, then
expanding the same origin array repeatedly. Candidate preparation scanned units/cases for each
product. More useful assertions therefore amplified shared assurance and transaction work.
This violated FP-07/A4, with supporting DP-10/16/19/20 and relevant efficient-architecture heuristics.
It did not imply wrong claims or a measured latency/capacity failure.

The correction prepares distinct full project/release/evaluation/digest keys, immutable origins
and case populations once within the native invocation, then uses relational joins. It retains
strict current-cut/run/dependency authorization, current C/partition, graded-origin/source-view,
named unit/pass/frame/case, policy/question/version, full statement/anchors and intrinsic IDs.
LEFT joins plus explicit cardinality checks refuse missing or duplicate matches; valid distinct
witnesses survive and only identical complete assertion rows deduplicate. No persistent cache,
new store or weaker producer seal replaces native authority.

Independent inspection found no further source defect and approved freezing144. Rollback-only
controls retained16 witnesses and refused10 malformed mixed batches with forged IDs recomputed.
The complete native144 semantic-admission file passes21 cases. A test initially expected duplicate
case credit; the existing one-physical-facet assignment correctly withheld it. The corrected test
expects two genuinely supported grade/case witnesses for one claim, preserving non-circularity.
Actual run45 subsequently reuses exact origin130/grade20 and admits16 denotations under144.
The coordinator owns final disposition; these facts remove the demonstrated A4 cause without a
performance claim.

Inherited F09–F26 corrections remain accounted at the coordinator. The reviewer inspected typed

## 8–9. Library fit and alternatives

Selected mechanisms are Sentence Transformers `encode_query`/`encode_document`, native tokenization,
pooling and batching under exact profiles; PostgreSQL full-text and official pgvector exact cosine;
spaCy `Doc`/`Matcher`/`PhraseMatcher`/`DependencyMatcher` over retained columns; Lark Earley with
explicit ambiguity/positions; and the shared NumPy/SciPy log-space executor. Concrete versions,
revisions, prompts, thresholds and source references remain in the plan companions and evidence.
These establish actual selected use, not every advertised capability.

Resident embedding services, ANN/rerankers, richer forests/grammars and Pyro/pgmpy remain conditional.
No useful actual sparse coupled question exceeds the retained-joint route, and no applicable domain
factor policy exists for the retained corpus question. Activating a universal solver or learned
reliability model now would add machinery without establishing a valid scientific model.
