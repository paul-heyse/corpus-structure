## 3–4. Contracts, composition and physical realization

Original sources remain in their own projects. `prepare_structural_sources` shares decoded views
by original run/view and settles its snapshot before encoder work. The automatic method validates
the full source frame, uses owned E5 encoding and bounded PostgreSQL/pgvector nomination, then
reuses one owned GLiNER worker over fixed-list pair batches. Completion reauthenticates inputs;
provider failures retain successful earlier replies and explicit failed/not-run stages. A produced
report does not mean every classification succeeded or that its readings are semantically supported.

Comparisons retain source-qualified lexical values and unknown dimensions. Dossiers retain all
members; exception/revision/conflict display is protected from representative pruning. The native
publisher resolves dossier predecessors from the selected final cut and checks actual semantic
participants, rather than treating shared input inventory as evidence of an emitted relationship.
Source occurrence, product envelope, task result, public claim and publication witness remain
different identities. Complete-record consumers keep their stronger contract.

| Analysis/question | Universe, method and status | Bounds and evidence linkage |
|---|---|---|
| Which passages are candidates for a usage? | Explicit source-backed inventory; E5, lexical/dense channels and retained candidate-list identity; heuristic | Encoder item/input limits and unique/channel budgets; raw vectors/settings retained |
| Is a nominated passage applicable? | Fixed usage–target pairs and six released categories; heuristic model observation | Owned bounded batches; per-target stage/raw replies; independent source judgment required |
| How do these clauses differ? | Explicit pair and ten ordered dimensions; exact over supplied lexical readings | Unknown rather than invented field; original passages cited; no scientific equivalence |
| What belongs in this provisional dossier? | Explicit member set grouped by role/sense/scope/version; deterministic assembly | Membership distinct from representative budget; explicit missing sections and upstream references |
| May a statement be public? | Exact current independent statement/frame/pass and original/selected upstream custody | Native policy inside common PublicationBatch; no public promotion from similarity/member metadata |
| Can a reviewer reconstruct it offline? | Selected inventories/raw bodies/source closure and separately authorized assessment history | JSONL/Parquet/digests, atomic no-replace publication, explicit byte/row limits; F01 applies |

The physical route is credible for this declared small inventory. It avoids holding transactions
through model computation, copying source books into an analysis project, inventing per-product
publishers or materializing all-pairs corpus relations. Capture shares raw/source objects, streams
bounded batches into existing Arrow/Parquet writers and settles readers before final verification
and atomic directory publication. Native history preflight precedes SETOF capture. Those are
structural advantages, not measured speed or capacity claims. Repeated full-source reconstruction
per field or metric is not required by the inspected route.

## 7. F01 — structural review does not close over its declared predecessors

**Initial implemented defect and subsequent correction, source-inspected 2026-11-05.** A supported selection containing only
`StructuralRequest(run_id=…, kind="dossier")` reaches the structural branch of
`capture_review_relations` in `serve/review_bundle.py`. That branch emits the requested dossier,
its own origin report and original sources, but does not follow
`report.dossier.members[*].relation_product_id`. `verify_review_bundle` adds required source IDs
and that product's origin task, but never requires those predecessor product IDs. Thus a full
`selected_source_closure` packet can verify with an unresolved declared upstream link. The
structural-only branch also omits released contracts, which are emitted only by the contribution
selection branch. The search covered the complete capture/verifier, structural types, selected-cut
reader, native dossier predecessor policy and review tests; this is not a claim about unrelated
export formats.

The source quotations alone cannot explain whether the dossier actually derives from the selected
definition/comparison products. This is the detached counterpart of the distinction repaired by
integrated R7: sharing an input source is weaker than participating in the predecessor's semantic
output. A complete combined run selection can accidentally include the missing products; it does
not repair the supported kind-filtered or structural-only case.

Principles: FP-02/04/05, DP-07/21/24, CI-11/13; A2 and gates G2/G3/G5/G6/CI-G2.
Priority: material PCE-09 acceptance defect, not a request for generic lineage infrastructure.

**Proposed correction:** at the existing capture owner, capture bounded known predecessor products
from the same immutable selected cut, including their raw reports and per-release contracts once;
teach the offline verifier the required product closure. Alternatively explicitly refuse a full
packet when the selected dependency closure is absent. Do not scan historical origins, guess
dependencies from arbitrary diagnostics, treat every opaque `inputs.dependencies` string as a
structural product, or silently widen to another cut. A legitimate dossier with no such members
does not need artificial predecessors. Unresolvable required members must fail full capture while
a deliberately narrower inventory remains explicitly narrow.

Required acceptance evidence: a dossier-only full export either contains and resolves every typed selected-cut
predecessor/raw report/contract or refuses before publication; omission of one required predecessor
fails offline verification. A real unrelated predecessor must not satisfy the link. Existing
combined packets and public-native selected predecessor controls remain applicable only to their
recorded scope. The coordinator owns scheduling and closure; this review owns the dated diagnosis.

**Inspected correction, Implemented 2026-11-05:** the coordinator chose explicit bounded refusal,
not automatic dependency discovery. Structural capture now emits `_contract_row(session.prepared)`
once per producer release and once per authenticated original source release. The offline verifier
records each structural selection's run/cut and release, adds every
`report.inputs.sources[*].release_id` to its required contract set and requires those contracts.
It derives required predecessors only from typed
`dossier.members[*].relation_product_id`. Required and present products are compared under the
same selected `(run_id, cut_id)`; a product from another selected scope cannot satisfy that link.
Every captured structural product still requires its own raw origin report and source closure.
Missing dependencies produce `dossier predecessor closure missing; include its selected-cut
structural products` before final directory publication. Inventory mode keeps its narrower meaning.
This removes the demonstrated architectural cause without reading arbitrary dependency strings or
widening to historical/foreign cuts. Missing-contract and missing-predecessor regression controls
were inspected. The original-release requirement is consumer-driven: `load_source_view` opens the
original source release and supplies its archived projection context to `published_record_reader`
and integrated-context interpretation even with `analysis=False`. Captured quotations support a
text inspection; interpreting their native items, coordinate/product shapes and original operation
under the full declared closure also needs that original release's definitions/registry. The required
set is derived from references, not a fixed contract count. This does not require executing an
archived runtime or establish original-document completeness. Final005 evidence below contains all
three demanded releases. The coordinator retains the separate structural-only full/filter-refusal
receipts and package disposition; this review does not infer those outcomes from a combined packet.

## 8–9. Library fit and alternatives

The current source-backed retrieval composes existing owned encoding with PostgreSQL/pgvector
rather than creating a second vector service. Context7 lookup of `/pgvector/pgvector` on
2026-11-05 confirms the [primary pgvector documentation](https://github.com/pgvector/pgvector#querying)
distinguishes exact nearest-neighbor search from approximate HNSW/IVFFlat indexes and their recall
tradeoff. Exact scoped search is a suitable current mechanism; ANN adds changed candidate/quality
obligations and is not justified solely because the product uses vectors. This is current capability
orientation, not a claim of a new locked-version provider qualification or measured scale benefit.

For F02, Context7 lookup of the pinned SQLAlchemy2.1.6 primary source on2026-11-05 confirms
[`Values.cte()`](https://github.com/sqlalchemy/sqlalchemy/blob/rel_2_1_6/doc/build/core/selectable.rst)
provides a named relation with explicit columns. Set-oriented joining uses that existing capability
instead of expanding a deeply nested composite membership predicate. The corrected route retains
bounded inputs and the original identity predicates; it does not add another cache or query engine.

GLiNER classification remains an existing owned provider boundary; this review does not propose
new library adoption or infer semantic adequacy from successful API execution. Actual raw outputs
and independent source assessment are more decisive than additional API inventory here. Arrow
schemas, logical row digests and Parquet serialization reuse established mechanisms; the bespoke
part is the necessary declared closure, not a custom columnar format.

For cross-source structure, preserving original pins in finite RUN reports is preferable to copying
documents into a merged source project or introducing a second semantic store/scheduler: the latter
options duplicate custody, retry, publication and operator responsibilities. For F01, bounded
same-cut predecessor capture or explicit incomplete refusal is sufficient; the coordinator selected
the latter. A generic dependency
registry, universal graph engine or new assurance framework is unnecessary.
