below as recommendations for subsequent planning.** No recommendation is implemented or authorized
as a rule change by this review. Implementation, native qualification and benefit measurement remain
separate. A proposed target is not a fully qualified system.

Functional intent is DESIGN §1.1 and its current owners: evidence-backed, typed document knowledge

**Workload premise:** local operator deployment with concurrent task renewal, publication and
readers; intact documents and source cuts; growing candidate/evidence populations and skewed
relation degree. Bounded answers must avoid repeated hydration of unrelated state. This is a
qualitative physical-route assessment, with no quantified latency, RSS or capacity claim.

## 2–4. Integrated responsibility model and target composition

The target has one released meaning layer, specialized prepared execution, controlled effect
lifetimes and demand-shaped readers. It extends the model and owners already present:

| Responsibility | Authoritative inputs and owned decisions | Consumers and effects |
|---|---|---|
| Released domain contracts | Effective enum subsets, semantic/display roles, admissible establishment, reference and representative policy, rule projection, producer and policy-context bindings | Existing compiled products, Pydantic adapters, native lowering and ordinary domain functions; no parallel registry |
| Prepared execution | Pinned cut/release, indexed candidate/role lookups, scientific evidence and complete rule universe | Consolidation/private preparation; inference initially stays in atomic publication; retain required checks |
| Effect ownership | Just-in-time claims, synchronized renewal/terminal retirement, operation admission and method-owned resource closure | Existing native protected task/publication operations; no stale attempt can become current |
| Pinned answers | Released selection, assessment and establishment semantics; query universe and coverage requirement | Shared batched fact hydration, paged evidence, explicit source retrieval, bounded walks, CLI/MCP/export |
| Evaluator provenance | Frozen split policy, actual seed/population and assignment reason; distinct M1 origin/sample contracts | Immutable evaluator-owned split decisions; historical provenance-unavailable rows remain honest |

Detailed corrective contracts, alternatives, precise source and library mechanisms:

- [Semantic contracts](audit-closure-target/semantic-contracts.md).
- [Execution and effect boundaries](audit-closure-target/runtime-boundaries.md).
- [Consumer and evaluation contracts](audit-closure-target/consumer-contracts.md).

Semantic declarations choose meaning, not a table, task, transaction or wrapper for each category.
A reusable mathematical concept can remain in the core; domain-specific interpretation follows
released roles. Output schemas alone do not establish the model: actual operations must consume
these definitions. Existing special-purpose code is retained where it owns a real semantic gap.

The fact/fidelity contract preserves extracted versus derived/heuristic establishment, provisional
identity versus resolved identity, selection versus assessment, original report values versus
representative display, and coverage unknown versus established absence. Relation witnesses retain
fact/occurrence IDs and same-snapshot evidence. Neither a returned page nor a resource budget proves
source completeness or scientific truth. Each projection retains its declared universe, relations,
direction, multiplicity, omissions, decision policy and completeness relative to that model.

## 5. Changes and scenarios

An ordinary enum/role extension should change its released semantic owner, then flow through
existing generated adapters/native constraints/query products; a genuinely new operation still
needs its own specialized implementation. A new producer binds a capability rather than causing
agent-name branches in policy, queue and serving. A provider revision changes the right invocation
and reuse identity without turning its display alias into verified model evidence.

Growing candidate cuts should reuse indexes instead of rebuilding premise collections for each
candidate. A large extraction/normalization group claims only work it owns now; its lifetime covers
preparation through terminal settlement, with completed tasks retired from renewal safely.
An evidence request selects only requested support/source identities before hydration. A depth-four
walk question remains a walk question with explicit cycle/multiplicity/depth semantics, bounded
frontiers and truthful exhaustion; a shortest witness is a separately versioned optional question.

Tests required after implementation are specified with each target. Key legitimate counterexamples
include an unsupported policy symbol, derived input at source admission, an ambiguous identity,
parallel edges and cyclic walks, a fact with contradictory assessments, an oversized source report,
a seed override, competing lease reclaim, and native deployment drift. No invented speedup or
runtime capacity estimate is used to choose these directions.

## 8–9. Library selection and alternatives

Targeted library-guide sections and Context7/primary or installed-source findings are preserved in
the supporting recommendations. Existing LinkML/Pydantic/rule-engine, SQLAlchemy/PostgreSQL,
Arrow/DuckDB and Python lifecycle capabilities are starting mechanisms, not automatic prescriptions.
No dependency is added or bumped by this review. A later version in a guide does not establish
availability under the current exact pin.

The chosen design improves current owners rather than adopting a universal mapping/workflow engine,
new graph store or certificate system. Library-owned structural interpretation and relational work
are reused; semantic policy remains domain-owned. LinkML-map, NetworkX and alternate inference
backends require a concrete complete-contract advantage before selection. Streaming controls
buffering, not query expansion; PostgreSQL CYCLE changes the selected walk semantics unless
explicitly governed. Keep current native validators wherever the failure boundary still needs them.

## 12. Architectural judgment and next decision

The fresh principal reviewer independently recommends **Revise**. Its final gate assessment
narrows preliminary local mappings: defined late rejection is not by itself G3 failure; renewal
ownership gaps do not establish corrupt native publication; missing fact standing is fidelity,
not automatically missing evidence closure. Supporting contributions do not claim an enclosing pass.

| Judgment | Current architecture | Proposed correction and its limit |
|---|---|---|
| A1 Localize change | violated | Released role/subset/producer definitions localize ordinary extensions once displaced classifiers are removed |
| A2 Explicit domain meaning | violated | Complete translations, resolution outcomes, standing and representative/attribution policies provide a coherent target |
| A3 Composition | violated | Owned reads, applicable policy contexts and producer bindings preserve existing capabilities without raw effects/literal routing |
| A4 Execution fit | violated | Prepared indexes, demand-shaped readers, bounded frontiers and whole claim lifetimes have credible qualitative routes; measured capacity remains unestablished |

All seven foundations inform this conclusion: FP-01/02 concern responsibility/effect boundaries;
FP-03 composed producers/policies; FP-04 owned meaning; FP-05 admissibility/outcomes/lifecycle;
FP-06 discoverable contracts and structured reasons; FP-07 actual work/lifetimes. Relevant DP IDs
remain attached to the source audit and their target arguments. No positive result offsets a failed
authority/fidelity gate. The target direction is suitable for subsequent planning, not implemented
acceptance or a claim that every unchanged invariant/provider was qualified.

The next owner is implementation-plan creation: confirm rule impacts, select the supported target
and transfer accepted corrections into coordinated existing/new plan scope without changing the
current disposition owners here. Priority is consequence-based (faithfulness, effect/lifetime and
truthfulness before convenience); dependency order starts with released contracts before their
consumer migrations. Detailed work packages and execution scheduling belong to that subsequent plan.
