# Alembic

**Realization assessed:** Alembic 1.20.0, used with SQLAlchemy 2.1.5.

**Researched:** 2026-10-29 by the R2 cluster.
- The [overview](../../../libraries/postgresql/alembic.md) was read end to end.
- Follow-ups: Context7 and the installed source (`ddl/postgresql.py`, `command.py`,
  `autogenerate/compare/tables.py`).
- One offline probe was run under two hash seeds
  ([evidence](../../../design_review/evidence/2026-10-29_library-leverage-postgres-migrations/README.md)).

## Reusable opportunity types

<a id="alembic-metadata-drift-check"></a>

### `alembic/metadata-drift-check`

**APIs.**
- `compare_metadata(MigrationContext.configure(conn, opts={...}), md)` returns diff tuples.
- `produce_migrations` returns a `MigrationScript` operation tree.
- `command.check(cfg)` reuses `env.py` and raises `AutogenerateDiffsDetected(diffs=…)`. It requires
  the database to be at head.

**What 1.20.0 compares.**
- Tables, excluding views.
- Columns, types and nullability.
- Server defaults, when `compare_server_default` is set. On PostgreSQL these are evaluated on the
  live connection. A *volatile* default such as `gen_random_uuid()::text` therefore differs on every
  evaluation and reports a false `modify_default`. Alembic's own source comments on this limitation,
  and the comparative review's probe observed it at head (2026-10-29). A `compare_server_default`
  callable can treat that default as equal.
- Primary keys, foreign keys and unique constraints.
- Indexes: uniqueness and expressions, with a heuristic cleanup of expressions.
- Named CHECKs, by name only, through `alembic.ext.checkconstraint_byname`.
- Comments.

**What it never compares.**
- Index `postgresql_where`, `postgresql_using` and `postgresql_include` options.
- A changed CHECK expression under an unchanged name.
- Functions, triggers, grants, owners, views, sequences outside the MetaData, and the database ACL.
  These are never reflected at all, so they are blind spots rather than false positives.

**Filters.**
- `include_name` filters early.
- `include_object` is needed only for tables, indexes or constraints that exist in the database but
  not in the MetaData, or for MetaData tables that are really views.

**Caller obligation.** A direct `compare_metadata` call must replicate every `env.py` option:
schemas, `include_name`, version table and plugins.

<a id="alembic-structured-diff-to-reviewed-artifact"></a>

### `alembic/structured-diff-to-reviewed-artifact`

**Mechanism.** An offline `MigrationContext.configure(dialect_name=…, opts={"as_sql": True, "output_buffer": buf})`
plus `Operations.invoke(op)` renders an operation tree to SQL text without a connection.

**Limit (probe observed).**
- `CreateTableOp.from_table(t)` renders the same elements as `CreateTable`.
- Its constraint order follows the `Table.constraints` set and varies between processes.
  `PYTHONHASHSEED` does not control it.

**Fit.**
- Good for discovering a change set: `produce_migrations` against the previous head.
- Good for rendering ALTER-style operations.
- Not byte-stable for CREATE TABLE emission. SQLAlchemy `CreateTable().compile()` is the stable
  emitter ([sqlalchemy](../sqlalchemy/README.md#sqlalchemy-ddl-text-emission)).

<a id="alembic-programmatic-migration-lifecycle"></a>

### `alembic/programmatic-migration-lifecycle`

**APIs.**
- `command.upgrade(cfg, target)` on a connection passed through `Config.attributes`.
- `on_version_apply` callbacks give structured receipts per step.
- `command.current(cfg, check_heads=True)` raises `DatabaseNotAtHead`, from 1.17.1.
- `ScriptDirectory.get_heads()` and `iterate_revisions()` enumerate revision pairs.

**Semantics.** On PostgreSQL, running inside the caller's transaction makes an interrupted upgrade
leave no partial state. `autocommit_block` and non-transactional statements break that guarantee.

## Applicability at source `d739b88` (read through `6b2335a`)

<a id="applicability-cbo-008"></a>

### CBO-008 — schema written twice, drift checked by names: **fits with conditions (tables only)**

**Opportunity:** [CBO-008](../../codebase/storage-and-analytics.md#cbo-008).

**The check works as configured.** `command.check(alembic_config(conn))` runs with the existing
`env.py`, which already passes `include_schemas`, `include_name`, `compare_server_default` and the
CHECK-by-name plugin.
- The probe confirms that all 41 tables created in SQL are in the MetaData, so no spurious
  `remove_table` results.
- CHECK names embed digests (59 CHECKs), so a changed expression is detected by name.

**Premise correction.** Functions, triggers and grants do not need `include_object` filters; Alembic
never sees them. The check therefore establishes **table structure only**.

**Blind spots for this schema.**
- The two `data.typed_value` partial-index predicates.
- GIN `USING`.
- Every function, trigger, owner and grant.
- The `data.selected_fact` view.
- The database ACL.

**Question 1 — clean at head? Unsettled.** Answering it needs a live run. Candidates for spurious
diffs: server-default evaluation, and the `to_tsvector('english'::regconfig, …)` expression cleanup.

**Question 2 — emit the next revision.** `produce_migrations` finds the change set. SQLAlchemy
`CreateTable` stays the emitter for CREATE TABLE (deterministic, and it matches frozen 0027). Offline
`Operations` renders ALTERs stably.

**Consistency with ADR-0025.** Past revisions are never regenerated, and downgrade stays refused.

**Lint versus functional check.** A suite check asserting that migrations realize the MetaData is an
SP-10 functional obligation, not a design-alignment lint. The operator should confirm this reading.

<a id="applicability-cbo-004"></a>

### CBO-004 (informs) — migration command route

`upgrade` already runs on the caller's connection, so an interrupted bootstrap leaves no partial
change.
- `on_version_apply` receipts are captured in `Config.attributes["applied"]` and could replace prose
  receipts.
- `command.current(check_heads=True)` gives a native "at head" refusal.

<a id="applicability-cbo-010"></a>

### CBO-010 (informs) — revision pairs

`upgrade(conn, "semantic_00NN")` with data loaded, followed by an upgrade to the next revision,
provides controlled-revision evidence. The template conditions are covered under
[PostgreSQL](../postgresql/README.md#applicability-cbo-010).

## Coverage limits

- No live database runs.
- Comparison of foreign-key options (`ondelete`, deferrable) was not inspected.
