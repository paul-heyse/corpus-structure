# Extraction, classification and normalization

**Discovery, 2026-11-10; benefits Proposed.** The objective is a rich first layer of
source-aligned characterization, including overlapping and competing descriptions, before
conceptual assembly. The judgments below concern that objective, including a substantially
redesigned implementation. They do not adopt dependencies or change plan dispositions.
[The account](briefing.md) owns the shared baseline: source `e283a63`, spaCy3.8.18,
en_core_web_sm3.8.0 and Lark1.3.1. Relevant pending discovery prose was reassessed as notes,
not accepted conclusions. Evidence here is guide, current-code, installed-source and primary
reference inspection on 2026-11-10; no inference or model-quality claim follows.

## Deterministic extraction

The useful native division is sequence patterns, known phrases, dependency configurations
and grammatically composed fields. These can nominate different, overlapping units of the
same sentence. A single winning entity sequence is an optional projection of that richer
inventory. [Sentence interpretation](sentence-structure-and-interpretation.md) develops
predicate, argument and qualifier analysis; [alternatives](ambiguity-and-alternative-interpretations.md)
explains why independently matching spans cannot represent every correlated reading.

| [`Matcher.add()` / `Matcher.__call__()`](https://spacy.io/api/matcher): predicates over `TEXT`, `LOWER`, `NORM`, `LEMMA`, `POS`, `TAG`, `DEP`, `MORPH`, lexical flags and `Token._` extensions. [PreparedAnnotationRules](../../../../python/corpus-structure/src/corpus_structure/methods/annotation_rules.py) and [predicate_frames._prepared](../../../../python/corpus-structure/src/corpus_structure/methods/predicate_frames.py) already prepare token matchers. | **Recommended.** Reusable patterns can characterize modal/negative/conditional markers, comparative forms, abbreviation constructions, reference syntax and technical phrase shapes over one annotation pass. This is broader than recognizing final record fields. | Patterns and output meanings remain authored. Require the annotations each predicate actually uses; a default empty attribute is not inspected absence. Extensions expose application features to matching, but do not calculate those features. |
| [`Matcher` comparison and repetition operators](https://spacy.io/api/matcher): `IN`/`NOT_IN`, numeric comparisons, `IS_SUBSET`/`IS_SUPERSET`/`INTERSECTS`, `OP` values `!`, `?`, `+`, `*`, `{n}`, `{n,m}`, `{n,}`, `{,m}`. Existing rules use membership and optional constructions; morphology is retained by [annotations.annotate](../../../../python/corpus-structure/src/corpus_structure/ingest/annotations.py). | **Recommended.** Morphological-set predicates distinguish combinations such as tense, voice and verb form without enumerating every inflection. Repetition recognizes variable-length constructions. `!` constrains sequence matching; it does not calculate linguistic negation or its scope. | Token boundaries bound expressibility. `greedy="FIRST"` / `"LONGEST"` filters returned matches and can discard useful alternatives; choose it by annotation meaning. `with_alignments=True` relates matched tokens to pattern positions when repetitions make positional bindings ambiguous. |
| [`REGEX`, `FUZZY`, `FUZZY1`…`FUZZY9`, `fuzzy_compare`](https://spacy.io/usage/rule-based-matching#fuzzy-matching). `REGEX`/fuzzy predicates can compose with `IN`/`NOT_IN`. The inspected prepared-rule path accepts native pattern dictionaries; specialized fuzzy policies were not found there. | **Recommended** as additional characterization evidence for spelling/OCR variants, scientific identifiers and lexical cues. Default `FUZZY` allows at least two edits or 30% of pattern length, whichever is greater; explicit limits or a custom comparator can be more appropriate for short terms. | These compare token attributes, not arbitrary document substrings or meanings. Preserve original spelling, match mechanism and candidate identity. An approximate match must not silently become a canonical concept or erase exact-match evidence. Cross-token regex spans require separate source matching and explicit alignment. |
| [`PhraseMatcher(vocab, attr=...)`](https://spacy.io/api/phrasematcher), `add()` and `as_spans=True`. [annotation_rules.py](../../../../python/corpus-structure/src/corpus_structure/methods/annotation_rules.py), [predicate_frames.py](../../../../python/corpus-structure/src/corpus_structure/methods/predicate_frames.py) and [math/scope.py](../../../../python/corpus-structure/src/corpus_structure/methods/math/scope.py) already use `LOWER` phrase matching. | **Recommended.** Shared terminology, idiom, discourse-marker and alias inventories can characterize occurrences once and expose their labels to several consumers. It fits large known-phrase collections more directly than elaborate per-token conditions. | Author dictionaries and their interpretation separately. `nlp.make_doc()` suffices for lexical patterns; matching `LEMMA` or `POS` requires those annotations on pattern documents too. A dictionary labels known forms and cannot establish exhaustive coverage of unseen constructions. |
| [`DependencyMatcher`](https://spacy.io/api/dependencymatcher) combines node-attribute patterns with dependency and ordering relations. [predicate_frames.py](../../../../python/corpus-structure/src/corpus_structure/methods/predicate_frames.py) and [annotation_rules.py](../../../../python/corpus-structure/src/corpus_structure/methods/annotation_rules.py) already use it. | **Recommended.** Structural rules can characterize predicate participants, passive agents, reporting clauses and qualifier attachments despite intervening words. Matched token indices preserve roles better than flattening a whole construction into an undifferentiated span. | Depends on the selected dependency analysis and its label scheme. Dependency matching supplies syntactic configurations, not semantic roles, truth, unique scope or all possible parses. Full operators and interpretation judgments belong in the [sentence chapter](sentence-structure-and-interpretation.md). |
| [`SpanRuler`](https://spacy.io/api/spanruler): token/phrase patterns, `spans_key`, `spans_filter`, `annotate_ents`, `ents_filter`, `overwrite`, `phrase_matcher_attr`, `matcher_fuzzy_compare`. [PreparedAnnotationRules.__init__](../../../../python/corpus-structure/src/corpus_structure/methods/annotation_rules.py) already creates a ruler with `spans_filter=None`, `annotate_ents=False` for raw candidate collection. | **Recommended** as a native overlapping annotation layer. Separate named groups can retain term occurrences, phrase types, qualifiers and formal fragments without forcing mutual exclusion. This extends an existing native mechanism. | `overwrite=True` is the default; give each writer an explicit destination/reconciliation policy. Filters can merge or select candidates but do not establish probabilistic compatibility. Preserve rule identity and role bindings outside a bare span if they are part of the product. |
| [`EntityRuler`](https://spacy.io/api/entityruler): token/phrase patterns, `overwrite_ents`, phrase attribute selection and match callbacks through its underlying matchers. No caller was located in the inspected product Python sources; existing candidate collection uses `SpanRuler`. | **Supporting.** Useful for a deliberately non-overlapping conventional entity layer and for seeding or correcting statistical NER. **Not advantageous** as the sole first-layer extraction representation because nested terms, clause spans and alternative mentions cannot coexist in `Doc.ents`. | Longer/earlier-match and overlap policies choose a projection. Author entity taxonomy and rule/NER precedence. Putting the ruler before NER constrains its predictions; putting it after NER applies a different reconciliation policy. Keep the wider candidate layer when it carries useful information. |
| [`Lark(..., parser="lalr", lexer="contextual")`](https://lark-parser.readthedocs.io/en/stable/parsers.html), positioned trees and [`Transformer`](https://lark-parser.readthedocs.io/en/stable/visitors.html). [structural_parsing.threshold_grammar / literal_grammar](../../../../python/corpus-structure/src/corpus_structure/semantic/structural_parsing.py) already recognize numeric comparisons, units, identifiers, dates and ranges. | **Recommended.** Grammar recognition gives candidate fields internal constituents and relations: comparator versus value, interval endpoints versus delimiter, identifier versus qualifier. Those are useful characterizations even before a domain assertion is assembled. | Author grammar families, nomination coverage, positions and normalization policy. Exact whole-field recognition remains useful; a grammar that accepts a nominated region does not establish that nomination discovered all relevant fields or that a unit name has been resolved correctly. |

## Learned proposal and classification

| Exact capability and current integration | Contribution and judgment | Prerequisites and remaining authored work |
| --- | --- | --- |
| [`EntityRecognizer` / `ner`](https://spacy.io/api/entityrecognizer) predicts labeled non-overlapping `Doc.ents`. The installed English model contains NER, but [SentenceConfig](../../../../python/corpus-structure/src/corpus_structure/ingest/sentences.py) and the richer [AnnotationProfile](../../../../python/corpus-structure/src/corpus_structure/ingest/annotations.py) exclude it. | **Promising-unresolved** for recognizable people, organizations, places and domain-specific conventional entities. It could enrich first-layer mentions without an existing downstream defect. **Not advantageous** as the universal extractor: transition-based whole-entity loss, non-overlap and sensitivity to early entity cues fit neither all long phrases nor correlated sentence readings. | The selected pretrained labels and technical-text accuracy require assessment. New tasks may need adaptation and reference annotation. Exclusion from present profiles is a current choice, not evidence that NER has no useful contribution. |
| [`SpanFinder` / `span_finder`](https://spacy.io/api/spanfinder) predicts token start/end scores and writes unlabeled overlapping spans under `spans_key`; `threshold`, `min_length`, `max_length` control proposal. No product caller was located. | **Promising-unresolved.** Learned boundaries can discover terminology, clauses or qualifying passages that dictionaries and fixed n-grams miss. Boundary proposal has distinct value from assigning a semantic type. | Experimental API. Labels/examples must define the desired span universe. Every admitted start/end pair within the length policy can become a candidate; scope and length decisions affect recall and work. The native span list does not automatically retain boundary-score provenance; `predict()` exposes scores if that is required. |
| [`SpanCategorizer` / `spancat`, `spancat_singlelabel`](https://spacy.io/api/spancategorizer) scores candidate spans. Multi-label logistic outputs permit several positive labels; single-label softmax includes a negative class. Results are `Doc.spans[key]` with retained-label scores in `SpanGroup.attrs["scores"]`. Current [annotation_rules.py](../../../../python/corpus-structure/src/corpus_structure/methods/annotation_rules.py) uses its preset suggester, not a trained categorizer. | **Promising-unresolved.** A strong native fit for overlapping phrase, clause, cue and discourse-span characterization. A span can be both a technical mention and part of a condition; classification need not destroy that overlap. | Experimental API. Author annotation meanings, supervision and acceptance policy; score is not calibrated confidence or conceptual truth. `predict()` returns candidate indices and the full score matrix; `set_annotations()` writes filtered results and overwrites its output group. Keep proposal and classified output keys distinct. |
| [`spacy.ngram_suggester.v1`, `spacy.ngram_range_suggester.v1`, `spacy.preset_spans_suggester.v1`](https://spacy.io/api/spancategorizer), custom `@registry.misc` suggesters and `SpanCategorizer.set_candidates()`. Current [PreparedAnnotationRules](../../../../python/corpus-structure/src/corpus_structure/methods/annotation_rules.py) already consumes raw-group candidates through `build_preset_spans_suggester`. | **Recommended** candidate-generation abstraction; the learned categorizer remains **Promising-unresolved**. Reuse rules, dependency constituents and Lark-positioned regions as candidates rather than requiring blind enumeration. Custom suggesters can union evidence from several producers. | Suggester returns a Thinc `Ragged` array of token `(start,end)` pairs per document. N-gram lengths are explicit or an inclusive range. Candidate deduplication, evidence identity and cross-token alignment remain authored; candidate recall bounds classifier recall. `set_candidates()` exposes the actual proposal set for inspection. |
| [`TextCategorizer` / `textcat`, `textcat_multilabel`](https://spacy.io/api/textcategorizer) writes `Doc.cats`. No product call was located; current source uses explicit record/cue classifications in [m1_source_capture.py](../../../../python/corpus-structure/src/corpus_structure/methods/m1_source_capture.py). | **Promising-unresolved** for passage characterizations such as definition, example, proof step, hypothesis, reported claim or mixed rhetorical roles. Classifying a sentence-sized or paragraph-sized `Doc` can supply a coarse layer alongside exact spans. | Define region ownership and taxonomy. Exclusive scores sum to one; multi-label scores do not. `Doc.cats` supplies no grounding span and cannot express predicate arguments, qualifier attachment or a full alternative reading. Keep syntactic/located evidence alongside passage scores. Supervision semantics differ; see [models](models-supervision-and-evaluation.md). |

An especially useful composition is **rules/grammar/learned boundary proposals → preserved
candidate groups → span classification → separately authored interpretation**. It is
recommended as a target shape, not as a requirement to run every producer. It expands the
first layer while allowing a rule-only pass to remain useful. Learning is worth considering
before training data exists; annotation acquisition and efficacy are adoption questions.
Neither a span classifier nor a passage classifier enumerates every sentence interpretation.

## Normalization and identity

| Exact capability and current integration | Contribution and judgment | Prerequisites and remaining authored work |
| --- | --- | --- |
| [`AttributeRuler.add(patterns, attrs, index=...)`](https://spacy.io/api/attributeruler), `add_patterns()`, `load_from_tag_map()` and `load_from_morph_rules()`. The current richer [annotation profile](../../../../python/corpus-structure/src/corpus_structure/ingest/annotations.py) requires the installed model's attribute ruler. | **Recommended** for contextual corrections to `NORM`, lemma, tag, POS and morphology where a deterministic technical construction has a settled reading. It makes context-sensitive normalization share the token-pattern language. | An assignment mutates the one token annotation; it does not preserve rival analyses. Author correction patterns, ordering and provenance. Use a separate layer for unresolved senses rather than replacing evidence with an assumed canonical reading. |
| [`EntityRuler` pattern `id`, `ent_ids`, `remove(id)`](https://spacy.io/usage/rule-based-matching#ent-ids), [`Span.ent_id_` versus `Span.kb_id_`](https://spacy.io/api/span). No EntityRuler caller was located in the inspected product sources. | **Supporting.** Known aliases can share a rule-assigned identifier without training an entity linker. The same idea can label deterministic terminology occurrences. | `ent_id` identifies rule-associated entities; `kb_id` is a distinct linking annotation. An alias match does not resolve homonymy, mathematical symbol scope or concept identity. Author dictionary identity and contextual exclusions; retain ambiguous candidates when aliases are not unique. |
| [`EntityLinker`](https://spacy.io/api/entitylinker), [`KnowledgeBase`](https://spacy.io/api/kb), [`InMemoryLookupKB`](https://spacy.io/api/inmemorylookupkb) and `Candidate`. No product call was located. | **Promising-unresolved** for grounded technical terms, cited authors or named entities against an authored reference vocabulary. Candidate generation and contextual disambiguation could replace separate mention-to-ID machinery. Scoped identifiers and scope-conditioned candidates could also support mathematical-name normalization; the linker alone does not establish variable scope or binding semantics. | Supply stable IDs, aliases, priors, entity vectors and a suitable model/reference task. Default candidates use exact case-sensitive aliases. Custom `get_candidates` / `get_candidates_batch` and `kb_loader` can adapt retrieval/loading; they do not supply KB content or its lifecycle. A scoped-symbol design must preserve occurrence-local identity rather than merging equal spellings. |
| [`EntityLinker` evidence/acceptance controls](https://spacy.io/api/entitylinker): `incl_prior`, `incl_context`, `n_sents`, `threshold`, `labels_discard`, `overwrite`, `use_gold_ents`. | **Promising-unresolved.** Separate alias coverage, prior preference, neighboring-sentence evidence and rejection rather than treating every top candidate as resolved. `NIL` can retain failure to accept an identity. | Both prior and context are enabled by default; `threshold=None` applies no confidence cutoff. Define rejection and overwrite meanings, evaluate candidate recall independently and account for predicted versus gold entity boundaries. spaCy does not make resulting links authoritative domain facts. |
| [Lark `Transformer` / `Interpreter`](https://lark-parser.readthedocs.io/en/stable/visitors.html) and positioned tokens; current [parse_threshold](../../../../python/corpus-structure/src/corpus_structure/semantic/structural_parsing.py) maps comparators and uses `Decimal`/`canonical_operand`. | **Recommended** for explicit, source-preserving normalization after recognition: Unicode/composite comparator spellings, numeric values, date fields and unit syntax can become typed values while original tokens remain available. | Author conversion and domain checks. An accepted date-shaped token still needs calendar validation; an accepted unit string still needs vocabulary/dimension policy. Keep normalized value, original support and unresolved interpretations distinct. |

The high-value next question is which **distinct useful characterizations** the shared layer
should expose, then which rule, grammar or learned task supplies each most faithfully. The
current prepared matchers and retained source columns are useful integration evidence, not a
limit on that target. Functional/model/provider tests and behavioral probes: **not_run**;
this chapter establishes capability and proposed fit, not extraction efficacy.
