# Representations and composition

**Discovery, 2026-11-10; recommendations and expected benefits Proposed.** Inspected baseline
`e283a63c09c8881698a51495c9dbe48f757b44f3`, with pending discovery edits treated as source
notes. The [shared briefing](briefing.md) defines the full primary-characterization target:
sentence structure and interpretations, including predicates, arguments, qualifiers and scope,
are explicit upstream products available to later conceptual composition. Existing boundaries
remain open to redesign. Relevant sections of both supplied
[Lark](../../../libraries/parsing/lark.md) and [spaCy](../../../libraries/parsing/spacy.md)
guides and addenda were read end to end; consequential behavior was checked in installed
Lark 1.3.1 and spaCy 3.8.18 source. No product change or runtime qualification accompanies
this discovery.

## spaCy's native annotation model

| Feature | Contribution and judgment |
| --- | --- |
| `Doc` | **Recommended working representation for token-aligned characterization.** Owns text/token annotations and provides a shared substrate for successive lexical, syntactic and candidate passes. A Doc can hold authored semantic annotations, but its existence does not supply them. The final primary product may combine Docs with typed ASTs and packed alternatives rather than force every relationship into token fields. [Doc API](https://spacy.io/api/doc). |
| `Token` | **Recommended native access to lexical and dependency structure.** A view exposing text, offsets, lemmas, morphology, dependency heads and other annotations without a second object for every stored column. Token indices belong to one tokenization; they are not source-stable identities after retokenization. [Token API](https://spacy.io/api/token). |
| `Span` | **Recommended contiguous constituent view.** Makes phrases, clauses, arguments and anchored formal fragments available with token and character boundaries. It references its parent Doc and does not independently own the text; discontinuous arguments and arbitrary relations require additional representation. [Span API](https://spacy.io/api/span). |
| `SpanGroup` / `Doc.spans` | **Recommended parallel annotation layers.** Retains overlapping constituents and candidate labels without discarding alternatives to satisfy non-overlap. It is not a general relation graph or a packed set of complete sentence readings. [SpanGroup API](https://spacy.io/api/spangroup), [ambiguity judgments](ambiguity-and-alternative-interpretations.md). |
| `Vocab`, `Lexeme`, `StringStore` | **Recommended shared lexical substrate; supporting beyond native annotations.** Shares lexical entries and string IDs across Docs. A Lexeme's context-independent features differ from a Token's contextual interpretation. Hashed strings reduce repeated label storage but are not document-level concept identities; external interchange needs the corresponding strings/vocabulary. [Vocab](https://spacy.io/api/vocab), [Lexeme](https://spacy.io/api/lexeme), [StringStore](https://spacy.io/api/stringstore). |
| `Doc/Token/Span.set_extension()` stored values | **Recommended composition point.** Attaches candidate IDs, source references, typed interpretations or formal-parser results through `._` without modifying spaCy's internal column layout. The application defines ownership, schema, mutation rules and retention of those values. It does not automatically create a trainable native attribute. [Custom attributes](https://spacy.io/usage/processing-pipelines#custom-components-attributes). |
| Extension `getter`, `setter`, `method` | **Supporting derived views and domain operations.** Encapsulates convenient access to existing characterization rather than duplicating annotations. Expensive getters need deliberate evaluation/caching, and setter semantics must preserve the authoritative source. Callable registration and object persistence are separate concerns. [Extension API](https://spacy.io/api/doc#set_extension). |
| `Doc.user_hooks`, `user_token_hooks`, `user_span_hooks` | **Supporting for a deliberate override of native behavior.** Can replace selected properties/methods such as similarity or sentence access. Useful when a qualified representation must expose a domain-specific interpretation; broad overrides can obscure which meaning a consumer reads. Prefer named extensions for additional meanings. [Hooks](https://spacy.io/usage/processing-pipelines#custom-components-user-hooks). |
| `Doc.char_span(..., alignment_mode="strict")` | **Recommended source-alignment boundary.** Requires external character extents to match token boundaries and returns no span when they do not. Preserve the original interval and alignment failure rather than silently lose the annotation. [Doc character spans](https://spacy.io/api/doc#char_span). |
| `alignment_mode="contract"` / `"expand"` | **Supporting explicit approximate alignment.** Contract keeps enclosed tokens; expand includes intersecting tokens. Either can change the characterized extent, so record the original interval and transformation. Neither establishes exact source equivalence. [API](https://spacy.io/api/doc#char_span). |
| `Doc.retokenize()` | **Supporting only when a changed tokenization is the intended representation.** Merges/splits tokens under spaCy's machinery, useful for qualified compound or formal atoms. Existing Token/Span views can become invalid; downstream patterns, alignment and dependency assumptions must use the new tokenization. It is not needed merely to attach a second semantic layer. [Retokenization](https://spacy.io/api/doc#retokenize). |
| `Alignment` | **Recommended when separately tokenized analyses must be combined.** Maps compatible token sequences, including one-to-many correspondence, enabling imported annotations and supervision without assuming equal token indices. It does not infer arbitrary OCR/transcription equivalence or recover deleted source structure. [Alignment API](https://spacy.io/api/alignment). |

The current [TokenAnnotation/AnnotationProduct](../../../../python/corpus-structure/src/corpus_structure/ingest/annotations.py)
retains absolute start/end, whitespace, prose/math/reference role, lemma, POS, tag, morphology,
dependency label, block-local head, sentence membership and source-piece indices, plus source,
model/configuration and availability metadata. Those columns are a useful existing substrate,
not the full target interpretation schema. [annotation_view()](../../../../python/corpus-structure/src/corpus_structure/ingest/annotation_views.py)
already rebuilds a consumer-local Doc from retained words/spaces/annotations, without running
the tokenizer/model, and checks layout and sentence ownership. This shows a practical native
composition route while leaving replacement of the retained schema open.

## Lark syntax, tokens and extents

| Feature | Contribution and judgment |
| --- | --- |
| `Tree(data, children, meta)` / `Token(type, value, positions...)` | **Recommended native syntax representation.** Named constituents and typed leaves expose formal and linguistic grammar structure directly; Tokens carry source locations while behaving as strings. Shared subtree identity means the structure can be a DAG. Ordinary string reconstruction loses token metadata, and Tree identity is not durable interpretation identity. [Tree API](https://github.com/lark-parser/lark/blob/1.3.1/lark/tree.py), [Token API](https://github.com/lark-parser/lark/blob/1.3.1/lark/lexer.py). |
| `_rule` and `?rule` | **Supporting grammar-directed normalization.** Always-inlined and single-child-inlined rules remove scaffolding before semantic processing. Use them when the removed constituent has no independent characterization value; retain linguistically meaningful clause/scope boundaries. [Tree construction](https://github.com/lark-parser/lark/blob/1.3.1/docs/tree_construction.md). |
| `-> alias` | **Recommended semantic dispatch naming.** Distinguishes alternatives such as condition, attribution or quantifier form before typed transformation. Aliases name grammatical structure, not established scientific meaning; handlers still implement that meaning. [Tree construction](https://github.com/lark-parser/lark/blob/1.3.1/docs/tree_construction.md). |
| Named/unnamed terminals, `_TERMINAL`, `!rule`, `keep_all_tokens=True` | **Recommended explicit token-retention choice.** Default filtering removes anonymous literals and underscore terminals; `!` retains tokens for a selected rule and the global option retains otherwise filtered tokens. Punctuation can determine argument, coordination and scope structure, so retain it where that distinction matters. Ignored whitespace/comments remain separate: keeping tokens does not undo `%ignore` or make a lossless concrete syntax tree. [Tree construction](https://github.com/lark-parser/lark/blob/1.3.1/docs/tree_construction.md). |
| `[item]` / `maybe_placeholders` | **Supporting positional optional fields.** An unmatched bracketed optional can contribute `None`, making constructor slots explicit. This is grammar absence, not an unknown/missing annotation state or semantic negation. `item?` does not provide the same placeholder. Choose the grammar/AST field contract together. [Tree construction](https://github.com/lark-parser/lark/blob/1.3.1/docs/tree_construction.md). |
| `propagate_positions=True` and `Meta` | **Recommended for source-grounded conventional trees.** Supplies start/end and line/column extents so interpretations can refer to exact text rather than re-find strings. It does not assign a source document identity or translate between OCR, projection and original document coordinates. [Position builder](https://github.com/lark-parser/lark/blob/1.3.1/lark/parse_tree_builder.py). |
| `container_start_pos/end_pos` and container line/column fields | **Recommended when inlining/filtering changes visible structure.** Retains the enclosing syntactic extent including material hidden by tree shaping, distinct from the visible node's ordinary extent. Choose which extent anchors a constituent instead of assuming they are equal. [Position builder](https://github.com/lark-parser/lark/blob/1.3.1/lark/parse_tree_builder.py). |
| Callable `propagate_positions` | **Supporting selective metadata calculation.** Filters which children contribute to position propagation. Useful when synthetic helper nodes should not determine source extents; an incorrect filter can produce misleading intervals. This does not provide general provenance inference. [Implementation](https://github.com/lark-parser/lark/blob/1.3.1/lark/parse_tree_builder.py). |
| `tree_class=` | **Supporting specialized tree containers.** Replaces ordinary Tree construction where additional local structure is useful. It does not replace typed AST synthesis or automatically preserve foreign domain metadata. Prefer a conventional Tree plus a transformer when that already expresses the target. [Configuration](https://github.com/lark-parser/lark/blob/1.3.1/lark/lark.py). |
| `TextSlice(text, start, end)` | **Recommended for compatible region parsers needing original coordinates.** Basic/contextual lexers can parse a source view without substring allocation; token positions remain in the underlying text. Dynamic Earley lexers do not support it, so it is not a direct change to today's math parser. Prefix line counting can still revisit preceding text: zero-copy does not mean constant-time setup or incremental parsing. [Input API](https://github.com/lark-parser/lark/blob/1.3.1/lark/lark.py), [LexerState source handling](https://github.com/lark-parser/lark/blob/1.3.1/lark/lexer.py). |
| `Token.update()` / `Token.new_borrow_pos()` | **Recommended metadata-preserving leaf adaptation.** Changes category/value while retaining start and end fields, useful when converting lexical evidence to typed grammar input. A new value's length can differ from its original source extent; retain the distinction between normalized value and source spelling. [Implementation](https://github.com/lark-parser/lark/blob/1.3.1/lark/lexer.py). |
| `__lark_meta__()` | **Supporting, source-observed extension protocol.** Lets a custom child contribute metadata to `PropagatePositions` when its enclosing builder returns a Tree. Useful for mixed native/domain objects; it does not propagate provenance through arbitrary object graphs. Prefer documented `WithMeta` where suitable; this less-public protocol carries release-coupling risk. [Implementation](https://github.com/lark-parser/lark/blob/1.3.1/lark/parse_tree_builder.py). |

The present [math parser](../../../../python/corpus-structure/src/corpus_structure/methods/math/grammar.py)
uses explicit Earley alternatives, all-token retention and propagated positions. Its
[source helpers](../../../../python/corpus-structure/src/corpus_structure/methods/math/_tree.py)
recover names from source slices rather than printed leaves. The
[native math codec](../../../../python/corpus-structure/src/corpus_structure/methods/math/native.py)
stores token type/text/start/end and tree rule/extent/children, restoring those selected fields;
it is not a full `Meta`, shared-node or SPPF codec. That concrete preservation boundary matters
if the primary representation changes. Storage choices are assessed in
[execution, retention and tools](execution-retention-and-tools.md).

## Transformation and typed interpretation

Every traversal choice should preserve the supported sentence interpretations, rather than
accidentally execute or discard a branch while constructing their description.

| Feature | Contribution and judgment |
| --- | --- |
| `Transformer` | **Recommended ordinary-tree semantic reduction.** Bottom-up rule/token callbacks can construct typed predicate, argument, complement and scope objects directly. The application supplies those types and grammar semantics. The default copies Tree nodes while retaining their metadata reference, so a no-op transformer is not an independent provenance copy. [Transformer implementation](https://github.com/lark-parser/lark/blob/1.3.1/lark/visitors.py). |
| `Transformer_NonRecursive` | **Recommended alternative when input depth is not safely bounded.** Performs bottom-up replacement without Python recursion. It preserves the Transformer semantic model, not arbitrary forest sharing or infinite ambiguity; use forest APIs for the latter. [Implementation](https://github.com/lark-parser/lark/blob/1.3.1/lark/visitors.py). |
| `Transformer_InPlace` | **Supporting for privately owned mutable normalization.** Nonrecursive transformation reuses tree objects, reducing reconstruction work. Shared subtrees or retained consumers make mutation consequential; choose ownership before using it to rewrite primary syntax. [Implementation](https://github.com/lark-parser/lark/blob/1.3.1/lark/visitors.py). |
| `Transformer_InPlaceRecursive` | **Supporting for bounded-depth, privately owned trees.** Offers recursive in-place processing with the same mutation concerns and recursion-depth exposure. No independent functional advantage over the nonrecursive variant is established for unrestricted sentence structures. [Implementation](https://github.com/lark-parser/lark/blob/1.3.1/lark/visitors.py). |
| `Visitor` | **Recommended inspection/annotation traversal.** Nonrecursive bottom-up `visit()` and top-down `visit_topdown()` inspect or mutate nodes without replacing the entire structure. Useful for structural characterization; application callbacks must not count shared constituents as independent occurrences unintentionally. [Visitor implementation](https://github.com/lark-parser/lark/blob/1.3.1/lark/visitors.py). |
| `Visitor_Recursive` | **Supporting bounded-depth inspection.** Recursive bottom-up/top-down traversal offers a simpler alternative where tree depth and repeated shared-node visits are acceptable. It is not the default for arbitrarily deep or shared primary structures. [Implementation](https://github.com/lark-parser/lark/blob/1.3.1/lark/visitors.py). |
| `Interpreter`, `visit_children()` / `visit_children_decor` | **Recommended for explicit inherited-context traversal.** Controls descent and can carry binding/scope environments or selectively interpret clauses. For primary characterization, retain described branches and conditions rather than short-circuit them as if executing the sentence. Authored environment and alternative semantics remain necessary. [Interpreter implementation](https://github.com/lark-parser/lark/blob/1.3.1/lark/visitors.py). |
| `v_args(inline=True)` | **Supporting typed callback signatures.** Passes children as positional arguments, reducing unpacking for fixed-arity constructions. Long/optional child sequences still need a deliberate constructor contract. [Decorator implementation](https://github.com/lark-parser/lark/blob/1.3.1/lark/visitors.py). |
| `v_args(meta=True)` | **Recommended positioned AST callbacks.** Supplies source metadata with children. It is unavailable to internal parse-time transformers, so choose a postparse transform when these extents are required. [Contract](https://github.com/lark-parser/lark/blob/1.3.1/lark/visitors.py). |
| `v_args(tree=True)` | **Supporting whole-node transformations.** Supplies the Tree for localized structural operations; cannot combine with `meta` or `inline`. Ownership and metadata mutation still require explicit choices. [Contract](https://github.com/lark-parser/lark/blob/1.3.1/lark/visitors.py). |
| `v_args(wrapper=...)` | **Supporting common callback adaptation.** Adds a shared wrapper without hand-decorating every handler. In 1.3.1 a custom wrapper cannot combine with the built-in argument modes; define the intended adaptation explicitly. Additional tracing/validation is worthwhile only for a concrete requirement. [Implementation](https://github.com/lark-parser/lark/blob/1.3.1/lark/visitors.py). |
| `__default__`, `__default_token__`, `visit_tokens=False`, `Discard` | **Supporting control over reduction coverage.** Defaults retain unhandled structure; skipping token callbacks avoids needless dispatch when leaves need no conversion. `Discard` removes a result, so apply it to known scaffolding rather than uninterpreted text whose absence could imply complete characterization. [Transformer behavior](https://github.com/lark-parser/lark/blob/1.3.1/lark/visitors.py). |
| Transformer multiplication / `TransformerChain` | **Supporting ordered semantic passes.** Composes existing transformations without handwritten pass plumbing. It does not resolve schema mismatch, prevent destructive normalization or guarantee source-preserving behavior between passes. [Implementation](https://github.com/lark-parser/lark/blob/1.3.1/lark/visitors.py). |
| `Lark(..., transformer=...)` internal LALR transformation | **Supporting for qualified deterministic fragments; not advantageous as the universal primary route.** Can build compact values while parsing, but cannot provide ordinary tree metadata through `v_args(meta=True)`; `Discard` is disabled and Earley does not support this mode. Keep a postparse or forest transformation when source structure and alternatives are required. [Parser setup](https://github.com/lark-parser/lark/blob/1.3.1/lark/lark.py), [visitor restrictions](https://github.com/lark-parser/lark/blob/1.3.1/docs/visitors.rst). |
| `VisitError.orig_exc` | **Recommended failure distinction.** Exposes semantic callback failure separately from recognition failure, with rule/object context. Preserve it as failed interpretation rather than treating syntax as absent or unsupported. [Callback wrapping](https://github.com/lark-parser/lark/blob/1.3.1/lark/visitors.py). |
| `ast_utils.Ast` / `create_transformer()` | **Recommended candidate for a typed interpretation model.** Generates constructor callbacks from public Ast subclasses, mapping CamelCase names to snake_case rules. Reduces repetitive dispatch while leaving predicate/scope/argument types explicit. Grammar aliases, child order, optionality and constructor fields must agree; it is not schema validation or semantic inference. Generated methods can overwrite existing methods. [AST utilities](https://github.com/lark-parser/lark/blob/1.3.1/lark/ast_utils.py). |
| `ast_utils.WithMeta` | **Recommended positioned AST construction.** Passes the source Meta to constructors; define source identity and retained extent fields alongside it. Sharing a mutable Meta is not immutable provenance. [AST utilities](https://github.com/lark-parser/lark/blob/1.3.1/lark/ast_utils.py). |
| `ast_utils.AsList` | **Supporting variable-arity constituents.** Gives a constructor one list rather than positional children, appropriate for coordination, argument lists and repeated modifiers. It does not impose their ordering or semantic relationship. [AST utilities](https://github.com/lark-parser/lark/blob/1.3.1/lark/ast_utils.py). |
| `create_transformer(decorator_factory=...)` | **Supporting uniform typed-handler adaptation.** Receives `inline` and `meta` flags and decorates generated constructor callbacks. Retains native class discovery while adding a required common adaptation; custom validation or provenance policies remain authored. [Implementation](https://github.com/lark-parser/lark/blob/1.3.1/lark/ast_utils.py). |

Direct forest transformation and `@handles_ambiguity` are distinct, promising foundations for
correlated interpretations; they should not be simulated by running an ordinary Transformer
independently over every expanded tree. Their contracts and remaining semantic algebra are in
[ambiguity and alternative interpretations](ambiguity-and-alternative-interpretations.md).

## Inspection, rewriting and ownership

| Feature | Contribution and judgment |
| --- | --- |
| `iter_subtrees()` | **Recommended shared-node inspection.** Bottom-up iteration avoids returning the same subtree object twice. Identity-based constituent processing differs from counting every source occurrence or derivation. [Implementation](https://github.com/lark-parser/lark/blob/1.3.1/lark/tree.py). |
| `iter_subtrees_topdown()` | **Supporting parent-first inspection.** The 1.3.1 implementation is preorder depth-first despite a breadth-first docstring; shared children can be revisited. Select it for the actual traversal semantics and avoid assuming unique callbacks. [Implementation](https://github.com/lark-parser/lark/blob/1.3.1/lark/tree.py). |
| `find_data()`, `find_pred()`, `find_token()`, `scan_values()` | **Supporting native structural queries.** Locate rule/alias, predicate-selected subtrees or typed leaves without a custom walker. Leaf scans are recursive and do not establish derivation-specific identity; queries alone are not semantic interpretation. [Implementation](https://github.com/lark-parser/lark/blob/1.3.1/lark/tree.py). |
| Python `match` on `Tree(data, children)` and `Token(type, value)` | **Recommended for localized structural dispatch.** Native `__match_args__` supports concise tests of known forms without a custom matching engine. Lark 1.3.1 has no `Tree.match()`; Python matching does not supply recursive semantic equivalence or rewriting. [Tree](https://github.com/lark-parser/lark/blob/1.3.1/lark/tree.py), [Token](https://github.com/lark-parser/lark/blob/1.3.1/lark/lexer.py). |
| `Tree.expand_kids_by_data()` | **Supporting selective normalization.** Flattens matching immediate child wrappers in place, reusing their children. It does not recalculate metadata; preserve meaningful grouping and source boundaries before flattening. [Implementation](https://github.com/lark-parser/lark/blob/1.3.1/lark/tree.py). |
| `Tree.set()` | **Supporting explicit local mutation.** Replaces data and children without rebuilding the object. Metadata and shared consumers are not repaired automatically; use only under known ownership. [Implementation](https://github.com/lark-parser/lark/blob/1.3.1/lark/tree.py). |
| `Tree.copy()`, `copy.deepcopy(Tree/Token)` | **Not advantageous as automatic isolation/provenance preservation.** Shallow Tree copy shares the child list and omits root Meta; deep Tree copy shares Meta, and deep Token copy loses end fields. Custom copying or explicit immutable interpretation objects are needed where those distinctions matter. [Tree implementation](https://github.com/lark-parser/lark/blob/1.3.1/lark/tree.py), [Token implementation](https://github.com/lark-parser/lark/blob/1.3.1/lark/lexer.py). |
| `TemplateConf`, `Template.match/search/apply_vars`, `TemplateTranslator` | **Promising for authored structural normalization.** Parsed templates bind subtrees and translate recurring forms more precisely than substring rewriting. This could relate equivalent surface constructions to a common characterized form. Grammar-specific templates and semantic equivalence conditions remain authored; do not erase original alternatives or assume rewrites preserve every source field. [Template implementation](https://github.com/lark-parser/lark/blob/1.3.1/lark/tree_templates.py). |
| `Reconstructor`, `postproc`, `cache_grammar=True` | **Supporting readable generated syntax; not advantageous as original-text recovery.** Experimental grammar-guided reconstruction can express transformed formal structures, but does not preserve original whitespace/comments/spelling. It requires compatible grammar/placeholder settings, and cached parsers need retained grammar for reconstruction. Original source slices remain authoritative. [Reconstructor](https://github.com/lark-parser/lark/blob/1.3.1/lark/reconstruct.py), [grammar cache option](https://github.com/lark-parser/lark/blob/1.3.1/lark/lark.py). |

## Composition within and across the libraries

| Feature or composition | Contribution and judgment |
| --- | --- |
| `Span.as_doc()` | **Supporting independently processed regions.** Creates a new Doc with local indices; dependency copying can rewire heads that leave the region, and partial entities can become missing. `copy_user_data` is optional and precomputed arrays can avoid repeated preparation. Preserve source mapping and broader context explicitly; this is not an unchanged live view. [Span API](https://spacy.io/api/span#as_doc); these edge cases were inspected in installed `spacy/tokens/span.pyx`. |
| `Doc.from_docs()` | **Supporting recomposition of compatible regions.** Concatenates Docs sharing a Vocab, with selected attributes and exclusions. `ensure_whitespace` can insert spaces; copied annotations and adjusted offsets do not recover original cross-region dependencies or identity. Use original source mapping rather than assuming concatenated offsets equal source offsets. [Doc API](https://spacy.io/api/doc#from_docs). |
| `Doc.to_array()` / `from_array()` | **Supporting native column interchange.** Moves selected token attributes without repeated Python property extraction. HEAD arrays use relative offsets, unlike absolute head indices passed to the Doc constructor; string IDs need compatible vocabulary. This is not a complete interpretation or neural-representation export. Full retention judgments are in [execution, retention and tools](execution-retention-and-tools.md). [Doc array API](https://spacy.io/api/doc#to_array). |
| `%import` + `merge_transformers()` | **Recommended modular grammar and handler composition.** Imported grammar namespaces pair with prefixed semantic handlers, allowing language fragments to carry their own typed interpretation code. Merge reports method collisions. Namespace agreement, shared type contracts and top-level whitespace policy remain authored; `%ignore` is not inherited from imported grammars. [Grammar imports](https://github.com/lark-parser/lark/blob/1.3.1/docs/grammar.md), [handler merge](https://github.com/lark-parser/lark/blob/1.3.1/lark/visitors.py). |
| `%declare`, `%extend`, `%override`, grammar templates | **Recommended language-family composition.** Deferred terminals define a token-input contract; extensions add alternatives; overrides specialize imported definitions; parameterized templates reuse constituent patterns. They enable formal/prose composition without duplicating whole grammars. Recognized-language changes and ambiguity remain explicit design work. More detailed sentence-grammar judgments are in [sentence structure and interpretation](sentence-structure-and-interpretation.md). [Grammar reference](https://github.com/lark-parser/lark/blob/1.3.1/docs/grammar.md). |
| spaCy annotations → custom Lark lexer → declared typed terminals | **Promising—unresolved for sentence-level structure.** A custom Lexer can emit positioned Tokens from an annotated input rather than re-lexing strings, allowing lexical categories, formal atoms and candidate constituents to participate in authored grammars. This can make predicate/argument/scope combinations explicit. One selected token type is not enough for every overlapping candidate; choose an ambiguity-preserving input/grammar design and establish backend compatibility. Custom lexers do not imply dynamic-Earley support or a native token lattice. [Custom-lexer example](https://github.com/lark-parser/lark/blob/1.3.1/examples/advanced/custom_lexer.py), [lexer frontend](https://github.com/lark-parser/lark/blob/1.3.1/lark/parser_frontends.py). |
| Positioned Lark outputs → spaCy spans/extensions | **Recommended composition direction.** Attaches formal constituents and typed results to linguistic context using source coordinates, SpanGroups and extensions. Preserve unaligned intervals and parser/source identities rather than forcing every fragment into one token span. This supplies additional primary annotations; it does not require immediate conversion into conceptual edges. [Span alignment](https://spacy.io/api/doc#char_span), [custom attributes](https://spacy.io/usage/processing-pipelines#custom-components-attributes). |
| Native Doc views + positioned AST/SPPF interpretations | **Recommended combined target direction; exact realization unresolved.** Lets spaCy retain linguistic evidence while Lark represents recursive structure and correlated alternatives. Shared source references connect the forms; typed interpretation objects carry authored predicates, arguments and scopes. A single native object need not own all physical forms, but each characterized meaning needs a clear authority. The forest/semantic algebra and enduring identity contract remain design work. [Doc model](https://spacy.io/api/doc), [forest API](https://github.com/lark-parser/lark/blob/1.3.1/docs/forest.rst). |

checked in installed 3.8.18 source; a corresponding external release source tag was not
