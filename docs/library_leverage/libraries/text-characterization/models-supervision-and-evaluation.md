# Models, supervision and evaluation

**Discovery, 2026-11-10; benefits Proposed.** A richer first characterization layer can combine
pretrained linguistic analysis, explicit rules, domain-adapted models and new prediction tasks.
The useful output determines the task; acquiring annotations is a possible investment, not a
precondition for recognizing its value. This chapter uses the [shared baseline](briefing.md),
source `e283a63`, installed spaCy3.8.18 / en_core_web_sm3.8.0 / Lark1.3.1, with relevant
pending discovery prose reassessed. Source/reference inspection is dated 2026-11-10. No new
model inference, fitting, data collection or runtime compatibility experiment was performed.

## Representations and trainable tasks

Current [SentenceConfig.pipeline](../../../../python/corpus-structure/src/corpus_structure/ingest/sentences.py)
loads the pinned English model. The richer [AnnotationProfile](../../../../python/corpus-structure/src/corpus_structure/ingest/annotations.py)
includes its tok2vec, tagger, parser, attribute ruler and lemmatizer. Inspection of installed
`en_core_web_sm/en_core_web_sm-3.8.0/config.cfg` shows the parser and tagger consume
`Tok2VecListener`; the package's excluded NER has a separate internal tok2vec network. Thus
shared representation is already real configuration, not merely a proposed feature. The
[English model source](https://github.com/explosion/spacy-models/tree/master/meta) and
[model conventions](https://spacy.io/models) describe the independently versioned pipeline
packages; actual selected configuration governs this account.

| Exact capability | Contribution and judgment | Current evidence, prerequisites and authored work |
| --- | --- | --- |
| [`Vectors`, `Vocab.vectors`, `Token.vector`, `Doc.vector`, `Span.vector`](https://spacy.io/api/vectors) and [`spacy.StaticVectors.v2`](https://spacy.io/api/architectures#StaticVectors) | **Supporting.** Lexical representations can help domain adaptation, statistical classification and lexical similarity. **Not advantageous** as a replacement for rich sentence characterization: an averaged document/span vector does not expose predicates, qualifier scopes, attribution or competing readings. | The selected small English model has no static vector table; its contextual tensors are a different representation. Larger `md`/`lg` tables or `spacy init vectors` require a chosen resource and dimensions/key semantics. A `trf` model does not automatically turn `.vector` into a retrieval-trained sentence embedding. |
| [`Vectors(mode="floret")`](https://spacy.io/api/vectors#init) | **Promising-unresolved.** Hashed subword lexical vectors could give technical or morphologically varied tokens useful representations beyond a fixed whole-word vocabulary. This is relevant even if the current model has no demonstrated OOV defect. | Requires an appropriate floret resource or training choice and compatible downstream model. Key enumeration and `most_similar()` are not supported as with ordinary dense tables. It improves lexical representation coverage, not semantic disambiguation by itself. |
| [`BaseVectors.__getitem__`, `get_batch`, `to_ops`, `to_bytes`/`from_bytes`, `to_disk`/`from_disk`](https://spacy.io/api/basevectors) | **Supporting.** A custom lexical backend, such as BPEmb-style subword retrieval, can supply established vector resources without replacing the NLP runtime. | No product subclass was located in the inspected sources. `get_batch()` is required for `StaticVectors` training; backend, device conversion, key semantics and serialization must be implemented. A custom backend is worthwhile only for a representation resource not adequately served by built-in dense/floret storage. |
| [`spacy.MultiHashEmbed.v2`, `spacy.CharacterEmbed.v2`, `spacy.MaxoutWindowEncoder.v2`, `spacy.HashEmbedCNN.v2`, `spacy.Tok2Vec.v2`](https://spacy.io/api/architectures#tok2vec) | **Recommended** native architecture family for adapting or adding structured prediction without assuming a transformer is necessary. Hashed lexical attributes, character/byte-position features and contextual encoding can support morphology, parsing, span labels and other characterization tasks. | The installed English configuration already uses MultiHashEmbed, MaxoutWindowEncoder and Tok2Vec. CharacterEmbed is an alternative building block, not enabled by mentioning it. Select input features, widths, receptive field and task loss together; swapping an encoder does not supply a new task's labels. |
| [`Tok2Vec` / `Tok2VecListener`](https://spacy.io/api/tok2vec), `Doc.tensor` | **Recommended** when related new heads can consume one compatible contextual analysis. Share representation computation and gradients instead of independently running an encoder per characterized property. | Current tagger/parser listeners demonstrate the mechanism. The upstream component must run first with aligned batches. A listener is not an independently reusable frozen encoder. Sharing can couple task updates, so ownership and training choices matter as well as execution. |
| [`CuratedTransformer` / `curated_transformer`](https://spacy.io/api/curatedtransformer), `spacy-curated-transformers` listeners | **Promising-unresolved.** Supported pretrained encoder families and shared contextual representations may improve difficult phrase/clause classifications and linguistic analysis. | Separate package/model, absent from the inherited installed-metadata scope. BERT/RoBERTa/ALBERT/CamemBERT/XLM-R families are documented; selected release/model support must be checked. Wordpiece alignment, windows, overlap and memory remain consequential. Transformer context is evidence for a task, not complete sentence interpretation. |
| [`Transformer` / `transformer`, `TransformerListener`, `TransformerModel`, `get_spans`](https://spacy.io/api/transformer) from `spacy-transformers` | **Promising-unresolved.** Broader Hugging Face encoder access, subword alignment and configurable span windows can supply one shared representation to multiple heads. This is a distinct option from curated transformers. | Separate package and compatible PyTorch/Transformers/model artifacts required. No current product import was located. Author task heads and window/reconciliation policy; establish actual Python3.14/platform support before adoption. A model's longer input limit does not by itself recover cross-sentence attribution or scope. |
| [`Thinc.Model`, `chain`, `concatenate`, `PyTorchWrapper`](https://thinc.ai/docs/api-model), [`@spacy.registry.architectures`](https://spacy.io/usage/layers-architectures) | **Supporting** for a needed custom architecture; **Promising-unresolved** where existing span/token heads cannot express useful characterization. Reuse neural composition and spaCy lifecycle while replacing only the prediction computation. | No custom trainable spaCy architecture was located in product source. Author tensor/gradient contracts, dimensions, device conversion and serialization. An architecture registry supplies dependency injection, not automatic interchangeability of arbitrary models. |
| [`TrainablePipe.predict`, `set_annotations`, `get_loss`, `update`, `initialize`, `score`, `finish_update`, `use_params`](https://spacy.io/api/pipe) and `Language.factory` | **Promising-unresolved.** A structured task for predicate-role edges, qualifier attachment or alternative-reading scores could participate in native batching, optimization and packaging when span or passage labels are insufficient. This keeps useful model infrastructure even if the target redesign is substantial. | No product subclass was located. Supply the output representation, aligned examples, loss and independent scoring; the base class does not supply those semantics. Prediction is separate from annotation mutation. Discontinuous relations and correlated alternatives need an authored representation rather than pretending a `SpanGroup` is a joint parse. |
| [`TextCatBOW`, `TextCatEnsemble`, `TextCatReduce`](https://spacy.io/api/architectures#textcat) | **Promising-unresolved.** Bag-of-words and contextual pooling provide materially different baselines for passage/rhetorical characterization. A simple lexical classifier may already identify useful discourse forms; contextual heads address a different uncertainty. | No current textcat component was located. Choose exclusive versus multi-label task semantics first; do not equate a more complex encoder with a better classification. Located support remains additional output, as discussed in [extraction](extraction-classification-and-normalization.md). |

Lark contributes grammars, candidate structures and interpretable alternatives rather than a
pretrained linguistic model. Its [`ForestSumVisitor` and custom forest prioritizers](https://lark-parser.readthedocs.io/en/stable/forest.html)
can rank derivations using authored weights or externally retained evidence. **Promising-unresolved**
for learned/rule-scored interpretation ranking, provided the result keeps correlated alternatives
and support. They supply neither a training objective nor calibrated probabilities; those remain
authored. Current [math grammar](../../../../python/corpus-structure/src/corpus_structure/methods/math/grammar.py)
uses explicit alternatives and declared context. It does not train a forest ranker. The
[alternatives chapter](ambiguity-and-alternative-interpretations.md) owns the richer mechanisms.

## Supervision and evaluation

| Exact capability | Contribution and judgment | What still has to be decided or authored |
| --- | --- | --- |
| [`Example(predicted, reference)`, `Example.from_dict`, `Alignment`](https://spacy.io/api/example) | **Recommended** shared supervision representation for adaptation or new tasks. Different predicted/reference tokenizations can align rather than requiring an unrelated gold-data model per component. | Produce reference annotations with source identity and annotation policy. Alignment does not make impossible runtime boundaries recoverable. Gold entities that cannot align to predicted tokens may be excluded by NER evaluation; retain original reference coverage when judging the end-to-end task. |
| [`Doc.set_ents(entities, blocked, missing, outside, default)`](https://spacy.io/api/doc#set_ents), [`EntityRecognizer.incorrect_spans_key`](https://spacy.io/api/entityrecognizer) | **Recommended** supervision distinctions when NER is selected. Unknown regions, confirmed negatives, blocked entities and explicitly incorrect span hypotheses carry different information. | Default uncovered state is `outside`; partial gold must deliberately use `missing` where appropriate. `blocked` constrains built-in NER, not every component. Incorrect spans discourage those exact annotations, not all overlapping hypotheses. Author coverage semantics when combining rule, model and operator labels. |
| [`Doc.has_annotation(attr, require_complete=True)`](https://spacy.io/api/doc#has_annotation) | **Recommended** availability distinction. Current [annotations.annotate](../../../../python/corpus-structure/src/corpus_structure/ingest/annotations.py) already records complete/partial/absent/not-applicable columns. | Completeness is structural, not linguistic correctness or semantic coverage. Keep this distinction if a redesigned shared layer adds new annotation families. |
| [`textcat` versus `textcat_multilabel` gold categories](https://spacy.io/api/textcategorizer) | **Recommended** explicit task choice. Missing labels in exclusive textcat count as false; missing multi-label gold entries do not contribute to loss/scoring. | Gold category values must be 0 or 1. Incomplete annotation should not accidentally become negative supervision. SpanCategorizer has its own candidate/negative semantics; do not assume textcat's masking behavior applies to every missing span label. |
| [`spacy.Corpus.v1`, `Corpus`, `JsonlCorpus`, `@readers`](https://spacy.io/api/corpus) | **Recommended** native readers if training is pursued. `.spacy` corpora, directories and custom readers can supply aligned examples; raw JSONL supports pretraining. `max_length`, `limit`, `shuffle`, `gold_preproc` and `augmenter` control the effective data stream. | No application training-data reader was located in the inspected product sources. Author sampling/splits and coverage. Gold preprocessing supplies reference segmentation and can create train–runtime mismatch; compare against the actual atom-preserving tokenizer/segmenter rather than assuming gold boundaries at inference. |
| [`source`, `training.frozen_components`, `training.annotating_components`, `replace_listeners`](https://spacy.io/usage/training#config-components) | **Recommended** controls for extending the current model. Reuse trained components, hold selected parameters, replace listeners when independence is needed, and generate upstream predictions during downstream training. | Freezing a head does not freeze changing shared upstream weights. Frozen components needed for annotations must still supply them through the configured training path. SpanFinder/ruler → preset-suggester → spancat should train with the intended proposal behavior, not only ideal gold candidates. |
| [`nlp.initialize`, `nlp.resume_training`, `nlp.update`, `spacy train`](https://spacy.io/usage/training) | **Supporting** native lifecycle; **Recommended** over a separate training runtime if selected tasks fit its examples/components. Initialization can infer label/model dimensions; resume/update can adapt existing models. | Calling initialize indiscriminately can replace trained state. Select model/data/configuration together, retain evaluation data and define which components change. This is prospective capability, not an instruction to fit a model during discovery. |
| [`spacy.orth_variants.v1`, registered augmenters](https://spacy.io/usage/training#data-augmentation) | **Promising-unresolved** for orthographic and punctuation variation, including technical-text styles. Native callbacks yield `Example` objects within the corpus reader. | Author label-preserving transformations. A callback must yield the original if it should remain in the stream; token-changing transformations require repaired alignment/annotations. Synthetic variation does not establish authentic domain coverage or reliable sentence interpretations. |
| [`spacy pretrain`, `PretrainVectors`, `PretrainCharacters`](https://spacy.io/api/cli#pretrain) | **Promising-unresolved** domain adaptation from unlabeled text. The installed 3.8.18 CLI/source supports vector-target **and character-target** approximate language-model objectives; the main guide's vector-only discussion is incomplete. Weights can initialize tok2vec for supervised training. | Experimental. Select compatible pretrain/downstream settings and an appropriate corpus/objective. Vector-target training needs target vectors; character-target training is a separate option. Neither is arbitrary transformer/LLM pretraining, nor does unlabeled text supply semantic gold. |
| [`TrainablePipe.rehearse`](https://spacy.io/api/pipe#rehearse) | **Supporting**, with unresolved component fit. Agreement with an earlier model can help preserve behavior during domain updates. | Experimental and implementation-dependent. The base method is not a complete continual-learning solution for every component. Author teacher/reference selection and assess both old and new tasks; preserving previous errors is a real countercondition. |
| [`Scorer`, `score_tokenization`, `score_spans`, `score_cats`, `score_deps`, custom `@scorers`](https://spacy.io/api/scorer) | **Recommended** native measures for tokenization, sentences, morphology, dependencies, NER, span labels, categories and linking. Score distinct boundaries/labels separately from conceptual assembly. | Native scores do not evaluate every desired interpretation, scope or relation. Author independent expectations for those outputs. Assess proposal recall as well as accepted span classification; a high score conditional on alignable/candidate spans can hide upstream omissions. |
| [`spacy find-threshold`](https://spacy.io/api/cli#find-threshold) | **Supporting.** Select a classification threshold against a chosen metric without retraining weights. Useful for spancat/multilabel acceptance policies. | Requires representative held-out labels and the desired tradeoff. Optimization against a metric is not probability calibration. For overlapping or alternative interpretations, thresholded independent spans still do not establish joint compatibility. |

Installed-source checks behind the pretraining correction read `spacy/cli/pretrain.py`,
`spacy/training/pretrain.py` and `spacy/ml/models/multi_task.py`; those are version3.8.18
observations, not claims that the mutable online documentation has been release-qualified.
Lark's [`hypothesis.extra.lark.from_lark`](https://hypothesis.readthedocs.io/en/latest/reference/strategies.html#hypothesis.extra.lark.from_lark)
integration already appears in [math/test_property.py](../../../../python/corpus-structure/tests/math/test_property.py).
It is **Supporting** for grammar-shaped examples and independent syntactic checks, not an
automatic source of correct linguistic labels or realistic ambiguity frequencies.

## Companion models and integrations

Usefulness and compatibility are separate judgments. The inherited installation check found no
metadata for the principal transformer, Stanza, scispaCy, experimental or LLM companions; that
does not prove absence from independent provider environments. The scoped product-source search
did not locate integrations for the following packages. No new package resolution was run.

| Package and concrete function | Functional judgment for the intended target | Compatibility and remaining work |
| --- | --- | --- |
| [`spacy-stanza`, `load_pipeline`, `PipelineAsTokenizer.v1`](https://github.com/explosion/spacy-stanza) | **Promising-unresolved.** Alternative statistical tokenization, sentences, lemmas, morphology, POS, dependencies and NER through `Doc` can broaden linguistic coverage and supply another analysis whose disagreements remain explicit. | Its spaCy3 wrapper is a separate tokenizer/pipeline boundary; predicted annotations originate in Stanza. Model/dependency/Python3.14 compatibility and preservation of math/reference atoms need assessment. Pretokenized support is useful but does not itself preserve this repository's source contract. |
| [`scispaCy` scientific models, `AbbreviationDetector`, `EntityLinker`](https://github.com/allenai/scispacy) | **Promising-unresolved** for abbreviation/long-form characterization and broad scientific mention proposals. Biomedical parser/NER/linker resources are **Supporting** examples with lower immediate fit for mathematical textbooks; the adjective “scientific” does not establish domain match. | Separate model/package compatibility and resources required. Compare the specific component rather than replacing the whole pipeline by default. Abbreviation normalization can be useful outside biomedicine; biomedical KB IDs and mention definitions must not be silently reused as mathematical concepts. |
| [`spacy-experimental` `experimental_coref` / `CoreferenceResolver`, `SpanResolver`](https://spacy.io/api/coref) | **Promising-unresolved**, especially for attribution, pronouns, repeated mentions and cross-sentence references. Word-level mention clusters plus span expansion could enrich the first layer materially. | The inspected published [0.6.4 requirements](https://github.com/explosion/spacy-experimental/blob/v0.6.4/requirements.txt) require `spacy>=3.3.0,<3.8.0`, incompatible with selected3.8.18. A compatible release/fork/adaptation or separately scoped runtime is an adoption question. Compatibility does not negate functional value; clusters still require scope/identity interpretation. |
| [`experimental_char_tagger_tokenizer`, `experimental_char_ner_tokenizer`, `char_pretokenizer.v1`](https://github.com/explosion/spacy-experimental#trainable-character-based-tokenizers) | **Promising-unresolved.** Learned character-sequence boundaries can address noisy or technical segmentation that deterministic language-tokenizer rules express poorly. Tagging and NER-style boundary models provide distinct native research options. | Same published0.6.4 spaCy<3.8 restriction as above, separate from functional usefulness. Select boundary supervision and assess model retraining; preserve math/reference atoms, exact source coordinates and layout identity when projecting character predictions into the shared token layer. These tokenizers do not automatically preserve the current prebuilt `Doc` contract. |
| [`spacy-huggingface-pipelines` `hf_token_pipe`, `hf_text_pipe`](https://github.com/explosion/spacy-huggingface-pipelines) | **Promising-unresolved.** Apply existing pretrained token/passage classifiers without first collecting a new training corpus. Token outputs can target `ents`, `spans`, POS or tags; passage outputs can supply categories. | Inference-only, distinct from shared transformer training. Choose task/model revision, subword aggregation, stride and strict/contract/expand alignment. Model weights are not saved by `nlp.to_disk()`; retain model artifacts independently. Python/Torch/model compatibility remains unqualified. |
| [`spacy-llm` `llm`, task/model registries, sharding and caching](https://github.com/explosion/spacy-llm) | **Promising-unresolved.** Prompt-based span, relation, entity-linking, passage-label and custom characterization can address linguistic distinctions beyond packaged tasks before supervised labels exist. It may also help discover annotation vocabularies. | Experimental; provider/model/task versions and exact source grounding require selection. Author prompts, response-to-source alignment, failure semantics and interpretation output. It does not guarantee all readings, truthful attribution or calibrated confidence. Compare integration with the existing [LLM method family](../../../../python/corpus-structure/src/corpus_structure/methods/llm) rather than automatically creating another provider owner. |
| [`spacy-lookups-data`, `Lookups`](https://github.com/explosion/spacy-lookups-data) | **Supporting.** Language-specific lemma/normalization tables can support deterministic or trained linguistic processing. This is useful shared data rather than a richer parser. | Per-language table availability and component mode matter. Model packages may already ship their required tables. Installing lookups does not add a contextual disambiguator or change every existing pipeline automatically. |
| [`spacy-layout`, `spaCyLayout`, `Doc.spans["layout"]`, table/layout extensions](https://github.com/explosion/spacy-layout) | **Promising-unresolved** for composing document regions and linguistic units: headings, tables and layout spans can delimit useful characterization contexts. | Separate Docling-backed integration. Current [PDF ingestion](../../../../python/corpus-structure/src/corpus_structure/ingest/pdf.py) already owns native extraction and coordinates. Assess whether this wrapper removes meaningful translation while preserving source identity; adding a second PDF parse only to obtain spaCy spans would add work. |

The model choice remains open at the **task** level: pretrained analysis, rule/grammar
construction, supervised adaptation, external task models and prompt-based characterization
can all contribute. Their output semantics and independent quality evidence determine where
each belongs. No missing present consumer, training set or current defect is used here to
exclude a potentially useful characterization.
